# 上下文、会话与交接

## 原则

任务的真实状态存仓库，聊天提供意图和反馈。新会话需要 A13 的目标、范围、版本、输入、未完成项、命令、环境和下一步。A21记录关键指令和决定，不能把模板例子当实际用户输入。

长任务每完成一个可验收步骤更新交接。服务PID/会话句柄只是线索，接手必须检查它现在是否存活；不能因旧锁文件还在而假设进程运行，也不能因一次超时重启正在执行的任务。

保存交接时同时核对 README、任务表和实际入口的状态，发现差异及时同步。涉及运行环境时检查可执行文件和进程是否实际存在，下载成功提示不是持久可用保证；纯文档任务不要求启动应用。

## 人驱动交接

能力：文件读写，验证时需终端；人提供任务或仓库入口即可，AI自己收集版本和文件事实。

```text
[CTX-SAVE] 请为 {任务} 生成A13交接到 {交接路径}。
记录目标、输入版本、当前提交及未提交差异、文件归属、已执行命令和结果、
实际运行服务的目标与状态、配置获取方式、未决事项和一项可执行下一步。
不要复制整段聊天或秘密，不把计划中的检查写成已通过。
```

```text
[CTX-RESUME] 这是新会话。只依据 {仓库入口} 和 {交接路径} 接续任务。
先查AGENTS、规格、Git状态和证据版本，复核所需进程/环境是否存在。
指出仍缺少的事实；能从文件找到的不问人。在授权内执行交接的下一步并保存证据。
如果你必须依赖原聊天才能继续，把具体缺失写出来，让AI修订交接后重试。
```

输出：接手记录、新结果、额外澄清次数及原因。通过条件为完成一个真实下一步；重复摘要或同一会话自检不算独立接手。

```text
[CTX-REVIEW] 请检查 {交接记录} 是否遗漏版本、数据准备、配置、命令目录或失败恢复。
按 {反馈} 修订，只写可复查事实；标明哪些旧证据因当前差异失效。
给下一会话一条完整的恢复指令，不需要隐藏记忆。
```

## 多 Agent 可选规则

确有授权时按文件或职责分工；共享契约、迁移和锁文件由协调者整合。独立验收只读实现，独立接手不继承原聊天。共享规格和测试环境可以复用，编码者的“通过”结论不作为判据。

```text
[CTX-SPLIT] 请为 {已授权并行任务} 划分不重叠的文件与输出，指定协调者和集成条件。
每位执行者读取同一规格基线，交付候选摘要和证据；发现重叠暂停冲突部分。
不要仅为了并行而拆出无独立产物的任务，也不要让验收者修改产品实现。
```

填写示例：TASK-001交接给新会话，下一步执行AC-09 API拒绝并核对数据库无变化；没有应用环境时记录阻塞，不伪造403。
