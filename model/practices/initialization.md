# 首次准备：仓库与 Agent 工作环境

## 目标与制品

人给出项目目标、已有仓库和技术约束，AI检查事实后生成 [A08](../artifacts/A08-agent-rules.md) 工作规则和 [A09](../artifacts/A09-engineering-baseline.md) 工程基线。AGENTS说明如何工作，工程基线保证实际能工作。文档项目只声明文档检查，应用准备好后才把真实npm命令写成可用。

## AGENTS 必须写什么

首次准备的重点是讲清 AGENTS 应写什么；其他工程基线提供清单和模板，不把完整基础设施建设设为构建原型的前提。AGENTS 最低内容：

1. 项目目的、范围、非目标与目录边界。
2. 可信资料、必读入口、规则冲突处理方式及子目录规则范围。
3. 技术栈、架构边界、命名和编码规范；详细规范用链接引用，不复制多份。
4. 当前计划、状态和任务入口，以及原型演化与同类问题排查规则。
5. 已授权执行范围、需要人决定的事项与交付要求。
6. 实际存在的开发、检查、测试和构建命令及工作目录；不存在的命令只能列为待建立，不能写成已可用。
7. 验证、候选版本、证据、数据安全和敏感信息要求。

稳定规则简洁集中，业务字段和页面细节链接到规格。工程基线清单覆盖目录、依赖锁、配置示例、忽略规则、检查入口和最小运行验证，按项目需要逐步增强。

根 AGENTS 管理方法论仓库，FocusTask 的 AGENTS 只管理教学文档。实际项目可以另设模块规则，不能将示例中的假设变成本仓库的应用执行授权。

## 操作链

输入：已有资料与当前环境；文件读写、终端；人仅对目标和主要技术取舍负责，AI查依赖和现有命令。

```text
[INIT-START] 请检查 {仓库} 的定位、文档、Git状态、目录、现有代码和真实命令。
为 {项目目标} 提出最小初始化清单，列哪些已存在、需要创建、需要权限或决定。
保护已有改动；没有代码时不要声称npm命令可以执行，不自行初始化完整无关产品。
```

输出为盘点和差距。进入下一步的条件是模块/技术约束足够，缺少关键选择按A06澄清。

```text
[INIT-GENERATE] 按已确认的 {范围与技术约束}，用A08模板生成根/必要子目录AGENTS，
用A09建立目录、运行时锁、配置示例、忽略规则、检查脚本与冒烟测试。
规则写真实路径和命令，示例配置不得包含凭据；已有文档改为引用。
仅使用任务专用本地端口和数据库，不修改已有服务，报告文件与环境变化。
```

输出为工作规则和实际基线；完成不是文件存在，而是新会话能依说明工作。

```text
[INIT-VERIFY] 请模拟新成员仅按README和AGENTS在 {环境} 准备项目。
实际运行安装、迁移、启动、检查和冒烟，记录工作目录、版本、命令、退出码和证据。
核对AGENTS声明与结果；缺工具记录阻塞并继续不依赖它的检查，不把建议命令算执行成功。
```

```text
[INIT-REVISE] 根据 {失败或反馈} 修订规则/基线，说明原因和影响，重跑失败及受影响步骤。
把恢复入口、环境事实和下一任务写入A13；不要为通过修改业务AC或丢弃用户文件。
```

填写示例：读取 examples/focustask/docs/context.md，为假设的目标项目填写 A08/A09 教学例，仅说明目录、命令及其前置条件。本仓库只验证文档，不据示例安装应用、创建数据库或声明命令可运行。
