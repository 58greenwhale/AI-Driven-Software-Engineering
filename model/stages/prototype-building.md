# 原型构建

## 进入、职责与输出

- 触发：具备顶层目标与当前功能的必要细节即可启动；新一轮演化以当前原型、反馈和已确认结果为输入。
- 输入：A01范围与目标、A02领域与权限规则、当前原型与运行入口、已知反馈、适用约束与A07策略。
- 产出：[制品目录](../artifact-catalog.md)中的 A03功能规格（SOP）、A10设计与实施计划（plan）、A11实现包、A23原型版本与反馈确认记录，以及受影响的A01/A02更新。
- 人与AI分工：人给目标、关键业务规则、重要取舍与风险接受，并亲自体验原型给出反馈；AI分析需求、提出方案、生成代码与测试、整理差异与未决事项。
- 退出：本轮选定行为得到确认，运行入口可用，模拟边界与未决事项明确，足以进入下一项适用活动。
- 失败/返回：关键业务规则缺失时暂停定案并澄清，不自行补业务语义；技术栈或非功能约束变化转[原型重构](prototype-refactoring.md)；整体目标变化返回A01范围决策。

构建同时完成需求获取、需求分析、设计、实现、体验反馈与需求澄清，形成一个内部循环：

```text
顶层目标与当前功能细节
  → 人驱动 AI 分析需求，形成或更新 A03 功能 SOP
  → 人驱动 AI 设计方案，形成或更新 A10 plan
  → 人驱动 AI 生成代码、测试及可运行原型（A11）
  → 人体验并反馈，AI 整理差异、问题与待决事项
  → 同步更新 A03、A10、A11 与 A23，进入下一轮
```

产品细节和架构按需要逐步完善，不要求全部需求与设计完成后才能构建；适用的数据保护、权限和安全底线从构建开始落实，不后置。模拟与未确认行为须经澄清后才能成为正式需求。

## 执行步骤与提示词

下面每一条都可直接给AI执行。参数从本活动输入和[提示词协议](../practices/prompt-protocol.md)取得；缺少参数先读取可发现事实，再澄清。已有授权足够时连续执行，不逐条重新索取批准。文件操作需要读写权限，运行/验证另需终端和对应环境；UI需要浏览器。

### BUILD-START：从目标与部分细节启动

```text
[BUILD-START] 请为 {项目} 的 {目标} 启动原型构建。读取 {输入路径}：顶层目标与范围、领域与权限规则、当前原型与运行入口、已有反馈与适用约束。区分已确认行为、假设与模拟，列出本轮可开始构建的部分、缺失的关键业务规则、适用的数据保护与权限底线。可发现的事实直接核对，不重复问人。
```

预期输出与判断：本轮范围、事实与缺口清单。若条件不满足，使用 BUILD-DECIDE 或 BUILD-RECOVER。

### BUILD-DECIDE：处理需求歧义与关键规则缺失

```text
[BUILD-DECIDE] 原型构建中 {问题} 存在歧义或缺少确认来源。请读取 {输入路径}，说明冲突来源与影响，给出会改变结果的选项、默认建议及各自代价；需人决定的关键业务规则单列。已明确部分继续起草 A03 与 A10，未确认内容标为待决，不把建议写成用户确认。
```

预期输出与判断：按影响排序的选项与待决清单。若条件不满足，使用 BUILD-RECOVER 或上文指定的返回路径。

### BUILD-GENERATE：同步SOP、plan与可运行原型

```text
[BUILD-GENERATE] 请依据 {输入路径} 为 {目标} 执行一轮构建：更新 A03 功能 SOP（正常/异常/边界、权限、数据变化与验收要求）与 A10 plan（方案理由、任务、依赖、验证安排），生成或修改 A11 实现与测试，并把原型版本、运行入口、真实与模拟边界、反馈与确认来源写入 A23。使用 templates/ 下对应模板；涉及运行结果必须来自真实工具，未执行不得填通过。
```

预期输出与判断：同步更新的制品与可运行原型。若条件不满足，使用 BUILD-RECOVER 或 BUILD-DECIDE。

### BUILD-REVIEW：整理体验反馈与差异

```text
[BUILD-REVIEW] 人已体验原型并给出 {反馈}。请读取 {制品路径} 与当前实现，整理事实、差异、问题与待决事项，区分表现问题、行为变化与目标变化；指出受影响的 A03 条目、A10 任务、A11 代码与 A16 待重验项，给出下一轮建议。不修改已确认标准，不把人未提出的要求写成需求。
```

预期输出与判断：差异与影响清单及下一轮范围。若条件不满足，使用 BUILD-DECIDE 或 BUILD-RECOVER。

### BUILD-VERIFY：核对本轮行为与运行入口

```text
[BUILD-VERIFY] 请核对 {候选} 是否满足 A03 选定行为与 A07 适用检查：运行入口可用、权限与数据规则生效、异常与边界有可观察结果、模拟部分已标明。逐项给出通过/失败/无法判定/阻塞，附命令、环境、版本与证据位置；未执行的检查保持无法判定，不以生成者总结当结果。
```

预期输出与判断：本轮行为的真实核验结论。若条件不满足，使用 BUILD-RECOVER 或转 A15。

### BUILD-HANDOFF：交出可进入下一活动的状态

```text
[BUILD-HANDOFF] 请把本轮构建结果交给下一执行者，保存到 {交接路径} 并更新 A23：当前原型版本与运行入口、已确认行为、模拟与未决项、受影响制品与待重验证据、下一条指令（进入重构、审查、精修或独立验收）。接手者应能只凭文件继续。
```

预期输出与判断：可恢复的交接与明确的下一步。若条件不满足，先补足版本、入口或未决项。

### BUILD-RECOVER：原型不可运行或环境失败

```text
[BUILD-RECOVER] 处理 {错误}：原型无法运行、依赖或环境失败、反馈与已确认规则冲突。读取实际输出、当前版本与 A03/A10 要求，判断属工具环境、规格缺失还是实现问题；记录已尝试方案、影响与安全恢复动作，不放宽验收、不删除测试求绿、不伪造确认。
```

预期输出与判断：可复现的恢复动作或阻塞清单。若条件不满足，记录解除条件并继续无依赖工作。

## FocusTask 教学填写示例

示例输入为 [FocusTask 教学上下文](../../examples/focustask/docs/context.md)。以下指令生成构建类文档，运行类检查未执行，不作通过结论。

```text
[BUILD-START / 已填参数示例] 从仓库根读取 examples/focustask/docs/context.md
及对应的 A01–A27 规范、模板与教学例。请为 teaching-base 的创建任务与 teaching-filter 的筛选变更准备 A03/A10/A11/A23 教学例，
标出假设、真实与模拟边界、权限底线及未决项，并说明 AC-01–AC-13 与各制品的对应关系。
只更新教学文档，不启动应用或数据库；不伪造确认、执行结果或发布身份。
若实际项目要执行本活动，请先提供确认规格、当前原型、运行入口与授权。
```

## 交接出口

只有上文退出条件满足才进入[原型重构](prototype-refactoring.md)、[原型审查](prototype-review.md)或按裁剪直接进入[独立验证](verification.md)。需要返工时在A15注明原因、影响、返回活动和重验范围。对未执行项使用无法判定或阻塞；模板、候选自检和教学示例不能代替独立证据。
