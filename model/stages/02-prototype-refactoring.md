# 原型重构

## 进入、职责与输出

- 触发：选定原型行为已确认，需按技术栈、架构和非功能要求演化实现；或决定部分调整乃至整体替换代码。
- 输入：当前原型与确认的A03、现状与目标技术约束、A07适用质量要求、A04架构与契约、A08工作规则。
- 产出：[制品目录](../artifact-catalog.md)中的 A24工程化差距与重构方案、更新的A11代码与测试、A04架构与契约、必要的A06重要决定记录、A08对应的AGENTS.md。
- 人与AI分工：人决定技术取舍、风险接受与是否整体替换；AI分析差距、提出方案、实施改造、保持已确认行为并给出验证证据。
- 退出：差距按计划处理，确认行为得到保持或经正式变更，适用检查通过，遗留风险及处理方式明确。
- 失败/返回：需要改变业务行为时返回[原型构建](01-prototype-building.md)澄清并确认；契约与非功能规则变化更新A04与A07；检查失败先修复或走A15变更，不放宽标准。

允许业务逻辑拆分、模块调整、契约完善、模拟实现替换、性能与安全改造，以及必要的整体重写。整体替换仍属演化：演化关系通过目标、反馈、确认行为和版本追踪保持，不因代码全部更换而丢失行为基线。

## 执行步骤与提示词

下面每一条都可直接给AI执行。参数从本活动输入和[提示词协议](../practices/prompt-protocol.md)取得；缺少参数先读取可发现事实，再澄清。已有授权足够时连续执行，不逐条重新索取批准。文件操作需要读写权限，运行/验证另需终端和对应环境；UI需要浏览器。

### REFR-START：建立当前与目标技术状态

```text
[REFR-START] 请为 {项目} 的重构目标建立基线：读取 {输入路径}（当前实现与依赖、A03 确认行为、A04 架构与契约、A07 质量要求、A08 工作规则），列出当前状态、目标技术约束、必须保持的行为清单及其可验证方式。指出可发现的事实与真实缺口，不把未确认的技术偏好写成项目要求。
```

预期输出与判断：当前/目标状态与行为保持基线。若条件不满足，使用 REFR-DECIDE 或 REFR-RECOVER。

### REFR-DECIDE：技术取舍与替换范围

```text
[REFR-DECIDE] 针对 {技术选择或差距}，请比较方案：影响范围、行为保持方式、迁移与回退代价、验证成本及剩余风险，标明推荐项与理由。影响多功能、难以逆转或修改既有主要约束时准备 A06；关键取舍由人决定，未确认前列为待决，不自行扩大替换范围。
```

预期输出与判断：方案对比、推荐与待决取舍。若条件不满足，使用 REFR-RECOVER 或上文指定的返回路径。

### REFR-GENERATE：产出方案并实施改造

```text
[REFR-GENERATE] 请依据 {确认方案} 生成 A24（当前/目标状态、差距、保留/调整/替换策略、步骤与依赖、行为映射、检查方式、失败恢复），再按步骤实施 A11 代码与测试改造，同步 A04 契约与 A08 的 AGENTS.md。整体替换也须保持已确认行为或走正式变更；未执行的检查记为待验证，不写成已通过。
```

预期输出与判断：A24方案与可运行的改造结果。若条件不满足，使用 REFR-RECOVER 或 REFR-DECIDE。

### REFR-REVIEW：检查行为保持与规则一致

```text
[REFR-REVIEW] 请审阅 {差异} 与 A24：确认行为是否逐项有对应实现与测试，契约、领域规则与非功能约束是否与 A02/A04/A07 一致，AGENTS.md 是否与代码和测试同步，模拟实现替换是否留下缺口。逐项给出位置、预期/实际、影响与建议；发现具体问题模式时按 A26 做全项目同类排查。
```

预期输出与判断：一致性问题清单与排查需求。若条件不满足，使用 REFR-RECOVER 或转 A15。

### REFR-VERIFY：运行适用检查与回归

```text
[REFR-VERIFY] 请对 {重构候选} 运行 A07 规定的适用检查与 A03 行为回归，记录命令、环境、版本、退出码与证据位置；比对重构前后行为差异，性能与安全改造给出实际测量或标未测量。给出通过/失败/无法判定/阻塞，不复用重构前的旧结果冒充新证据。
```

预期输出与判断：真实检查与回归结论。若条件不满足，使用 REFR-RECOVER。

### REFR-HANDOFF：移交重构结果

```text
[REFR-HANDOFF] 请把重构结果交给下一执行者，保存到 {交接路径}：A24 版本、已处理差距、保持与变更的行为、更新的契约与工作规则、剩余风险与下一步（进入审查、精修或独立验收）。涉及运行中的服务先标记需要复查状态。
```

预期输出与判断：可恢复的交接与下一步入口。若条件不满足，先补足版本、风险或未决项。

### REFR-RECOVER：行为变化或检查失败

```text
[REFR-RECOVER] 处理 {失败结果}：重构后行为不一致、检查无法运行或依赖环境损坏。先恢复到上一个可运行版本并核对数据，区分实现缺陷、方案不当与环境问题；记录尝试、影响与解除条件。业务行为变化无确认来源时暂停相关改动，其余已确定工作继续。
```

预期输出与判断：可恢复状态与进一步决策。若条件不满足，记录阻塞与解除条件。

## FocusTask 教学填写示例

示例输入为 [FocusTask 教学上下文](../../examples/focustask/docs/context.md)。以下指令生成重构类文档，运行类检查未执行，不作通过结论。

```text
[REFR-START / 已填参数示例] 从仓库根读取 examples/focustask/docs/context.md
及对应的 A01–A27 规范、模板与教学例。请以教学架构（Next.js/React/TypeScript 与 PostgreSQL/Prisma）为当前设定，
填写 A24 教学例：列出权限与幂等实现差距、行为映射、保留/调整/替换策略与未执行的验证方式。
只更新教学文档，不启动应用或数据库；不伪造确认、执行结果或发布身份。
若实际项目要执行本活动，请先提供当前实现、确认行为清单、目标约束与授权。
```

## 交接出口

只有上文退出条件满足才进入[原型审查](03-prototype-review.md)；需要独立验收时进入[独立验收](05-verification.md)。新的业务取舍返回[原型构建](01-prototype-building.md)确认后再调整行为。需要返工时在A15注明原因、影响、返回活动和重验范围；模板、候选自检和教学示例不能代替独立证据。裁剪与并行安排记录在A10，见[裁剪](../tailoring.md)；裁剪不取消适用的确认、测试、审查与证据要求。
