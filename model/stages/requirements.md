# 需求分析

## 进入、职责与输出

- 触发：人有问题、目标或新要求，需要转成可执行范围；维护的新需求也从这里进入。
- 输入：人的目标、现有文档、已接受决定、约束和原型观察。
- 产出：[制品目录](../artifact-catalog.md)中的 A01 范围、A02 领域权限、A03 功能规格；重要取舍用 A06；过程用 A21。
- 人与AI分工：人决定目标用户、本轮包含/排除、关键业务规则和未决项是否阻塞；AI给出场景、选项、影响和推荐，不代造用户确认。
- 退出：目标和非目标明确；字段、权限、错误与数据结果可判定；每项关键规则有来源和AC；未决项不影响当前切片。
- 失败/返回：范围不明继续澄清；规则冲突向责任人报告；不要把代码现状当新需求；原型可探索但不算实现承诺。

## 执行步骤与提示词

下面每一条都可直接给AI执行。参数从本阶段输入和[提示词协议](../practices/prompt-protocol.md)取得；缺少参数先读取可发现事实，再澄清。已有授权足够时连续执行，不逐条重新索取批准。文件操作需要读写权限，运行/验证另需终端和对应环境；UI需要浏览器。

### REQ-START：检查目标与上下文

```text
[REQ-START] 读取 {项目} 的AGENTS、产品资料和 {本轮目标}，分别列确认事实、建议和缺口。先搜索已有规则，指出哪些问题影响范围、权限或数据。
```

预期输出与判断：阶段定位、资料清单和问题列表。若条件不满足，使用 REQ-RECOVER 或上文指定的返回路径。

### REQ-DECIDE：澄清并记录选择

```text
[REQ-DECIDE] 对 {关键问题} 给出可行选项、正常与异常例子、影响与推荐。已有确认来源则直接引用，否则等关键决定；按 {人的选择与来源} 更新范围，不把默认建议当确认。
```

预期输出与判断：A01范围与决定、A02规则草稿。若条件不满足，使用 REQ-RECOVER 或上文指定的返回路径。

### REQ-GENERATE：生成可执行需求

```text
[REQ-GENERATE] 使用A01/A02/A03规范和模板，按 {输出位置} 生成范围、规则和功能规格。每条AC使用给定/当/那么，写明权限、重试、边界与数据变化；未知规则标待决策。
```

预期输出与判断：具有规则来源与编号AC的需求包。若条件不满足，使用 REQ-RECOVER 或上文指定的返回路径。

### REQ-REVIEW：从下游审阅并修订

```text
[REQ-REVIEW] 审阅 {需求包} 是否足够让陌生实现者和验收者工作。找出歧义、范围漏项及不可观察用例，依据 {反馈及确认来源} 修订，并列影响的设计/测试。
```

预期输出与判断：问题清单、修订内容与待决策项。若条件不满足，使用 REQ-RECOVER 或上文指定的返回路径。

### REQ-VERIFY：检查进入设计条件

```text
[REQ-VERIFY] 只读核对 {需求包版本} 与已确认资料。逐项检查范围、字段、权限、异常、数据、AC与未决项，提供位置和结论；这是规格检查，不声称应用已通过。
```

预期输出与判断：规格检查记录；没有阻断歧义。若条件不满足，使用 REQ-RECOVER 或上文指定的返回路径。

### REQ-HANDOFF：交给设计

```text
[REQ-HANDOFF] 生成A13，列输入版本、确认来源、未决项、AC与需要方案比较的风险。给出DES-START指令，设计者必须能不依赖本次聊天继续。
```

预期输出与判断：交接及下一条设计指令。若条件不满足，使用 REQ-RECOVER 或上文指定的返回路径。

### REQ-RECOVER：反馈不足或冲突

```text
[REQ-RECOVER] 处理 {实际冲突/错误}，核对来源优先级和受影响范围。提出最小澄清与修订路径；继续不受影响部分，不猜权限或数据规则。
```

预期输出与判断：问题记录及返回的具体步骤。若条件不满足，使用 REQ-RECOVER 或上文指定的返回路径。

## FocusTask 填写示例

教学案例：对 FocusTask 先区分原产品愿景和v0.1切片，继承TASK-001的AC-01至13；不将预置身份/项目说成实现邀请。

```text
[REQ-START / 已填参数示例] 请在 examples/focustask 开展需求分析。
本轮目标按根目录实施计划1.1和示例实证范围；输入从该目录的docs、evidence和实际代码读取。
先核对当前阶段和前置条件，对 FocusTask 先区分原产品愿景和v0.1切片，继承TASK-001的AC-01至13；不将预置身份/项目说成实现邀请。
按本阶段操作链推进，在已有授权内执行，保存文件/结果/证据。
本段是可复制示例，实际运行时请在A21区分用户输入和模板实例化执行。
```

## 交接出口

只有上文退出条件满足才进入[设计](design.md)。需要返工时在A15注明原因、影响、返回阶段和重验范围。对未执行项使用无法判定或阻塞；模板、候选自检和教学示例不能代替独立证据。
