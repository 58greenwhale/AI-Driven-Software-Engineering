# 原型审查

## 进入、职责与输出

- 触发：候选形成后进行首次系统审查或后续差异审查；大范围重写后需重新建立覆盖范围。
- 输入：候选快照与代码版本、A03/A04/A05确认规格、A07验证策略、A11实现与测试、A24（如有）、既有A12覆盖记录。
- 产出：[制品目录](../artifact-catalog.md)中的 A12代码与制品评审记录、A25面向人的实现解读、A26同类问题排查与修复记录，以及A16待重验项。
- 人与AI分工：人决定审查范围与严重度取舍、按解读分层审阅并下钻到代码、追问与判断风险接受；AI执行逐行或差异审查、生成便于人理解的解读、排查同类问题并说明依据。
- 退出：范围内自有实现有覆盖记录（首轮逐行，后续为差异及受影响路径），发现有位置与处置，解读与代码版本一致，需人决定的问题已列出。
- 失败/返回：实现缺陷返回受影响活动并重新审查；覆盖不足或既有结论失效时重建范围；代码审查不替代独立验收。

首次系统审查逐行覆盖范围内全部自有实现，包括业务代码、测试、配置、迁移和脚本，可按模块分批完成。后续审查覆盖差异及受影响路径；大范围重写重新建立覆盖范围，不能沿用已失效的逐行审查结论。依赖、生成文件和二进制资产单列检查方式。

## 执行步骤与提示词

下面每一条都可直接给AI执行。参数从本活动输入和[提示词协议](../practices/prompt-protocol.md)取得；缺少参数先读取可发现事实，再澄清。已有授权足够时连续执行，不逐条重新索取批准。文件操作需要读写权限，运行/验证另需终端和对应环境；UI需要浏览器。

### AUDIT-START：确定候选与覆盖范围

```text
[AUDIT-START] 请为 {候选} 建立审查范围：读取 {输入路径}，区分首次系统审查（逐行覆盖范围内全部自有实现，可按模块分批）与后续审查（差异及受影响路径）。列出模块清单、文件与代码区段、依赖与生成文件的单列检查方式、本批目标与未覆盖部分。大范围重写不得沿用已失效的逐行结论。
```

预期输出与判断：明确的覆盖范围与本批目标。若条件不满足，使用 AUDIT-DECIDE 或 AUDIT-RECOVER。

### AUDIT-DECIDE：分批策略与检查方式

```text
[AUDIT-DECIDE] 针对 {范围或分批问题}，请说明依赖顺序、每批可判定的完成标准、所需能力（文件读写、终端、浏览器）以及无法检查的模块及原因。把风险高或影响大的部分排在前面；严重度阈值与豁免由人决定并单列，不自行缩小覆盖范围。
```

预期输出与判断：分批计划、能力需求与待决阈值。若条件不满足，使用 AUDIT-RECOVER 或上文指定的返回路径。

### AUDIT-GENERATE：产出评审、解读与排查记录

```text
[AUDIT-GENERATE] 请执行审查并生成：A12 记录候选版本、文件及代码区段、问题编号与位置、严重度、预期/实际、证据、处置与复查结果；A25 提供模块关系、数据流、关键路径、A03 到实现的映射、设计理由、风险与需人决定的问题，并链接代码位置与版本；发现具体问题时按 A26 做全项目同类排查。未覆盖部分写明原因，不把静态阅读写成运行验证。
```

预期输出与判断：评审记录、实现解读与排查记录。若条件不满足，使用 AUDIT-RECOVER 或 AUDIT-DECIDE。

### AUDIT-REVIEW：解释发现并支持下钻

```text
[AUDIT-REVIEW] 请以人可审阅的方式解释 {审查结果}：按模块或风险分层给出摘要，指出每个发现的证据位置、影响与建议，说明哪些结论来自静态阅读、哪些来自实际运行。允许人追问并下钻到具体代码；不以机械逐行复述代替解释，也不隐藏未覆盖部分。
```

预期输出与判断：分层解读、追问入口与证据边界。若条件不满足，使用 AUDIT-GENERATE 补充依据。

### AUDIT-VERIFY：复核修复与覆盖一致性

```text
[AUDIT-VERIFY] 请对 {修复候选} 复核：原发现是否按处置关闭并有证据，回归是否覆盖受影响路径，A12 覆盖记录与 A25 解读是否已更新到当前代码版本，A16 待重验项是否正确标记。给出通过/失败/无法判定/阻塞；全部覆盖不等于证明不存在缺陷。
```

预期输出与判断：修复复核与覆盖一致性结论。若条件不满足，使用 AUDIT-RECOVER 或转 A15。

### AUDIT-HANDOFF：移交结论与未决问题

```text
[AUDIT-HANDOFF] 请把审查结论交给下一执行者，保存到 {交接路径}：候选与代码版本、覆盖范围与未覆盖原因、未关闭发现、需人决定的问题、同类排查结论及下一步（精修、重构或独立验收）。接手者应能只凭文件继续。
```

预期输出与判断：可恢复的交接与未决问题清单。若条件不满足，先补足版本、覆盖或未决项。

### AUDIT-RECOVER：覆盖失效或无法检查

```text
[AUDIT-RECOVER] 处理 {失败或阻塞}：大范围重写导致既有审查结论失效、模块无法检查、依赖或生成文件无法审阅。重新建立覆盖范围并记录失效的旧结论，明确不能检查的部分、原因与解除条件；不得把未检查部分写成没有问题。
```

预期输出与判断：重建的覆盖范围与阻塞说明。若条件不满足，记录解除条件并继续可检查部分。

## FocusTask 教学填写示例

示例输入为 [FocusTask 教学上下文](../../examples/focustask/docs/context.md)。以下指令生成审查类文档，运行类检查未执行，不作通过结论。

```text
[AUDIT-START / 已填参数示例] 从仓库根读取 examples/focustask/docs/context.md
及对应的 A01–A27 规范、模板与教学例。请以虚构问题“Viewer 可直接调用创建接口写入”为起点，
填写 A12 覆盖与发现、A25 实现解读与 A26 同类排查教学例：说明根因、检索的代码模式与业务条件、
已确认/疑似/不适用分类及未执行的回归验证。只更新教学文档，不启动应用或数据库；不伪造确认、执行结果或发布身份。
若实际项目要执行本活动，请先提供候选快照、代码版本、确认规格与授权。
```

## 交接出口

只有上文退出条件满足才进入[原型精修](prototype-polishing.md)或[独立验收](verification.md)；实现缺陷返回受影响活动并在修复后重新审查。需要返工时在A15注明原因、影响、返回活动和重验范围；全部覆盖不等于证明不存在缺陷，模板、候选自检和教学示例不能代替独立证据。裁剪与并行安排记录在A10，见[裁剪](../tailoring.md)；裁剪不取消适用的确认、测试、审查与证据要求。
