# 人驱动 AI 的软件生命周期模型

当前为面向 v0.3 的方向总纲及可复用基础。四项活动的详细指南、扩展制品和图解尚未建立，任务见[修订计划](../AI_LIFECYCLE_V03_REFINEMENT_PLAN.md)与[执行状态](../execution/status.md)。不声明实际应用效果已验证。

## 生命周期方向

目标与最小准备 → 按项目组织原型构建、原型重构、原型审查、原型精修 → 独立验收 → 直接本地发布 → 维护与下一轮。

人表达目标、约束和体验反馈并决定关键取舍；AI 分析、生成、执行、解释与验证。这里的 vibe coding 指这一协作方式，不声称是行业统一定义。市场发现和商业运营不展开。

原型构建包含需求获取、分析、设计、实现、体验反馈和澄清。原型持续演化，即使代码全部替换，仍追踪目标、确认行为与版本关系；模拟和未确认行为不自动成为正式需求。

原型重构对齐技术栈、架构和非功能约束，同步实现、测试与工作规则。原型审查检查实现、生成面向人的解读，从单个问题排查全项目同类实例。原型精修使用 AI、人工或混合设计改善 UI 与交互，行为变化同步规格并重新审查、回归。

活动可按功能并行、按迭代顺序或混合组织，可裁剪合并；适用的质量、确认和追踪责任仍存在。安全与数据保护从构建起适用，不能全部推迟到重构。

## 人驱动下一步

```text
[MODEL-START] 读取 AGENTS、执行状态及当前计划，为 {目标} 找到下一项就绪任务。
核对实际输入、当前活动与缺口，不把教学设定当实际批准。
在授权内生成和检查制品；需要新业务决定时给出选项及影响，保存可接手状态。
```

```text
[MODEL-REVIEW] 对照 {目标和确认标准} 检查指定候选及真实证据。
区分通过、失败、无法判定和阻塞；发现问题时检查全项目同类模式。
解释下一动作和需人决定的事项，不能以文件存在或自评证明应用已验证。
```

独立验收者依据确认规格和固定候选，不修改实现；修复后对新候选复验。版本及证据失效遵循[约定](conventions.md)。
