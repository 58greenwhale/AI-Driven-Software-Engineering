# A04 架构与契约

## 用途与生命周期

- 适用与触发：必要；接口和非功能可分文档；首次设计、公共接口/数据/依赖边界变化。
- 生产者：人驱动的 AI；责任角色：技术责任人。
- 输入：A01–A03、已有代码、平台约束和重要 ADR。
- 使用者与用途：工程初始化、服务端/界面实现、集成验证和发布者。
- 输出：项目内 `docs/architecture-contracts.md`；实例、版本、来源及失效遵循[约定](../conventions.md)。
- 配套：[模板](../../templates/A04-architecture-contracts.md) · [教学填写示例](../../examples/focustask/docs/artifact-examples/A04-architecture-contracts.md)。

## 必填内容与字段含义

| 章节 | 必须回答 |
| --- | --- |
| 现状、目标与确认设计 | 当前实现事实、目标技术约束、已确认设计及三者差异与迁移路径 |
| 组件与边界 | 模块、依赖方向、数据流与禁止跨层行为 |
| 运行时与依赖 | 确切版本、选择理由、锁定方式、升级依据 |
| 接口契约 | 方法/路径、输入、成功和失败结构、状态码、认证和幂等 |
| 数据与兼容 | 表关系、约束、迁移顺序、旧新版本读写兼容 |
| 安全与配置 | 会话、来源校验、密钥注入、日志字段、限流 |
| 非功能与验证 | 明确指标、测量方法、环境、失败方式 |

元数据必须包含实例ID、版本、状态、责任角色、输入版本、确认来源、下游用途、未决项。字段未知标明原因；建议与事实分开。

## 质量标准与边界

接口字段、状态、认证、错误、事务与适用领域规则一致；区分当前实现、目标约束与确认设计，不把未确认目标写成现状。定义本项目实际组件和公共接口，不强行引入登录、成员或网络服务。重构差距、替换策略与实施步骤由 A24 记录，本文只保存当前确认的架构与契约。规则变化先更新来源，相关测试/运行记录标为待重验，旧结果保留原适用版本。

- 不足示例：“前端调用后端保存即可”。
- 可判定示例：“Route Handler 解析协议，server 服务重新验证角色，在数据库事务中创建任务与幂等记录”。

## 人驱动 AI 的操作链

依[提示词协议](../practices/prompt-protocol.md)取得参数。开始时人提供目标与输入位置；AI先读取事实，缺关键规则才追问。选择/修订用真实人的反馈或既有授权，不要求每一步重新批准。只写本文需文件读写；验证/执行代码另需终端和目标环境，UI需浏览器。

### A04-START

```text
[A04-START] 请为 {项目} 的 {目标} 开始准备 A04 架构与契约。先读取 {输入路径}：A01–A03、已有代码、平台约束和重要 ADR。定义本项目实际组件和公共接口，不强行引入登录、成员或网络服务。列事实、缺口与下一步；可发现的事实直接核对，不重复问人。
```

### A04-CLARIFY

```text
[A04-CLARIFY] 请澄清 架构与契约 的 {问题}。先读 {输入路径} 并说明冲突来源，给出会改变结果的选项和取舍。重点检查：接口字段、状态、认证、错误、事务与适用领域规则一致；区分当前实现、目标约束与确认设计，不把未确认目标写成现状。未知关键规则暂停定案，已明确内容继续起草。
```

### A04-SELECT

```text
[A04-SELECT] 依据 {确认来源}，本轮对 架构与契约 采用 {已选方案}，适用范围是 {目标}。请记录决定、来源、影响和未确认事项；先核对来源真实存在，再更新状态，不把建议写成人的批准。
```

### A04-GENERATE

```text
[A04-GENERATE] 请依据 {输入路径} 为 {目标} 生成 A04 架构与契约，写入 {输出路径}，使用 templates/A04-architecture-contracts.md。定义本项目实际组件和公共接口，不强行引入登录、成员或网络服务。逐章填写规范要求，未知和不适用说明原因；涉及运行结果必须来源于真实工具，未执行不得填通过；返回文件、版本和实际检查。
```

### A04-REVIEW

```text
[A04-REVIEW] 请按下游使用者的视角审阅 {制品路径}：工程初始化、服务端/界面实现、集成验证和发布者。检查 接口字段、状态、认证、错误、事务与适用领域规则一致；区分当前实现、目标约束与确认设计，不把未确认目标写成现状。逐项给出位置、预期/实际、影响与建议，区分缺输入和内容错误；不直接改变已确认标准。
```

### A04-REVISE

```text
[A04-REVISE] 请根据 {反馈} 修订 {制品路径}，保留来源和版本关系。重点仍是：定义本项目实际组件和公共接口，不强行引入登录、成员或网络服务。先列影响，再修改获准内容，同步关联制品并在 A16 标记需重验的证据；业务规则变化无确认来源时暂停相关改动。
```

### A04-VERIFY

```text
[A04-VERIFY] 请独立核对 {制品路径} 的候选 {候选}，依据 {输入路径} 与 A04 规范。验证 接口字段、状态、认证、错误、事务与适用领域规则一致；区分当前实现、目标约束与确认设计，不把未确认目标写成现状。给出通过/失败/无法判定/阻塞，附步骤、环境、版本和证据；只读产品实现，不以生成者总结当结果。
```

### A04-HANDOFF

```text
[A04-HANDOFF] 请把 架构与契约 交给下一执行者，保存到 {交接路径}。明确 工程初始化、服务端/界面实现、集成验证和发布者，记录输入/输出版本、真实检查、未决项及下一条指令。接手者应能只凭文件继续，涉及运行中的服务先标记需要复查状态。
```

### A04-FAILURE

```text
[A04-FAILURE] 处理生成或验证 架构与契约 时发生的 {错误}。读取实际输出、当前版本和 A04 输入要求，判断是工具/环境、规格缺失还是实现问题。记录已尝试方案和影响；仅执行已授权的安全恢复，不放宽验收、不伪造结果。
```

## 完成、更新与交接

检查必填项、来源、质量标准和下游可用性；每次修改按版本更新，不覆盖旧确认历史。草稿完成不等于业务确认，候选验证不等于已发布。无证据的运行结论保持无法判定。交接给上述使用者，失败按 FAILURE 返回相关阶段。
