# A21 实际人机交互记录

## 用途与生命周期

- 适用与触发：研究实证时必要；普通项目可简化；关键活动、决策、反馈、失败恢复时记录。
- 生产者：人驱动的 AI；责任角色：执行协调者。
- 输入：真实用户意图、提示词模板、执行者指令和工具结果。
- 使用者与用途：接手者、模型评价者和审计读者。
- 输出：项目内 `evidence/interactions.md`；实例、版本、来源及失效遵循[约定](../conventions.md)。
- 配套：[模板](../templates/A21-interaction-log.md) · [教学填写示例](../../examples/focustask/docs/artifact-examples/A21-interaction-log.md)。

## 必填内容与字段含义

| 章节 | 必须回答 |
| --- | --- |
| 身份与来源 | 交互ID、时间、阶段、来源类型、模板版本和参数 |
| 指令与背景 | 脱敏后的实际指令、输入路径、授权范围 |
| 输出与决定 | 输出位置、AI建议、人决定或既有授权依据 |
| 验证与成本 | 证据、失败、澄清/返工、耗时、不可采集项 |

元数据必须包含实例ID、版本、状态、责任角色、输入版本、确认来源、下游用途、未决项。字段未知标明原因；建议与事实分开。

## 质量标准与边界

人工确认有真实来源，已授权事项不重复审批，示例对话不当实证。区分模板、教学示例、实际用户输入和授权执行，不记录秘密或隐藏推理。规则变化先更新来源，相关测试/运行记录标为待重验，旧结果保留原适用版本。

- 不足示例：“用户确认通过（实际没有这条输入）”。
- 可判定示例：“用户授权执行计划；本轮按A03-GENERATE展开执行，未发生逐条人工审批”。

## 人驱动 AI 的操作链

依[提示词协议](../practices/prompt-protocol.md)取得参数。开始时人提供目标与输入位置；AI先读取事实，缺关键规则才追问。选择/修订用真实人的反馈或既有授权，不要求每一步重新批准。只写本文需文件读写；验证/执行代码另需终端和目标环境，UI需浏览器。

### A21-START

```text
[A21-START] 请为 {项目} 的 {目标} 开始准备 A21 实际人机交互记录。先读取 {输入路径}：真实用户意图、提示词模板、执行者指令和工具结果。区分模板、教学示例、实际用户输入和授权执行，不记录秘密或隐藏推理。列事实、缺口与下一步；可发现的事实直接核对，不重复问人。
```

### A21-CLARIFY

```text
[A21-CLARIFY] 请澄清 实际人机交互记录 的 {问题}。先读 {输入路径} 并说明冲突来源，给出会改变结果的选项和取舍。重点检查：人工确认有真实来源，已授权事项不重复审批，示例对话不当实证。未知关键规则暂停定案，已明确内容继续起草。
```

### A21-SELECT

```text
[A21-SELECT] 依据 {确认来源}，本轮对 实际人机交互记录 采用 {已选方案}，适用范围是 {目标}。请记录决定、来源、影响和未确认事项；先核对来源真实存在，再更新状态，不把建议写成人的批准。
```

### A21-GENERATE

```text
[A21-GENERATE] 请依据 {输入路径} 为 {目标} 生成 A21 实际人机交互记录，写入 {输出路径}，使用 model/templates/A21-interaction-log.md。区分模板、教学示例、实际用户输入和授权执行，不记录秘密或隐藏推理。逐章填写规范要求，未知和不适用说明原因；涉及运行结果必须来源于真实工具，未执行不得填通过；返回文件、版本和实际检查。
```

### A21-REVIEW

```text
[A21-REVIEW] 请按下游使用者的视角审阅 {制品路径}：接手者、模型评价者和审计读者。检查 人工确认有真实来源，已授权事项不重复审批，示例对话不当实证。逐项给出位置、预期/实际、影响与建议，区分缺输入和内容错误；不直接改变已确认标准。
```

### A21-REVISE

```text
[A21-REVISE] 请根据 {反馈} 修订 {制品路径}，保留来源和版本关系。重点仍是：区分模板、教学示例、实际用户输入和授权执行，不记录秘密或隐藏推理。先列影响，再修改获准内容，同步关联制品并在 A16 标记需重验的证据；业务规则变化无确认来源时暂停相关改动。
```

### A21-VERIFY

```text
[A21-VERIFY] 请独立核对 {制品路径} 的候选 {候选}，依据 {输入路径} 与 A21 规范。验证 人工确认有真实来源，已授权事项不重复审批，示例对话不当实证。给出通过/失败/无法判定/阻塞，附步骤、环境、版本和证据；只读产品实现，不以生成者总结当结果。
```

### A21-HANDOFF

```text
[A21-HANDOFF] 请把 实际人机交互记录 交给下一执行者，保存到 {交接路径}。明确 接手者、模型评价者和审计读者，记录输入/输出版本、真实检查、未决项及下一条指令。接手者应能只凭文件继续，涉及运行中的服务先标记需要复查状态。
```

### A21-FAILURE

```text
[A21-FAILURE] 处理生成或验证 实际人机交互记录 时发生的 {错误}。读取实际输出、当前版本和 A21 输入要求，判断是工具/环境、规格缺失还是实现问题。记录已尝试方案和影响；仅执行已授权的安全恢复，不放宽验收、不伪造结果。
```

## 完成、更新与交接

检查必填项、来源、质量标准和下游可用性；每次修改按版本更新，不覆盖旧确认历史。草稿完成不等于业务确认，候选验证不等于已发布。无证据的运行结论保持无法判定。交接给上述使用者，失败按 FAILURE 返回相关阶段。
