# A12 代码与制品评审记录

## 用途与生命周期

- 适用与触发：必要；可用本地记录，外部PR非必需；候选形成、修复后复评。
- 生产者：人驱动的 AI；责任角色：评审责任人。
- 输入：候选快照、确认规格、差异、测试与运行证据。
- 使用者与用途：集成责任人、修复者和后续维护者。
- 输出：项目内 `evidence/review.md`；实例、版本、来源及失效遵循[约定](../conventions.md)。
- 配套：[模板](../templates/A12-review.md) · [教学填写示例](../../examples/focustask/docs/artifact-examples/A12-review.md)。

## 必填内容与字段含义

| 章节 | 必须回答 |
| --- | --- |
| 评审上下文 | 候选标识、差异范围、依据版本、评审者职责 |
| 检查覆盖 | 首轮逐行或后续差异的范围、文件与代码区段、规格/权限/数据/异常/模块/依赖/测试与无关改动、未覆盖原因、依赖与生成文件的单列检查方式 |
| 解读与排查入口 | 对应 A25 解读版本与已覆盖模块、A26 同类问题排查记录 |
| 发现与处置 | 编号、位置、严重度、预期/实际、证据、处理人和状态 |
| 复评与集成 | 新候选、重验结果、剩余风险、合并事实 |

元数据必须包含实例ID、版本、状态、责任角色、输入版本、确认来源、下游用途、未决项。字段未知标明原因；建议与事实分开。

## 质量标准与边界

发现有位置、预期实际、严重度、处置及复验，意见有证据；覆盖区分首轮逐行与后续差异，未覆盖写明原因。检查候选的规则、异常、数据、模块和测试；区分本地评审与外部平台事实。首轮系统审查逐行覆盖范围内全部自有实现，后续审查覆盖差异与受影响路径，大范围重写重新建立覆盖范围而不沿用已失效结论；全部覆盖不等于证明不存在缺陷，代码审查不替代独立验收。规则变化先更新来源，相关测试/运行记录标为待重验，旧结果保留原适用版本。

- 不足示例：“LGTM，代码很清晰”。
- 可判定示例：“发现服务层未校验Viewer，直接API写入成功；阻断集成，修复后重测”。

## 人驱动 AI 的操作链

依[提示词协议](../practices/prompt-protocol.md)取得参数。开始时人提供目标与输入位置；AI先读取事实，缺关键规则才追问。选择/修订用真实人的反馈或既有授权，不要求每一步重新批准。只写本文需文件读写；验证/执行代码另需终端和目标环境，UI需浏览器。

### A12-START

```text
[A12-START] 请为 {项目} 的 {目标} 开始准备 A12 代码与制品评审记录。先读取 {输入路径}：候选快照、确认规格、差异、测试与运行证据。检查候选的规则、异常、数据、模块和测试；区分本地评审与外部平台事实。列事实、缺口与下一步；可发现的事实直接核对，不重复问人。
```

### A12-CLARIFY

```text
[A12-CLARIFY] 请澄清 代码与制品评审记录 的 {问题}。先读 {输入路径} 并说明冲突来源，给出会改变结果的选项和取舍。重点检查：发现有位置、预期实际、严重度、处置及复验，意见有证据；覆盖区分首轮逐行与后续差异，未覆盖写明原因。未知关键规则暂停定案，已明确内容继续起草。
```

### A12-SELECT

```text
[A12-SELECT] 依据 {确认来源}，本轮对 代码与制品评审记录 采用 {已选方案}，适用范围是 {目标}。请记录决定、来源、影响和未确认事项；先核对来源真实存在，再更新状态，不把建议写成人的批准。
```

### A12-GENERATE

```text
[A12-GENERATE] 请依据 {输入路径} 为 {目标} 生成 A12 代码与制品评审记录，写入 {输出路径}，使用 model/templates/A12-review.md。检查候选的规则、异常、数据、模块和测试；区分本地评审与外部平台事实。逐章填写规范要求，未知和不适用说明原因；涉及运行结果必须来源于真实工具，未执行不得填通过；返回文件、版本和实际检查。
```

### A12-REVIEW

```text
[A12-REVIEW] 请按下游使用者的视角审阅 {制品路径}：集成责任人、修复者和后续维护者。检查 发现有位置、预期实际、严重度、处置及复验，意见有证据；覆盖区分首轮逐行与后续差异，未覆盖写明原因。逐项给出位置、预期/实际、影响与建议，区分缺输入和内容错误；不直接改变已确认标准。
```

### A12-REVISE

```text
[A12-REVISE] 请根据 {反馈} 修订 {制品路径}，保留来源和版本关系。重点仍是：检查候选的规则、异常、数据、模块和测试；区分本地评审与外部平台事实。先列影响，再修改获准内容，同步关联制品并在 A16 标记需重验的证据；业务规则变化无确认来源时暂停相关改动。
```

### A12-VERIFY

```text
[A12-VERIFY] 请独立核对 {制品路径} 的候选 {候选}，依据 {输入路径} 与 A12 规范。验证 发现有位置、预期实际、严重度、处置及复验，意见有证据；覆盖区分首轮逐行与后续差异，未覆盖写明原因。给出通过/失败/无法判定/阻塞，附步骤、环境、版本和证据；只读产品实现，不以生成者总结当结果。
```

### A12-HANDOFF

```text
[A12-HANDOFF] 请把 代码与制品评审记录 交给下一执行者，保存到 {交接路径}。明确 集成责任人、修复者和后续维护者，记录输入/输出版本、真实检查、未决项及下一条指令。接手者应能只凭文件继续，涉及运行中的服务先标记需要复查状态。
```

### A12-FAILURE

```text
[A12-FAILURE] 处理生成或验证 代码与制品评审记录 时发生的 {错误}。读取实际输出、当前版本和 A12 输入要求，判断是工具/环境、规格缺失还是实现问题。记录已尝试方案和影响；仅执行已授权的安全恢复，不放宽验收、不伪造结果。
```

## 完成、更新与交接

检查必填项、来源、质量标准和下游可用性；每次修改按版本更新，不覆盖旧确认历史。草稿完成不等于业务确认，候选验证不等于已发布。无证据的运行结论保持无法判定。交接给上述使用者，失败按 FAILURE 返回相关阶段。
