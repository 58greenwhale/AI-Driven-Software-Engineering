# A28 模块蓝图

## 用途与生命周期

- 适用与触发：每个需要独立原型上下文的业务模块使用；模块边界、能力地图、跨模块关系或功能清单变化时更新。
- 生产者：人驱动的 AI；责任角色：模块产品/技术责任人。
- 输入：所属系统 A29、A01、A02、A04、A07、A10、已有 A03、代码与产品资料、相关模块资料和开发人员回答。
- 使用者与用途：模块功能实现者、架构与领域责任人、审查者、独立验收者和后续会话接手者。
- 输出：项目内模块目录的 `module-blueprint.md`；实例、版本、来源及失效遵循[约定](../conventions.md)。
- 配套：[模板](../templates/A28-module-blueprint.md) · [教学填写示例](../../examples/focustask/docs/artifact-examples/A28-module-blueprint.md)。

## 必填内容与字段含义

| 章节 | 必须回答 |
| --- | --- |
| 模块定位与边界 | 模块 ID、目标、职责、业务上下文、包含范围、非目标和 A01 关系 |
| 能力地图与功能清单 | 功能编号、名称、优先级、状态、A03 路径、依赖、前置条件和完成关系 |
| 概念领域模型 | 核心实体、关系、生命周期、跨功能不变量和 A02 来源 |
| 角色与端到端流程 | 角色职责、主流程、关键分支、跨功能流程和外部参与者 |
| 模块关系与数据流 | 依赖模块、接口、事件、数据所有权、读写边界、外部系统和失败传播 |
| UI/API/数据约束摘要 | 已确认入口、状态、错误语义、数据边界、非功能约束及 A04/A05/A07 来源 |
| 原型边界与假设 | 真实/模拟行为、暂不实现项、未确认交互、夹具和解除条件 |
| 关联制品与版本 | A01/A02/A03/A04/A07/A10/A13/A16 路径、版本、状态和用途 |
| 未决事项与变更影响 | 问题、来源、影响范围、责任人、决定状态和下一步 |
| 确认与 handoff | 确认人、确认版本、复核意见、剩余风险、接手入口和下一条指令 |

每个实例必须有稳定模块 ID，例如 `orders`，并记录所属系统 A29 路径和版本；每个功能点 A03 必须记录所属模块 ID 和 A28 路径。A28 只保存摘要、索引和关系，不复制 A02/A03/A04/A10 的完整权威细节；冲突时标记来源、影响和待决定事项。

## 质量标准与边界

模块目标、边界、功能地图、跨模块关系和原型假设可从本文直接找到；每项摘要都有来源和版本。A02 负责正式领域与权限规则，A03 负责单项功能细节，A04 负责技术契约，A10 负责本轮实施安排，A13 负责会话级交接。A28 与这些制品冲突时不能覆盖权威来源。

- 不足示例：只列“订单模块包含创建和支付”，没有模块边界、功能路径、状态关系或来源。
- 可判定示例：`orders` 蓝图列出草稿、支付、取消和查询功能，分别链接 A03，说明订单与库存模块的数据关系，并标记支付规则以 A02 为准。

## 人驱动 AI 的操作链

依[提示词协议](../practices/prompt-protocol.md)取得参数。主模型整理资料和问题，开发人员回答关键问题并确认；其他模型复核是可选只读质量环节，复核意见不能自动成为业务确认。

### A28-START

```text
[A28-START] 请为 {模块 ID} 盘点模块蓝图输入。读取 {输入路径}：A01/A02/A04/A07/A10、已有 A03、代码事实、产品资料和相关模块。列出已知事实、缺口、冲突、候选功能点和需要开发人员回答的问题，不补充未确认业务规则。
```

### A28-GENERATE

```text
[A28-GENERATE] 请依据 {输入路径} 使用 model/templates/A28-module-blueprint.md 生成 {模块 ID} 模块蓝图草稿，写入 {输出路径}。建立模块边界、能力地图、概念模型摘要、角色流程、跨模块关系、原型假设和关联制品索引。每项事实记录来源；未知内容标为待确认、模拟或不适用。
```

### A28-CLARIFY

```text
[A28-CLARIFY] 请针对 {模块蓝图问题} 读取 {输入路径}，按影响排序列出需要开发人员回答的问题和选项。记录回答来源、适用范围、影响章节及需要同步的 A02/A03/A04/A10；可从仓库发现的事实直接核对，不重复询问。
```

### A28-REVIEW

```text
[A28-REVIEW] 请只读复核 {制品路径} 的模块边界、功能覆盖、关系完整性、来源一致性、重复定义、未决项和下游可实施性。区分事实、建议和待确认；不能修改权威制品或把建议写成确认。
```

### A28-REVISE

```text
[A28-REVISE] 请根据开发人员确认和 {复核意见} 修订 {制品路径}。先列影响，再修改获准内容，更新关联制品版本和失效/待重验项；业务语义没有确认来源时暂停相关改动。
```

### A28-HANDOFF

```text
[A28-HANDOFF] 请交付已确认的 {制品路径} 作为模块级 handoff。记录模块版本、关联 A03 清单、权威制品版本、未决事项、剩余风险和下一条原型构建指令；说明 A28 不替代 A13 会话交接。
```

## 完成、更新与交接

检查章节、来源、版本、功能清单和下游可用性；确认人和确认版本必须真实记录。草稿完成不等于模块确认，复核建议不等于业务批准。A28 版本变化保留旧版本关系；权威制品变化后标记摘要和关联版本待更新。
