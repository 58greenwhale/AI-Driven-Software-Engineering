# A11 实现包

## 用途与生命周期

- 适用与触发：功能变更必要；源代码为主体，清单不能替代；功能实现、修复或已确认重构。
- 生产者：人驱动的 AI；责任角色：实现责任人。
- 输入：就绪任务、确认规格/契约、工程基线、测试策略。
- 使用者与用途：验证者、评审者、构建与发布流程。
- 输出：项目内 `app/ 与 docs/implementation.md`；实例、版本、来源及失效遵循[约定](../conventions.md)。
- 配套：[模板](../../templates/A11-implementation.md) · [教学填写示例](../../examples/focustask/docs/artifact-examples/A11-implementation.md)。

## 必填内容与字段含义

| 章节 | 必须回答 |
| --- | --- |
| 目标与候选 | 任务、范围、确认规格版本、源码提交或快照 |
| 演化来源 | 前序原型版本、驱动本轮的反馈与确认行为、部分调整或整体替换的范围 |
| 改动与接口 | 修改文件、用途、输入输出、模块影响 |
| 数据与依赖 | 迁移、唯一约束、锁文件、安全和配置变化 |
| 测试与自检 | AC映射、执行命令、结果、失败及原因 |
| 交付与遗留 | 证据索引、待验收项、已知风险、下一步 |

元数据必须包含实例ID、版本、状态、责任角色、输入版本、确认来源、下游用途、未决项。字段未知标明原因；建议与事实分开。

## 质量标准与边界

差异和AC一一对应，测试能发现目标缺陷，正常产物无演练后门；演化来源与前序版本可追溯。按确认契约实现业务、安全、一致性及模块边界，保存源码版本与差异。实现可以部分调整或整体替换代码，整体替换仍属演化：演化关系通过目标、反馈、确认行为与版本追踪保持，版本与确认来源记入 A23。规则变化先更新来源，相关测试/运行记录标为待重验，旧结果保留原适用版本。

- 不足示例：“代码编译了所以功能完成”。
- 可判定示例：“候选包含 API/表单/迁移/测试；五项检查实际通过后移交 AC 逐项验证”。

## 人驱动 AI 的操作链

依[提示词协议](../practices/prompt-protocol.md)取得参数。开始时人提供目标与输入位置；AI先读取事实，缺关键规则才追问。选择/修订用真实人的反馈或既有授权，不要求每一步重新批准。只写本文需文件读写；验证/执行代码另需终端和目标环境，UI需浏览器。

### A11-START

```text
[A11-START] 请为 {项目} 的 {目标} 开始准备 A11 实现包。先读取 {输入路径}：就绪任务、确认规格/契约、工程基线、测试策略。按确认契约实现业务、安全、一致性及模块边界，保存源码版本与差异。列事实、缺口与下一步；可发现的事实直接核对，不重复问人。
```

### A11-CLARIFY

```text
[A11-CLARIFY] 请澄清 实现包 的 {问题}。先读 {输入路径} 并说明冲突来源，给出会改变结果的选项和取舍。重点检查：差异和AC一一对应，测试能发现目标缺陷，正常产物无演练后门；演化来源与前序版本可追溯。未知关键规则暂停定案，已明确内容继续起草。
```

### A11-SELECT

```text
[A11-SELECT] 依据 {确认来源}，本轮对 实现包 采用 {已选方案}，适用范围是 {目标}。请记录决定、来源、影响和未确认事项；先核对来源真实存在，再更新状态，不把建议写成人的批准。
```

### A11-GENERATE

```text
[A11-GENERATE] 请依据 {输入路径} 为 {目标} 生成 A11 实现包，写入 {输出路径}，使用 templates/A11-implementation.md。按确认契约实现业务、安全、一致性及模块边界，保存源码版本与差异。逐章填写规范要求，未知和不适用说明原因；同时创建真正可运行的工程/代码与测试，清单不能替代实现；返回文件、版本和实际检查。
```

### A11-REVIEW

```text
[A11-REVIEW] 请按下游使用者的视角审阅 {制品路径}：验证者、评审者、构建与发布流程。检查 差异和AC一一对应，测试能发现目标缺陷，正常产物无演练后门；演化来源与前序版本可追溯。逐项给出位置、预期/实际、影响与建议，区分缺输入和内容错误；不直接改变已确认标准。
```

### A11-REVISE

```text
[A11-REVISE] 请根据 {反馈} 修订 {制品路径}，保留来源和版本关系。重点仍是：按确认契约实现业务、安全、一致性及模块边界，保存源码版本与差异。先列影响，再修改获准内容，同步关联制品并在 A16 标记需重验的证据；业务规则变化无确认来源时暂停相关改动。
```

### A11-VERIFY

```text
[A11-VERIFY] 请独立核对 {制品路径} 的候选 {候选}，依据 {输入路径} 与 A11 规范。验证 差异和AC一一对应，测试能发现目标缺陷，正常产物无演练后门；演化来源与前序版本可追溯。给出通过/失败/无法判定/阻塞，附步骤、环境、版本和证据；只读产品实现，不以生成者总结当结果。
```

### A11-HANDOFF

```text
[A11-HANDOFF] 请把 实现包 交给下一执行者，保存到 {交接路径}。明确 验证者、评审者、构建与发布流程，记录输入/输出版本、真实检查、未决项及下一条指令。接手者应能只凭文件继续，涉及运行中的服务先标记需要复查状态。
```

### A11-FAILURE

```text
[A11-FAILURE] 处理生成或验证 实现包 时发生的 {错误}。读取实际输出、当前版本和 A11 输入要求，判断是工具/环境、规格缺失还是实现问题。记录已尝试方案和影响；仅执行已授权的安全恢复，不放宽验收、不伪造结果。
```

## 完成、更新与交接

检查必填项、来源、质量标准和下游可用性；每次修改按版本更新，不覆盖旧确认历史。草稿完成不等于业务确认，候选验证不等于已发布。无证据的运行结论保持无法判定。交接给上述使用者，失败按 FAILURE 返回相关阶段。
