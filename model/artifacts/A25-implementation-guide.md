# A25 面向人的实现解读

## 用途与生命周期

- 适用与触发：首轮系统[原型审查](../stages/03-prototype-review.md)后必要；可按模块增量生成；代码变化后同步更新受影响解读与覆盖记录。
- 生产者：人驱动的 AI；责任角色：审查责任人。
- 输入：候选与代码版本、A11实现与测试、A03/A04/A05确认规格、A12覆盖记录、A24（如有）。
- 使用者与用途：产品与技术责任人分层审阅并下钻代码、后续维护者理解实现、独立验收者核对实现与规格关系。
- 输出：项目内 `docs/implementation-guide.md`；实例、版本、来源及失效遵循[约定](../conventions.md)。
- 配套：[模板](../templates/A25-implementation-guide.md) · [教学填写示例](../../examples/focustask/docs/artifact-examples/A25-implementation-guide.md)。

## 必填内容与字段含义

| 章节 | 必须回答 |
| --- | --- |
| 解读范围与代码版本 | 覆盖模块、依据提交或源码摘要、未覆盖部分及原因 |
| 模块关系与数据流 | 依赖方向、边界与接口、关键路径、外部依赖 |
| 规格到实现的映射 | A03/A05条目到代码位置与测试位置的对应 |
| 重要判断与设计理由 | 取舍、约束、替代方案与不选原因、关联A06 |
| 风险与需人决定的问题 | 风险及影响、待决问题、建议与所需确认来源 |
| 分层审阅入口 | 从概览下钻到代码的路径、按模块的追问起点 |

元数据必须包含实例ID、版本、状态、责任角色、输入版本、确认来源、下游用途、未决项。字段未知标明原因；建议与事实分开。

## 质量标准与边界

解读链接具体代码位置与版本，不整段复制代码充当解释；区分静态阅读得出的结论与实际运行验证的结论；不要求人手工编写说明，也不以机械逐行复述代替解释；代码变化后同步更新，失效结论标明适用版本。本文不替代A12的评审结论与覆盖记录，也不替代A14独立验收。

- 不足示例："系统分为前端和后端，结构清晰，逻辑合理。"
- 可判定示例："创建请求先经页面表单初检，再由服务端创建任务流程完成权限、项目状态与字段校验，并与幂等记录同事务写入（对应 AC-07/AC-08/AC-11）；测试位于服务端创建用例；解读依据代码版本 teaching-1，浏览器验证未执行。"

## 人驱动 AI 的操作链

依[提示词协议](../practices/prompt-protocol.md)取得参数。开始时人提供候选、代码版本与关注模块；AI先读取实现与规格，缺关键规则才追问。选择/修订用真实人的反馈或既有授权，不要求每一步重新批准。只写本文需文件读写；核对运行行为另需终端和目标环境，UI需浏览器。

### A25-START

```text
[A25-START] 请为 {项目} 的 {候选} 开始准备 A25 面向人的实现解读。先读取 {输入路径}：实现与测试、A03/A04/A05 规格、A12 覆盖记录。确认代码版本与解读范围，列出模块清单、人已关注的部分与未覆盖模块；可发现的事实直接核对，不重复问人。
```

### A25-CLARIFY

```text
[A25-CLARIFY] 请澄清 面向人的实现解读 的 {问题}。先读 {输入路径} 并说明冲突来源，给出会改变结果的选项和取舍。重点检查：规格与实现是否存在语义差异、设计理由是否有来源、风险是否需要人决定。未知关键规则暂停定案，已明确内容继续起草。
```

### A25-SELECT

```text
[A25-SELECT] 依据 {确认来源}，本轮对 面向人的实现解读 采用 {已选方案}，适用范围是 {模块或候选}。请记录决定、来源、影响和未确认事项；先核对来源真实存在，再更新状态，不把自己的推断写成人的确认。
```

### A25-GENERATE

```text
[A25-GENERATE] 请依据 {输入路径} 为 {候选} 生成 A25 面向人的实现解读，写入 {输出路径}，使用 model/templates/A25-implementation-guide.md。按模块给出关系与数据流、A03/A05 到实现与测试位置的映射、重要判断与理由、风险与需人决定的问题，并提供可下钻的分层入口；每条结论链接代码位置与版本；未覆盖部分写明原因，不把静态阅读写成运行验证。
```

### A25-REVIEW

```text
[A25-REVIEW] 请按下游使用者的视角审阅 {制品路径}：产品与技术责任人、后续维护者、独立验收者。检查解读是否可下钻到具体代码、映射是否与当前版本一致、理由是否有来源、风险与待决问题是否明确。逐项给出位置、预期/实际、影响与建议，区分缺输入和内容错误；不直接改变已确认标准。
```

### A25-REVISE

```text
[A25-REVISE] 请根据 {反馈或代码变化} 修订 {制品路径}，保留来源和版本关系。重点仍是：模块关系、映射与设计理由是否随实现同步，失效结论是否标明适用版本。先列影响，再修改获准内容，同步 A12 覆盖记录与 A16 待重验项；业务规则变化无确认来源时暂停相关改动。
```

### A25-VERIFY

```text
[A25-VERIFY] 请独立核对 {制品路径} 与候选 {候选}，依据 {输入路径} 与 A25 规范。抽样验证映射的代码位置真实存在、行为描述与规格一致、未覆盖部分已说明。给出通过/失败/无法判定/阻塞，附步骤、版本和证据；只读产品实现，不以生成者总结当结果。
```

### A25-HANDOFF

```text
[A25-HANDOFF] 请把 面向人的实现解读 交给下一执行者，保存到 {交接路径}。明确审阅者、维护者与独立验收者，记录解读覆盖范围与代码版本、未覆盖部分、需人决定的问题及下一条指令。接手者应能只凭文件继续。
```

### A25-FAILURE

```text
[A25-FAILURE] 处理生成或验证 面向人的实现解读 时发生的 {错误}。读取实际输出、当前版本和 A25 输入要求，判断是工具/环境、代码不可读还是规格缺失。记录已尝试方案和影响；仅执行已授权的安全恢复，不用猜测填补无法核对的实现细节。
```

## 完成、更新与交接

检查必填项、来源、质量标准和下游可用性；代码变化后按版本更新，不覆盖旧解读的适用版本标识。解读完成不等于审查通过，也不等于验收通过。无证据的运行结论保持无法判定。交接给上述使用者，失败按 FAILURE 返回[原型审查](../stages/03-prototype-review.md)。
