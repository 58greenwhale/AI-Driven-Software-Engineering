# A24 工程化差距与重构方案

## 用途与生命周期

- 适用与触发：条件触发；开展[原型重构](../stages/02-prototype-refactoring.md)、模拟实现替换或整体重写时必要；无重构需要不强制生成。
- 生产者：人驱动的 AI；责任角色：技术责任人。
- 输入：当前实现与依赖、确认的A03行为、A04架构与契约、A07质量要求、A08工作规则、目标技术约束。
- 使用者与用途：实施重构的执行者、审查责任人、独立验收者。
- 输出：项目内 `docs/refactoring-plan.md`；实例、版本、来源及失效遵循[约定](../conventions.md)。
- 配套：[模板](../templates/A24-refactoring-plan.md) · [教学填写示例](../../examples/focustask/docs/artifact-examples/A24-refactoring-plan.md)。

## 必填内容与字段含义

| 章节 | 必须回答 |
| --- | --- |
| 当前与目标状态 | 技术栈与版本、架构与非功能现状、目标约束及其来源 |
| 差距清单 | 编号、领域、影响、严重度、依据位置 |
| 策略与步骤 | 保留/调整/替换决定、步骤与依赖、回退点、整体替换时的行为保持方式 |
| 行为映射与验证 | 确认行为到实现与测试位置的映射、检查方式、回归范围、A07关联 |
| 风险与失败恢复 | 剩余风险、阻塞与解除条件、失败恢复路径、需人决定的取舍 |

元数据必须包含实例ID、版本、状态、责任角色、输入版本、确认来源、下游用途、未决项。字段未知标明原因；建议与事实分开。

## 质量标准与边界

差距有依据位置与影响，不写笼统评价；策略区分保留、调整与替换并说明行为保持方式；整体替换列出行为基线与追踪方式；验证方式可执行，未执行明确标注；重要取舍有A06或标为待决。本方案不改变已确认业务行为，新业务取舍返回[原型构建](../stages/01-prototype-building.md)澄清；实施任务统一关联A10，不在本文重复排期。

- 不足示例："重构为更清晰的分层架构，提升可维护性与性能。"
- 可判定示例："G-03 幂等键校验位于页面层，目标移至服务端并与任务写入同事务；保持 AC-08 行为，回归用例为幂等重试两项；检查未执行，标为待验证。"

## 人驱动 AI 的操作链

依[提示词协议](../practices/prompt-protocol.md)取得参数。开始时人提供重构目标与技术约束来源；AI先读取当前实现与确认行为，缺关键规则才追问。选择/修订用真实人的取舍或既有授权，不要求每一步重新批准。只写本文需文件读写；核对现状与执行验证另需终端和目标环境。

### A24-START

```text
[A24-START] 请为 {项目} 的 {重构目标} 开始准备 A24 工程化差距与重构方案。先读取 {输入路径}：当前实现与依赖、A03 确认行为、A04 架构与契约、A07 质量要求、A08 工作规则。列出当前状态、目标约束与必须保持的行为；可发现的事实直接核对，不重复问人。
```

### A24-CLARIFY

```text
[A24-CLARIFY] 请澄清 工程化差距与重构方案 的 {问题}。先读 {输入路径} 并说明冲突来源，给出会改变结果的选项和取舍。重点检查：目标技术约束是否有来源、行为保持范围是否明确、非功能要求是否可测量。未知关键规则暂停定案，已明确内容继续起草。
```

### A24-SELECT

```text
[A24-SELECT] 依据 {确认来源}，本轮对 工程化差距与重构方案 采用 {已选方案}，适用范围是 {重构目标}。请记录决定、来源、影响和未确认事项；影响多功能或难以逆转时准备 A06；先核对来源真实存在，不把技术偏好写成项目要求。
```

### A24-GENERATE

```text
[A24-GENERATE] 请依据 {输入路径} 为 {重构目标} 生成 A24 工程化差距与重构方案，写入 {输出路径}，使用 model/templates/A24-refactoring-plan.md。逐章填写当前与目标状态、差距清单、策略与步骤、行为映射与验证、风险与失败恢复；每项差距给依据位置；未知和不适用说明原因；未执行的检查标为待验证，不写成已通过。
```

### A24-REVIEW

```text
[A24-REVIEW] 请按下游使用者的视角审阅 {制品路径}：实施重构的执行者、审查责任人、独立验收者。检查差距是否有依据、策略是否说明行为保持、回归范围是否覆盖受影响路径、回退点是否可执行。逐项给出位置、预期/实际、影响与建议，区分缺输入和内容错误；不直接改变已确认标准。
```

### A24-REVISE

```text
[A24-REVISE] 请根据 {反馈} 修订 {制品路径}，保留来源和版本关系。重点仍是：差距依据、行为映射与验证方式是否随实现变化同步。先列影响，再修改获准内容，同步 A04/A07/A08/A10 与 A16，并标记需重验的证据；业务行为变化无确认来源时暂停相关改动。
```

### A24-VERIFY

```text
[A24-VERIFY] 请独立核对 {制品路径} 的候选 {重构候选}，依据 {输入路径} 与 A24 规范。验证差距是否按计划处理、确认行为是否保持或有正式变更、回归与适用检查是否真实运行。给出通过/失败/无法判定/阻塞，附命令、环境、版本和证据；不复用重构前旧结果冒充新证据。
```

### A24-HANDOFF

```text
[A24-HANDOFF] 请把 工程化差距与重构方案 交给下一执行者，保存到 {交接路径}。明确实施者、审查责任人与独立验收者，记录已处理差距、保持与变更的行为、更新的契约与工作规则、剩余风险及下一条指令。接手者应能只凭文件继续。
```

### A24-FAILURE

```text
[A24-FAILURE] 处理生成或验证 工程化差距与重构方案 时发生的 {错误}。读取实际输出、当前版本和 A24 输入要求，判断是工具/环境、方案不当还是实现问题；必要时恢复到上一个可运行版本并核对数据。记录已尝试方案和影响；仅执行已授权的安全恢复，不放宽验收、不伪造结果。
```

## 完成、更新与交接

检查必填项、来源、质量标准和下游可用性；技术约束或实现变化后按版本更新，不覆盖旧确认历史。方案完成不等于重构已实施，实施结果以真实检查为准。无证据的运行结论保持无法判定。交接给上述使用者，失败按 FAILURE 返回[原型重构](../stages/02-prototype-refactoring.md)。
