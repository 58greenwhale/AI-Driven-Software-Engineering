# A16 制品与验收追踪表

## 用途与生命周期

- 适用与触发：必要；表格即可，可自动汇总但需查内容；每次生成、修订、验证、发布后增量更新。
- 生产者：人驱动的 AI；责任角色：质量/协调责任人。
- 输入：所有已产生制品、任务/AC编号、实际测试和证据。
- 使用者与用途：验收、变更分析、发布审计和模型评价。
- 输出：项目内 `evidence/traceability.md`；实例、版本、来源及失效遵循[约定](../conventions.md)。
- 配套：[模板](../../templates/A16-traceability.md) · [教学填写示例](../../examples/focustask/docs/artifact-examples/A16-traceability.md)。

## 必填内容与字段含义

| 章节 | 必须回答 |
| --- | --- |
| 范围与版本 | 项目、任务/版本、标准与候选快照 |
| 追踪矩阵 | AC→设计→实现→测试→证据→评审→发布 |
| 覆盖与失效 | 缺失、不适用理由、证据适用版本和待重验 |
| 检查记录 | 断链、孤立制品、测试内容核对、下一步 |

元数据必须包含实例ID、版本、状态、责任角色、输入版本、确认来源、下游用途、未决项。字段未知标明原因；建议与事实分开。

## 质量标准与边界

文件存在不等于覆盖，读取断言并绑定版本，变更后标失效。从本项目每条AC追踪设计、实现、测试与证据，未生成引用记待生成。规则变化先更新来源，相关测试/运行记录标为待重验，旧结果保留原适用版本。

- 不足示例：“需求已关联测试，全部覆盖”。
- 可判定示例：“AC-08→幂等契约→创建服务→同键重试测试→指定运行结果；未运行记待验”。

## 人驱动 AI 的操作链

依[提示词协议](../practices/prompt-protocol.md)取得参数。开始时人提供目标与输入位置；AI先读取事实，缺关键规则才追问。选择/修订用真实人的反馈或既有授权，不要求每一步重新批准。只写本文需文件读写；验证/执行代码另需终端和目标环境，UI需浏览器。

### A16-START

```text
[A16-START] 请为 {项目} 的 {目标} 开始准备 A16 制品与验收追踪表。先读取 {输入路径}：所有已产生制品、任务/AC编号、实际测试和证据。从本项目每条AC追踪设计、实现、测试与证据，未生成引用记待生成。列事实、缺口与下一步；可发现的事实直接核对，不重复问人。
```

### A16-CLARIFY

```text
[A16-CLARIFY] 请澄清 制品与验收追踪表 的 {问题}。先读 {输入路径} 并说明冲突来源，给出会改变结果的选项和取舍。重点检查：文件存在不等于覆盖，读取断言并绑定版本，变更后标失效。未知关键规则暂停定案，已明确内容继续起草。
```

### A16-SELECT

```text
[A16-SELECT] 依据 {确认来源}，本轮对 制品与验收追踪表 采用 {已选方案}，适用范围是 {目标}。请记录决定、来源、影响和未确认事项；先核对来源真实存在，再更新状态，不把建议写成人的批准。
```

### A16-GENERATE

```text
[A16-GENERATE] 请依据 {输入路径} 为 {目标} 生成 A16 制品与验收追踪表，写入 {输出路径}，使用 templates/A16-traceability.md。从本项目每条AC追踪设计、实现、测试与证据，未生成引用记待生成。逐章填写规范要求，未知和不适用说明原因；涉及运行结果必须来源于真实工具，未执行不得填通过；返回文件、版本和实际检查。
```

### A16-REVIEW

```text
[A16-REVIEW] 请按下游使用者的视角审阅 {制品路径}：验收、变更分析、发布审计和模型评价。检查 文件存在不等于覆盖，读取断言并绑定版本，变更后标失效。逐项给出位置、预期/实际、影响与建议，区分缺输入和内容错误；不直接改变已确认标准。
```

### A16-REVISE

```text
[A16-REVISE] 请根据 {反馈} 修订 {制品路径}，保留来源和版本关系。重点仍是：从本项目每条AC追踪设计、实现、测试与证据，未生成引用记待生成。先列影响，再修改获准内容，同步关联制品并在 A16 标记需重验的证据；业务规则变化无确认来源时暂停相关改动。
```

### A16-VERIFY

```text
[A16-VERIFY] 请独立核对 {制品路径} 的候选 {候选}，依据 {输入路径} 与 A16 规范。验证 文件存在不等于覆盖，读取断言并绑定版本，变更后标失效。给出通过/失败/无法判定/阻塞，附步骤、环境、版本和证据；只读产品实现，不以生成者总结当结果。
```

### A16-HANDOFF

```text
[A16-HANDOFF] 请把 制品与验收追踪表 交给下一执行者，保存到 {交接路径}。明确 验收、变更分析、发布审计和模型评价，记录输入/输出版本、真实检查、未决项及下一条指令。接手者应能只凭文件继续，涉及运行中的服务先标记需要复查状态。
```

### A16-FAILURE

```text
[A16-FAILURE] 处理生成或验证 制品与验收追踪表 时发生的 {错误}。读取实际输出、当前版本和 A16 输入要求，判断是工具/环境、规格缺失还是实现问题。记录已尝试方案和影响；仅执行已授权的安全恢复，不放宽验收、不伪造结果。
```

## 完成、更新与交接

检查必填项、来源、质量标准和下游可用性；每次修改按版本更新，不覆盖旧确认历史。草稿完成不等于业务确认，候选验证不等于已发布。无证据的运行结论保持无法判定。交接给上述使用者，失败按 FAILURE 返回相关阶段。
