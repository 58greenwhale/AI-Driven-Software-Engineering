# A14 独立验收报告

## 用途与生命周期

- 适用与触发：必要；只读产品实现；候选自检后及影响行为的变更后。
- 生产者：人驱动的 AI；责任角色：独立验收责任人。
- 输入：确认的 AC、页面/非功能规则、指定候选、夹具与环境。
- 使用者与用途：集成与发布责任人、修复者。
- 输出：项目内 `evidence/acceptance.md`；实例、版本、来源及失效遵循[约定](../conventions.md)。
- 配套：[模板](../../templates/A14-acceptance.md) · [教学填写示例](../../examples/focustask/docs/artifact-examples/A14-acceptance.md)。

## 必填内容与字段含义

| 章节 | 必须回答 |
| --- | --- |
| 依据与环境 | 规格和候选版本、测试环境、数据、执行者和时间、独立性依据（职责、依据与记录） |
| 逐项结果 | AC、步骤、预期、实际、结论、证据 |
| 失败与缺口 | 严重度、复现、受影响功能、缺失能力 |
| 复验与结论 | 新旧候选、已修复、仍失败、适用范围与发布输入 |

元数据必须包含实例ID、版本、状态、责任角色、输入版本、确认来源、下游用途、未决项。字段未知标明原因；建议与事实分开。

## 质量标准与边界

每个AC有结果与可定位证据，失败包含复现与环境，验收者不改产品；自检与独立验收分别记录。从确认标准出发，按项目实际界面/接口/数据方式取证。独立性体现为职责、依据与执行记录，可以使用同种或不同 AI 工具；验收者只读固定候选，不为适配实现放宽标准，发现问题交回受影响活动，修复后对新候选复验。规则变化先更新来源，相关测试/运行记录标为待重验，旧结果保留原适用版本。

- 不足示例：“所有功能看起来正常，通过”。
- 可判定示例：“AC-09 预期403且无新增；观察201且计数+1，失败，附调用与快照”。

## 人驱动 AI 的操作链

依[提示词协议](../practices/prompt-protocol.md)取得参数。开始时人提供目标与输入位置；AI先读取事实，缺关键规则才追问。选择/修订用真实人的反馈或既有授权，不要求每一步重新批准。只写本文需文件读写；验证/执行代码另需终端和目标环境，UI需浏览器。

### A14-START

```text
[A14-START] 请为 {项目} 的 {目标} 开始准备 A14 独立验收报告。先读取 {输入路径}：确认的 AC、页面/非功能规则、指定候选、夹具与环境。从确认标准出发，按项目实际界面/接口/数据方式取证。列事实、缺口与下一步；可发现的事实直接核对，不重复问人。
```

### A14-CLARIFY

```text
[A14-CLARIFY] 请澄清 独立验收报告 的 {问题}。先读 {输入路径} 并说明冲突来源，给出会改变结果的选项和取舍。重点检查：每个AC有结果与可定位证据，失败包含复现与环境，验收者不改产品；自检与独立验收分别记录。未知关键规则暂停定案，已明确内容继续起草。
```

### A14-SELECT

```text
[A14-SELECT] 依据 {确认来源}，本轮对 独立验收报告 采用 {已选方案}，适用范围是 {目标}。请记录决定、来源、影响和未确认事项；先核对来源真实存在，再更新状态，不把建议写成人的批准。
```

### A14-GENERATE

```text
[A14-GENERATE] 请依据 {输入路径} 为 {目标} 生成 A14 独立验收报告，写入 {输出路径}，使用 templates/A14-acceptance.md。从确认标准出发，按项目实际界面/接口/数据方式取证。逐章填写规范要求，未知和不适用说明原因；涉及运行结果必须来源于真实工具，未执行不得填通过；返回文件、版本和实际检查。
```

### A14-REVIEW

```text
[A14-REVIEW] 请按下游使用者的视角审阅 {制品路径}：集成与发布责任人、修复者。检查 每个AC有结果与可定位证据，失败包含复现与环境，验收者不改产品；自检与独立验收分别记录。逐项给出位置、预期/实际、影响与建议，区分缺输入和内容错误；不直接改变已确认标准。
```

### A14-REVISE

```text
[A14-REVISE] 请根据 {反馈} 修订 {制品路径}，保留来源和版本关系。重点仍是：从确认标准出发，按项目实际界面/接口/数据方式取证。先列影响，再修改获准内容，同步关联制品并在 A16 标记需重验的证据；业务规则变化无确认来源时暂停相关改动。
```

### A14-VERIFY

```text
[A14-VERIFY] 请独立核对 {制品路径} 的候选 {候选}，依据 {输入路径} 与 A14 规范。验证 每个AC有结果与可定位证据，失败包含复现与环境，验收者不改产品；自检与独立验收分别记录。给出通过/失败/无法判定/阻塞，附步骤、环境、版本和证据；只读产品实现，不以生成者总结当结果。
```

### A14-HANDOFF

```text
[A14-HANDOFF] 请把 独立验收报告 交给下一执行者，保存到 {交接路径}。明确 集成与发布责任人、修复者，记录输入/输出版本、真实检查、未决项及下一条指令。接手者应能只凭文件继续，涉及运行中的服务先标记需要复查状态。
```

### A14-FAILURE

```text
[A14-FAILURE] 处理生成或验证 独立验收报告 时发生的 {错误}。读取实际输出、当前版本和 A14 输入要求，判断是工具/环境、规格缺失还是实现问题。记录已尝试方案和影响；仅执行已授权的安全恢复，不放宽验收、不伪造结果。
```

## 完成、更新与交接

检查必填项、来源、质量标准和下游可用性；每次修改按版本更新，不覆盖旧确认历史。草稿完成不等于业务确认，候选验证不等于已发布。无证据的运行结论保持无法判定。交接给上述使用者，失败按 FAILURE 返回相关阶段。
