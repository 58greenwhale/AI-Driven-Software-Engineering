# A02 领域与权限规则

## 用途与生命周期

- 适用与触发：有业务数据时必要；术语可独立文件；业务实体、状态、权限或数据约束发生变化。
- 生产者：人驱动的 AI；责任角色：业务责任人。
- 输入：A01、原领域模型、权限矩阵、状态 ADR。
- 使用者与用途：接口与数据设计者、服务端实现和权限测试。
- 输出：项目内 `docs/domain-permissions.md`；实例、版本、来源及失效遵循[约定](../conventions.md)。
- 配套：[模板](../../templates/A02-domain-permissions.md) · [教学填写示例](../../examples/focustask/docs/artifact-examples/A02-domain-permissions.md)。

## 必填内容与字段含义

| 章节 | 必须回答 |
| --- | --- |
| 术语与实体 | 术语定义；字段类型、必填、唯一、关系与来源 |
| 状态与转换 | 当前状态、操作、下一状态、允许角色和失败条件 |
| 权限矩阵 | 角色×操作；界面和服务端分别约束 |
| 一致性与时间 | 幂等、并发、事务、UTC与日期、删除保留 |
| 边界验证与决策 | 每条规则映射用例；缺失和冲突来源 |

元数据必须包含实例ID、版本、状态、责任角色、输入版本、确认来源、下游用途、未决项。字段未知标明原因；建议与事实分开。

## 质量标准与边界

每项允许/拒绝都有数据结果和验证方法；边界和状态变化有规则。按项目真实角色、实体、状态、时间与一致性约束建立规则，不新增未确认业务。规则变化先更新来源，相关测试/运行记录标为待重验，旧结果保留原适用版本。

- 不足示例：“管理员可以管理，其他人按权限使用”。
- 可判定示例：“Viewer 调用创建 API 返回 403，任务数不变；非成员返回 404”。

## 人驱动 AI 的操作链

依[提示词协议](../practices/prompt-protocol.md)取得参数。开始时人提供目标与输入位置；AI先读取事实，缺关键规则才追问。选择/修订用真实人的反馈或既有授权，不要求每一步重新批准。只写本文需文件读写；验证/执行代码另需终端和目标环境，UI需浏览器。

### A02-START

```text
[A02-START] 请为 {项目} 的 {目标} 开始准备 A02 领域与权限规则。先读取 {输入路径}：A01、原领域模型、权限矩阵、状态 ADR。按项目真实角色、实体、状态、时间与一致性约束建立规则，不新增未确认业务。列事实、缺口与下一步；可发现的事实直接核对，不重复问人。
```

### A02-CLARIFY

```text
[A02-CLARIFY] 请澄清 领域与权限规则 的 {问题}。先读 {输入路径} 并说明冲突来源，给出会改变结果的选项和取舍。重点检查：每项允许/拒绝都有数据结果和验证方法；边界和状态变化有规则。未知关键规则暂停定案，已明确内容继续起草。
```

### A02-SELECT

```text
[A02-SELECT] 依据 {确认来源}，本轮对 领域与权限规则 采用 {已选方案}，适用范围是 {目标}。请记录决定、来源、影响和未确认事项；先核对来源真实存在，再更新状态，不把建议写成人的批准。
```

### A02-GENERATE

```text
[A02-GENERATE] 请依据 {输入路径} 为 {目标} 生成 A02 领域与权限规则，写入 {输出路径}，使用 templates/A02-domain-permissions.md。按项目真实角色、实体、状态、时间与一致性约束建立规则，不新增未确认业务。逐章填写规范要求，未知和不适用说明原因；涉及运行结果必须来源于真实工具，未执行不得填通过；返回文件、版本和实际检查。
```

### A02-REVIEW

```text
[A02-REVIEW] 请按下游使用者的视角审阅 {制品路径}：接口与数据设计者、服务端实现和权限测试。检查 每项允许/拒绝都有数据结果和验证方法；边界和状态变化有规则。逐项给出位置、预期/实际、影响与建议，区分缺输入和内容错误；不直接改变已确认标准。
```

### A02-REVISE

```text
[A02-REVISE] 请根据 {反馈} 修订 {制品路径}，保留来源和版本关系。重点仍是：按项目真实角色、实体、状态、时间与一致性约束建立规则，不新增未确认业务。先列影响，再修改获准内容，同步关联制品并在 A16 标记需重验的证据；业务规则变化无确认来源时暂停相关改动。
```

### A02-VERIFY

```text
[A02-VERIFY] 请独立核对 {制品路径} 的候选 {候选}，依据 {输入路径} 与 A02 规范。验证 每项允许/拒绝都有数据结果和验证方法；边界和状态变化有规则。给出通过/失败/无法判定/阻塞，附步骤、环境、版本和证据；只读产品实现，不以生成者总结当结果。
```

### A02-HANDOFF

```text
[A02-HANDOFF] 请把 领域与权限规则 交给下一执行者，保存到 {交接路径}。明确 接口与数据设计者、服务端实现和权限测试，记录输入/输出版本、真实检查、未决项及下一条指令。接手者应能只凭文件继续，涉及运行中的服务先标记需要复查状态。
```

### A02-FAILURE

```text
[A02-FAILURE] 处理生成或验证 领域与权限规则 时发生的 {错误}。读取实际输出、当前版本和 A02 输入要求，判断是工具/环境、规格缺失还是实现问题。记录已尝试方案和影响；仅执行已授权的安全恢复，不放宽验收、不伪造结果。
```

## 完成、更新与交接

检查必填项、来源、质量标准和下游可用性；每次修改按版本更新，不覆盖旧确认历史。草稿完成不等于业务确认，候选验证不等于已发布。无证据的运行结论保持无法判定。交接给上述使用者，失败按 FAILURE 返回相关阶段。
