# A15 缺陷与变更单

## 用途与生命周期

- 适用与触发：条件触发；缺陷和需求变更标不同类型；问题或范围变化出现时，早于改代码。
- 生产者：人驱动的 AI；责任角色：变更责任人。
- 输入：失败证据、用户新要求、维护技术反馈。
- 使用者与用途：需求/设计/实现的责任人，回归与发布者。
- 输出：项目内 `docs/changes/CHANGE-001.md`；实例、版本、来源及失效遵循[约定](../conventions.md)。
- 配套：[模板](../../templates/A15-change-defect.md) · [教学填写示例](../../examples/focustask/docs/artifact-examples/A15-change-defect.md)。

## 必填内容与字段含义

| 章节 | 必须回答 |
| --- | --- |
| 来源与类型 | 缺陷/变更/演练、触发者、版本、背景 |
| 现状与期望 | 复现或新行为、旧标准、新标准、影响用户 |
| 影响与选择 | 规格、接口、数据、代码、测试、发布、风险与备选 |
| 决定与执行 | 确认来源、负责人、任务、失败恢复 |
| 回归与关闭 | 用例、证据、新候选、残余风险和关闭条件 |

元数据必须包含实例ID、版本、状态、责任角色、输入版本、确认来源、下游用途、未决项。字段未知标明原因；建议与事实分开。

## 质量标准与边界

每项影响关联重验，原标准变化有确认来源，关闭有验证证据。先区分新要求、旧规格缺陷与人为演练，再影响分析和修改。规则变化先更新来源，相关测试/运行记录标为待重验，旧结果保留原适用版本。

- 不足示例：“列表不好用，顺便重构全部”。
- 可判定示例：“CHANGE-001 增加status筛选，影响列表API/query/UI/空状态/回归，不修改创建默认状态”。

## 人驱动 AI 的操作链

依[提示词协议](../practices/prompt-protocol.md)取得参数。开始时人提供目标与输入位置；AI先读取事实，缺关键规则才追问。选择/修订用真实人的反馈或既有授权，不要求每一步重新批准。只写本文需文件读写；验证/执行代码另需终端和目标环境，UI需浏览器。

### A15-START

```text
[A15-START] 请为 {项目} 的 {目标} 开始准备 A15 缺陷与变更单。先读取 {输入路径}：失败证据、用户新要求、维护技术反馈。先区分新要求、旧规格缺陷与人为演练，再影响分析和修改。列事实、缺口与下一步；可发现的事实直接核对，不重复问人。
```

### A15-CLARIFY

```text
[A15-CLARIFY] 请澄清 缺陷与变更单 的 {问题}。先读 {输入路径} 并说明冲突来源，给出会改变结果的选项和取舍。重点检查：每项影响关联重验，原标准变化有确认来源，关闭有验证证据。未知关键规则暂停定案，已明确内容继续起草。
```

### A15-SELECT

```text
[A15-SELECT] 依据 {确认来源}，本轮对 缺陷与变更单 采用 {已选方案}，适用范围是 {目标}。请记录决定、来源、影响和未确认事项；先核对来源真实存在，再更新状态，不把建议写成人的批准。
```

### A15-GENERATE

```text
[A15-GENERATE] 请依据 {输入路径} 为 {目标} 生成 A15 缺陷与变更单，写入 {输出路径}，使用 templates/A15-change-defect.md。先区分新要求、旧规格缺陷与人为演练，再影响分析和修改。逐章填写规范要求，未知和不适用说明原因；涉及运行结果必须来源于真实工具，未执行不得填通过；返回文件、版本和实际检查。
```

### A15-REVIEW

```text
[A15-REVIEW] 请按下游使用者的视角审阅 {制品路径}：需求/设计/实现的责任人，回归与发布者。检查 每项影响关联重验，原标准变化有确认来源，关闭有验证证据。逐项给出位置、预期/实际、影响与建议，区分缺输入和内容错误；不直接改变已确认标准。
```

### A15-REVISE

```text
[A15-REVISE] 请根据 {反馈} 修订 {制品路径}，保留来源和版本关系。重点仍是：先区分新要求、旧规格缺陷与人为演练，再影响分析和修改。先列影响，再修改获准内容，同步关联制品并在 A16 标记需重验的证据；业务规则变化无确认来源时暂停相关改动。
```

### A15-VERIFY

```text
[A15-VERIFY] 请独立核对 {制品路径} 的候选 {候选}，依据 {输入路径} 与 A15 规范。验证 每项影响关联重验，原标准变化有确认来源，关闭有验证证据。给出通过/失败/无法判定/阻塞，附步骤、环境、版本和证据；只读产品实现，不以生成者总结当结果。
```

### A15-HANDOFF

```text
[A15-HANDOFF] 请把 缺陷与变更单 交给下一执行者，保存到 {交接路径}。明确 需求/设计/实现的责任人，回归与发布者，记录输入/输出版本、真实检查、未决项及下一条指令。接手者应能只凭文件继续，涉及运行中的服务先标记需要复查状态。
```

### A15-FAILURE

```text
[A15-FAILURE] 处理生成或验证 缺陷与变更单 时发生的 {错误}。读取实际输出、当前版本和 A15 输入要求，判断是工具/环境、规格缺失还是实现问题。记录已尝试方案和影响；仅执行已授权的安全恢复，不放宽验收、不伪造结果。
```

## 完成、更新与交接

检查必填项、来源、质量标准和下游可用性；每次修改按版本更新，不覆盖旧确认历史。草稿完成不等于业务确认，候选验证不等于已发布。无证据的运行结论保持无法判定。交接给上述使用者，失败按 FAILURE 返回相关阶段。
