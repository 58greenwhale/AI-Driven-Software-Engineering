# A07 验证策略

## 用途与生命周期

- 适用与触发：必要；不能实现后倒推放宽标准；实现前建立；风险或范围变化后更新。
- 生产者：人驱动的 AI；责任角色：质量/技术责任人。
- 输入：A01–A05、非功能要求和风险。
- 使用者与用途：编码者先编写有意义测试，验收者准备环境和判据。
- 输出：项目内 `docs/test-strategy.md`；实例、版本、来源及失效遵循[约定](../conventions.md)。
- 配套：[模板](../templates/A07-verification-strategy.md) · [教学填写示例](../../examples/focustask/docs/artifact-examples/A07-verification-strategy.md)。

## 必填内容与字段含义

| 章节 | 必须回答 |
| --- | --- |
| 验证类型与责任 | 体验检查、行为保持、工程质量、审查后回归、视觉交互验证、独立验收的判据、执行者与记录位置 |
| 风险与覆盖 | 风险、需求/AC映射、优先级、测试层次 |
| 环境与数据 | 版本、隔离策略、角色夹具、可控时钟和故障注入 |
| 命令与判据 | 检查入口、成功标准、失败/无法运行处理 |
| 非功能与UI | 指标、浏览器、视口、可访问性、原始结果 |
| 证据与重验 | 记录格式、版本摘要、保留、变更失效范围 |

元数据必须包含实例ID、版本、状态、责任角色、输入版本、确认来源、下游用途、未决项。字段未知标明原因；建议与事实分开。

## 质量标准与边界

覆盖确认规则和高风险异常，而不仅是实现已有正常分支；六类验证分别定判据、执行者与记录位置。按功能风险选择适用测试层，先确定判据再实现。六类验证不互相替代：体验检查由人在原型上执行并记入 A23，行为保持由重构与回归覆盖，工程质量由 lint、类型、单元与构建判定，审查后回归针对差异与受影响路径并记入 A12，视觉交互验证按 A05 的视口与状态，独立验收只读固定候选并记入 A14。规则变化先更新来源，相关测试/运行记录标为待重验，旧结果保留原适用版本。

- 不足示例：“测试覆盖率达到80%就通过”。
- 可判定示例：“Viewer 直接 API 被拒绝且计数不变；两次同键并发创建只产生一条”。

## 人驱动 AI 的操作链

依[提示词协议](../practices/prompt-protocol.md)取得参数。开始时人提供目标与输入位置；AI先读取事实，缺关键规则才追问。选择/修订用真实人的反馈或既有授权，不要求每一步重新批准。只写本文需文件读写；验证/执行代码另需终端和目标环境，UI需浏览器。

### A07-START

```text
[A07-START] 请为 {项目} 的 {目标} 开始准备 A07 验证策略。先读取 {输入路径}：A01–A05、非功能要求和风险。按功能风险选择适用测试层，先确定判据再实现。列事实、缺口与下一步；可发现的事实直接核对，不重复问人。
```

### A07-CLARIFY

```text
[A07-CLARIFY] 请澄清 验证策略 的 {问题}。先读 {输入路径} 并说明冲突来源，给出会改变结果的选项和取舍。重点检查：覆盖确认规则和高风险异常，而不仅是实现已有正常分支；六类验证分别定判据、执行者与记录位置。未知关键规则暂停定案，已明确内容继续起草。
```

### A07-SELECT

```text
[A07-SELECT] 依据 {确认来源}，本轮对 验证策略 采用 {已选方案}，适用范围是 {目标}。请记录决定、来源、影响和未确认事项；先核对来源真实存在，再更新状态，不把建议写成人的批准。
```

### A07-GENERATE

```text
[A07-GENERATE] 请依据 {输入路径} 为 {目标} 生成 A07 验证策略，写入 {输出路径}，使用 model/templates/A07-verification-strategy.md。按功能风险选择适用测试层，先确定判据再实现。逐章填写规范要求，未知和不适用说明原因；涉及运行结果必须来源于真实工具，未执行不得填通过；返回文件、版本和实际检查。
```

### A07-REVIEW

```text
[A07-REVIEW] 请按下游使用者的视角审阅 {制品路径}：编码者先编写有意义测试，验收者准备环境和判据。检查 覆盖确认规则和高风险异常，而不仅是实现已有正常分支；六类验证分别定判据、执行者与记录位置。逐项给出位置、预期/实际、影响与建议，区分缺输入和内容错误；不直接改变已确认标准。
```

### A07-REVISE

```text
[A07-REVISE] 请根据 {反馈} 修订 {制品路径}，保留来源和版本关系。重点仍是：按功能风险选择适用测试层，先确定判据再实现。先列影响，再修改获准内容，同步关联制品并在 A16 标记需重验的证据；业务规则变化无确认来源时暂停相关改动。
```

### A07-VERIFY

```text
[A07-VERIFY] 请独立核对 {制品路径} 的候选 {候选}，依据 {输入路径} 与 A07 规范。验证 覆盖确认规则和高风险异常，而不仅是实现已有正常分支；六类验证分别定判据、执行者与记录位置。给出通过/失败/无法判定/阻塞，附步骤、环境、版本和证据；只读产品实现，不以生成者总结当结果。
```

### A07-HANDOFF

```text
[A07-HANDOFF] 请把 验证策略 交给下一执行者，保存到 {交接路径}。明确 编码者先编写有意义测试，验收者准备环境和判据，记录输入/输出版本、真实检查、未决项及下一条指令。接手者应能只凭文件继续，涉及运行中的服务先标记需要复查状态。
```

### A07-FAILURE

```text
[A07-FAILURE] 处理生成或验证 验证策略 时发生的 {错误}。读取实际输出、当前版本和 A07 输入要求，判断是工具/环境、规格缺失还是实现问题。记录已尝试方案和影响；仅执行已授权的安全恢复，不放宽验收、不伪造结果。
```

## 完成、更新与交接

检查必填项、来源、质量标准和下游可用性；每次修改按版本更新，不覆盖旧确认历史。草稿完成不等于业务确认，候选验证不等于已发布。无证据的运行结论保持无法判定。交接给上述使用者，失败按 FAILURE 返回相关阶段。
