# A09 工程基线

## 用途与生命周期

- 适用与触发：新项目必要；非文档主体加基线清单；新项目、环境或依赖变化。
- 生产者：人驱动的 AI；责任角色：技术责任人。
- 输入：A04、A08、工作区与工具实际状态。
- 使用者与用途：开发、自动化测试和发布脚本。
- 输出：项目内 `app/ 与 docs/engineering-baseline.md`；实例、版本、来源及失效遵循[约定](../conventions.md)。
- 配套：[模板](../../templates/A09-engineering-baseline.md) · [教学填写示例](../../examples/focustask/docs/artifact-examples/A09-engineering-baseline.md)。

## 必填内容与字段含义

| 章节 | 必须回答 |
| --- | --- |
| 清单与版本 | 运行时、包管理器、锁文件、框架、测试工具与选用依据 |
| 模块与配置 | 实际目录、配置变量名、安全示例、忽略规则 |
| 准备和启动 | 工具检查、专用数据目录、端口、依赖/迁移/种子/运行 |
| 检查与最小用例 | lint、类型、单元、E2E、构建与冒烟的真实入口 |
| 增强路线 | 当前最小可运行范围、后续增强项、触发条件与责任人 |
| 证据与限制 | 实际命令、退出码、版本、缺失工具、恢复步骤 |

元数据必须包含实例ID、版本、状态、责任角色、输入版本、确认来源、下游用途、未决项。字段未知标明原因；建议与事实分开。

## 质量标准与边界

依赖安装、初始化、启动和冒烟可复现，不使用固定成功的空脚本；基线按最小可运行逐步增强，未建立的命令标待建立。创建真正可运行的最小工程和检查命令，适用的本地数据与服务需隔离。先保证最小可运行准备，再按项目需要增强 E2E、性能与安全类检查；不把完整基础设施建设设为构建原型的前提。规则变化先更新来源，相关测试/运行记录标为待重验，旧结果保留原适用版本。

- 不足示例：“已提供 package.json 所以初始化完成”。
- 可判定示例：“锁文件安装后启动专用测试数据库，迁移成功，健康与冒烟通过，有日志”。

## 人驱动 AI 的操作链

依[提示词协议](../practices/prompt-protocol.md)取得参数。开始时人提供目标与输入位置；AI先读取事实，缺关键规则才追问。选择/修订用真实人的反馈或既有授权，不要求每一步重新批准。只写本文需文件读写；验证/执行代码另需终端和目标环境，UI需浏览器。

### A09-START

```text
[A09-START] 请为 {项目} 的 {目标} 开始准备 A09 工程基线。先读取 {输入路径}：A04、A08、工作区与工具实际状态。创建真正可运行的最小工程和检查命令，适用的本地数据与服务需隔离。列事实、缺口与下一步；可发现的事实直接核对，不重复问人。
```

### A09-CLARIFY

```text
[A09-CLARIFY] 请澄清 工程基线 的 {问题}。先读 {输入路径} 并说明冲突来源，给出会改变结果的选项和取舍。重点检查：依赖安装、初始化、启动和冒烟可复现，不使用固定成功的空脚本；基线按最小可运行逐步增强，未建立的命令标待建立。未知关键规则暂停定案，已明确内容继续起草。
```

### A09-SELECT

```text
[A09-SELECT] 依据 {确认来源}，本轮对 工程基线 采用 {已选方案}，适用范围是 {目标}。请记录决定、来源、影响和未确认事项；先核对来源真实存在，再更新状态，不把建议写成人的批准。
```

### A09-GENERATE

```text
[A09-GENERATE] 请依据 {输入路径} 为 {目标} 生成 A09 工程基线，写入 {输出路径}，使用 templates/A09-engineering-baseline.md。创建真正可运行的最小工程和检查命令，适用的本地数据与服务需隔离。逐章填写规范要求，未知和不适用说明原因；同时创建真正可运行的工程/代码与测试，清单不能替代实现；返回文件、版本和实际检查。
```

### A09-REVIEW

```text
[A09-REVIEW] 请按下游使用者的视角审阅 {制品路径}：开发、自动化测试和发布脚本。检查 依赖安装、初始化、启动和冒烟可复现，不使用固定成功的空脚本；基线按最小可运行逐步增强，未建立的命令标待建立。逐项给出位置、预期/实际、影响与建议，区分缺输入和内容错误；不直接改变已确认标准。
```

### A09-REVISE

```text
[A09-REVISE] 请根据 {反馈} 修订 {制品路径}，保留来源和版本关系。重点仍是：创建真正可运行的最小工程和检查命令，适用的本地数据与服务需隔离。先列影响，再修改获准内容，同步关联制品并在 A16 标记需重验的证据；业务规则变化无确认来源时暂停相关改动。
```

### A09-VERIFY

```text
[A09-VERIFY] 请独立核对 {制品路径} 的候选 {候选}，依据 {输入路径} 与 A09 规范。验证 依赖安装、初始化、启动和冒烟可复现，不使用固定成功的空脚本；基线按最小可运行逐步增强，未建立的命令标待建立。给出通过/失败/无法判定/阻塞，附步骤、环境、版本和证据；只读产品实现，不以生成者总结当结果。
```

### A09-HANDOFF

```text
[A09-HANDOFF] 请把 工程基线 交给下一执行者，保存到 {交接路径}。明确 开发、自动化测试和发布脚本，记录输入/输出版本、真实检查、未决项及下一条指令。接手者应能只凭文件继续，涉及运行中的服务先标记需要复查状态。
```

### A09-FAILURE

```text
[A09-FAILURE] 处理生成或验证 工程基线 时发生的 {错误}。读取实际输出、当前版本和 A09 输入要求，判断是工具/环境、规格缺失还是实现问题。记录已尝试方案和影响；仅执行已授权的安全恢复，不放宽验收、不伪造结果。
```

## 完成、更新与交接

检查必填项、来源、质量标准和下游可用性；每次修改按版本更新，不覆盖旧确认历史。草稿完成不等于业务确认，候选验证不等于已发布。无证据的运行结论保持无法判定。交接给上述使用者，失败按 FAILURE 返回相关阶段。
