# A22 模型实证评价

## 用途与生命周期

- 适用与触发：开展模型评价时使用；实际实验前建评价基线，结束后填观察并修订。没有实验时只能说明评价方法和未验证事项。
- 生产者：人驱动的 AI；责任角色：模型责任人。
- 输入：预先定义的评价问题、A16/A21、真实全流程证据。
- 使用者与用途：模型维护者、采用模型的团队。
- 输出：项目内 `evaluation.md`；实例、版本、来源及失效遵循[约定](../conventions.md)。
- 配套：[模板](../../templates/A22-model-evaluation.md) · [教学填写示例](../../examples/focustask/docs/artifact-examples/A22-model-evaluation.md)。

## 必填内容与字段含义

| 章节 | 必须回答 |
| --- | --- |
| 问题与基线 | 事先定义的问题、判据、采集方法和样本 |
| 观察与证据 | 每问题对应场景、原始记录、次数/耗时、结果 |
| 制品效果 | 使用者、用途、额外解释、重复/无效内容、未验证项 |
| 修订与重验 | 问题→规范/提示词变更→重验场景→新证据 |
| 局限与总体结论 | 样本、环境、预置故障、未采集数据、适用性边界 |

元数据必须包含实例ID、版本、状态、责任角色、输入版本、确认来源、下游用途、未决项。字段未知标明原因；建议与事实分开。

## 质量标准与边界

结论有观察证据，未使用制品标未验证，不能从单例推出普适收益。评价制品实际下游使用、额外解释、变更传播、验证和接手效果。规则变化先更新来源，相关测试/运行记录标为待重验，旧结果保留原适用版本。

- 不足示例：“AI提高效率90%，文档齐全”。
- 可判定示例：“记录接手者额外询问次数及原因；对未使用制品注明未验证，修订后重试”。

## 人驱动 AI 的操作链

依[提示词协议](../practices/prompt-protocol.md)取得参数。开始时人提供目标与输入位置；AI先读取事实，缺关键规则才追问。选择/修订用真实人的反馈或既有授权，不要求每一步重新批准。只写本文需文件读写；验证/执行代码另需终端和目标环境，UI需浏览器。

### A22-START

```text
[A22-START] 请为 {项目} 的 {目标} 开始准备 A22 模型实证评价。先读取 {输入路径}：预先定义的评价问题、A16/A21、真实全流程证据。评价制品实际下游使用、额外解释、变更传播、验证和接手效果。列事实、缺口与下一步；可发现的事实直接核对，不重复问人。
```

### A22-CLARIFY

```text
[A22-CLARIFY] 请澄清 模型实证评价 的 {问题}。先读 {输入路径} 并说明冲突来源，给出会改变结果的选项和取舍。重点检查：结论有观察证据，未使用制品标未验证，不能从单例推出普适收益。未知关键规则暂停定案，已明确内容继续起草。
```

### A22-SELECT

```text
[A22-SELECT] 依据 {确认来源}，本轮对 模型实证评价 采用 {已选方案}，适用范围是 {目标}。请记录决定、来源、影响和未确认事项；先核对来源真实存在，再更新状态，不把建议写成人的批准。
```

### A22-GENERATE

```text
[A22-GENERATE] 请依据 {输入路径} 为 {目标} 生成 A22 模型实证评价，写入 {输出路径}，使用 templates/A22-model-evaluation.md。评价制品实际下游使用、额外解释、变更传播、验证和接手效果。逐章填写规范要求，未知和不适用说明原因；涉及运行结果必须来源于真实工具，未执行不得填通过；返回文件、版本和实际检查。
```

### A22-REVIEW

```text
[A22-REVIEW] 请按下游使用者的视角审阅 {制品路径}：模型维护者、采用模型的团队。检查 结论有观察证据，未使用制品标未验证，不能从单例推出普适收益。逐项给出位置、预期/实际、影响与建议，区分缺输入和内容错误；不直接改变已确认标准。
```

### A22-REVISE

```text
[A22-REVISE] 请根据 {反馈} 修订 {制品路径}，保留来源和版本关系。重点仍是：评价制品实际下游使用、额外解释、变更传播、验证和接手效果。先列影响，再修改获准内容，同步关联制品并在 A16 标记需重验的证据；业务规则变化无确认来源时暂停相关改动。
```

### A22-VERIFY

```text
[A22-VERIFY] 请独立核对 {制品路径} 的候选 {候选}，依据 {输入路径} 与 A22 规范。验证 结论有观察证据，未使用制品标未验证，不能从单例推出普适收益。给出通过/失败/无法判定/阻塞，附步骤、环境、版本和证据；只读产品实现，不以生成者总结当结果。
```

### A22-HANDOFF

```text
[A22-HANDOFF] 请把 模型实证评价 交给下一执行者，保存到 {交接路径}。明确 模型维护者、采用模型的团队，记录输入/输出版本、真实检查、未决项及下一条指令。接手者应能只凭文件继续，涉及运行中的服务先标记需要复查状态。
```

### A22-FAILURE

```text
[A22-FAILURE] 处理生成或验证 模型实证评价 时发生的 {错误}。读取实际输出、当前版本和 A22 输入要求，判断是工具/环境、规格缺失还是实现问题。记录已尝试方案和影响；仅执行已授权的安全恢复，不放宽验收、不伪造结果。
```

## 完成、更新与交接

检查必填项、来源、质量标准和下游可用性；每次修改按版本更新，不覆盖旧确认历史。草稿完成不等于业务确认，候选验证不等于已发布。无证据的运行结论保持无法判定。交接给上述使用者，失败按 FAILURE 返回相关阶段。
