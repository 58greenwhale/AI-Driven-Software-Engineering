# A20 维护验证报告

## 用途与生命周期

- 适用与触发：项目按维护事件触发；每次修复、变更或回退演练。
- 生产者：人驱动的 AI；责任角色：维护责任人。
- 输入：A15、诊断证据、变更候选、回归与发布记录。
- 使用者与用途：问题责任人、下一位维护者和模型评价。
- 输出：项目内 `evidence/maintenance/report.md`；实例、版本、来源及失效遵循[约定](../conventions.md)。
- 配套：[模板](../templates/A20-maintenance.md) · [教学填写示例](../../examples/focustask/docs/artifact-examples/A20-maintenance.md)。

## 必填内容与字段含义

| 章节 | 必须回答 |
| --- | --- |
| 事件与边界 | 变更/缺陷/演练、来源、影响版本、严重度和目标 |
| 诊断与决定 | 复现、原始证据、原因、影响和选择依据 |
| 修订与追踪 | 规格/代码/测试/配置/ADR差异、版本与证据失效 |
| 回归与再发布 | 原失败用例、相关回归、构建/发布/回退链接和结果 |
| 关闭与改进 | 结果、恢复数据、剩余事项、模型不足和下一步 |

元数据必须包含实例ID、版本、状态、责任角色、输入版本、确认来源、下游用途、未决项。字段未知标明原因；建议与事实分开。

## 质量标准与边界

原现象可复现，修复后同用例通过，回归和数据结果有证据。由问题单追踪规格/实现/验证/再交付，人为故障和正常产物隔离。规则变化先更新来源，相关测试/运行记录标为待重验，旧结果保留原适用版本。

- 不足示例：“修了应该好了”。
- 可判定示例：“缺陷候选Viewer写201，修复返回403且计数不变；发布后同用例复验”。

## 人驱动 AI 的操作链

依[提示词协议](../practices/prompt-protocol.md)取得参数。开始时人提供目标与输入位置；AI先读取事实，缺关键规则才追问。选择/修订用真实人的反馈或既有授权，不要求每一步重新批准。只写本文需文件读写；验证/执行代码另需终端和目标环境，UI需浏览器。

### A20-START

```text
[A20-START] 请为 {项目} 的 {目标} 开始准备 A20 维护验证报告。先读取 {输入路径}：A15、诊断证据、变更候选、回归与发布记录。由问题单追踪规格/实现/验证/再交付，人为故障和正常产物隔离。列事实、缺口与下一步；可发现的事实直接核对，不重复问人。
```

### A20-CLARIFY

```text
[A20-CLARIFY] 请澄清 维护验证报告 的 {问题}。先读 {输入路径} 并说明冲突来源，给出会改变结果的选项和取舍。重点检查：原现象可复现，修复后同用例通过，回归和数据结果有证据。未知关键规则暂停定案，已明确内容继续起草。
```

### A20-SELECT

```text
[A20-SELECT] 依据 {确认来源}，本轮对 维护验证报告 采用 {已选方案}，适用范围是 {目标}。请记录决定、来源、影响和未确认事项；先核对来源真实存在，再更新状态，不把建议写成人的批准。
```

### A20-GENERATE

```text
[A20-GENERATE] 请依据 {输入路径} 为 {目标} 生成 A20 维护验证报告，写入 {输出路径}，使用 model/templates/A20-maintenance.md。由问题单追踪规格/实现/验证/再交付，人为故障和正常产物隔离。逐章填写规范要求，未知和不适用说明原因；涉及运行结果必须来源于真实工具，未执行不得填通过；返回文件、版本和实际检查。
```

### A20-REVIEW

```text
[A20-REVIEW] 请按下游使用者的视角审阅 {制品路径}：问题责任人、下一位维护者和模型评价。检查 原现象可复现，修复后同用例通过，回归和数据结果有证据。逐项给出位置、预期/实际、影响与建议，区分缺输入和内容错误；不直接改变已确认标准。
```

### A20-REVISE

```text
[A20-REVISE] 请根据 {反馈} 修订 {制品路径}，保留来源和版本关系。重点仍是：由问题单追踪规格/实现/验证/再交付，人为故障和正常产物隔离。先列影响，再修改获准内容，同步关联制品并在 A16 标记需重验的证据；业务规则变化无确认来源时暂停相关改动。
```

### A20-VERIFY

```text
[A20-VERIFY] 请独立核对 {制品路径} 的候选 {候选}，依据 {输入路径} 与 A20 规范。验证 原现象可复现，修复后同用例通过，回归和数据结果有证据。给出通过/失败/无法判定/阻塞，附步骤、环境、版本和证据；只读产品实现，不以生成者总结当结果。
```

### A20-HANDOFF

```text
[A20-HANDOFF] 请把 维护验证报告 交给下一执行者，保存到 {交接路径}。明确 问题责任人、下一位维护者和模型评价，记录输入/输出版本、真实检查、未决项及下一条指令。接手者应能只凭文件继续，涉及运行中的服务先标记需要复查状态。
```

### A20-FAILURE

```text
[A20-FAILURE] 处理生成或验证 维护验证报告 时发生的 {错误}。读取实际输出、当前版本和 A20 输入要求，判断是工具/环境、规格缺失还是实现问题。记录已尝试方案和影响；仅执行已授权的安全恢复，不放宽验收、不伪造结果。
```

## 完成、更新与交接

检查必填项、来源、质量标准和下游可用性；每次修改按版本更新，不覆盖旧确认历史。草稿完成不等于业务确认，候选验证不等于已发布。无证据的运行结论保持无法判定。交接给上述使用者，失败按 FAILURE 返回相关阶段。
