# A10 设计与实施计划（plan）

## 用途与生命周期

- 适用与触发：必要；可用表格无需项目管理系统；首次拆分、范围/依赖/执行状态变化。
- 生产者：人驱动的 AI；责任角色：迭代责任人。
- 输入：范围、功能与设计、验收要求、当前工作事实。
- 使用者与用途：协调者和执行 Agent 选择下一个就绪任务。
- 输出：项目内 `docs/iteration-plan.md`；实例、版本、来源及失效遵循[约定](../conventions.md)。
- 配套：[模板](../templates/A10-task-plan.md) · [教学填写示例](../../examples/focustask/docs/artifact-examples/A10-task-plan.md)。

## 必填内容与字段含义

| 章节 | 必须回答 |
| --- | --- |
| 迭代范围 | 版本目标、包含/延期与成功条件 |
| 方案与理由 | 候选方案、选择依据与被否代价、需人决定的取舍 |
| 任务表 | 编号、目标、范围、输入、输出、责任角色、状态与AC |
| 活动裁剪与并行边界 | 采用的活动、合并/简化/跳过理由、并行功能、文件与工作区归属 |
| 依赖与就绪 | 前驱关系、外部条件、关键未决项、独立验收粒度 |
| 验证与集成条件 | 每项任务的验证方式、集成顺序、跨功能路径与集成后重验范围 |
| 流转与证据 | 自检、待验收、验证/集成、阻塞和重开规则 |
| 变更与下一步 | 影响传播、待决策、已知限制、下一条指令 |

元数据必须包含实例ID、版本、状态、责任角色、输入版本、确认来源、下游用途、未决项。字段未知标明原因；建议与事实分开。

## 质量标准与边界

每个就绪任务有真实前置满足证据，裁剪与并行边界有理由，验证与集成条件可执行，不引入范围外工作。区分产品目标和本轮任务，写明方案与理由、活动裁剪、并行边界、验证与集成条件；依赖无循环，初始化不要求自己的产物预先存在。裁剪依据见[裁剪规则](../tailoring.md)；一项功能的就绪状态不代表全部功能。规则变化先更新来源，相关测试/运行记录标为待重验，旧结果保留原适用版本。

- 不足示例：“所有功能都标就绪，发布依赖所有P0含自身”。
- 可判定示例：“初始化完成后身份任务就绪；发布依赖明确选入的功能和质量任务”。

## 人驱动 AI 的操作链

依[提示词协议](../practices/prompt-protocol.md)取得参数。开始时人提供目标与输入位置；AI先读取事实，缺关键规则才追问。选择/修订用真实人的反馈或既有授权，不要求每一步重新批准。只写本文需文件读写；验证/执行代码另需终端和目标环境，UI需浏览器。

### A10-START

```text
[A10-START] 请为 {项目} 的 {目标} 开始准备 A10 设计与实施计划（plan）。先读取 {输入路径}：范围、功能与设计、验收要求、当前工作事实。区分产品目标和本轮任务，写明方案与理由、活动裁剪、并行边界、验证与集成条件；依赖无循环，初始化不要求自己的产物预先存在。列事实、缺口与下一步；可发现的事实直接核对，不重复问人。
```

### A10-CLARIFY

```text
[A10-CLARIFY] 请澄清 设计与实施计划（plan） 的 {问题}。先读 {输入路径} 并说明冲突来源，给出会改变结果的选项和取舍。重点检查：每个就绪任务有真实前置满足证据，裁剪与并行边界有理由，验证与集成条件可执行，不引入范围外工作。未知关键规则暂停定案，已明确内容继续起草。
```

### A10-SELECT

```text
[A10-SELECT] 依据 {确认来源}，本轮对 设计与实施计划（plan） 采用 {已选方案}，适用范围是 {目标}。请记录决定、来源、影响和未确认事项；先核对来源真实存在，再更新状态，不把建议写成人的批准。
```

### A10-GENERATE

```text
[A10-GENERATE] 请依据 {输入路径} 为 {目标} 生成 A10 设计与实施计划（plan），写入 {输出路径}，使用 model/templates/A10-task-plan.md。区分产品目标和本轮任务，写明方案与理由、活动裁剪、并行边界、验证与集成条件；依赖无循环，初始化不要求自己的产物预先存在。逐章填写规范要求，未知和不适用说明原因；涉及运行结果必须来源于真实工具，未执行不得填通过；返回文件、版本和实际检查。
```

### A10-REVIEW

```text
[A10-REVIEW] 请按下游使用者的视角审阅 {制品路径}：协调者和执行 Agent 选择下一个就绪任务。检查 每个就绪任务有真实前置满足证据，裁剪与并行边界有理由，验证与集成条件可执行，不引入范围外工作。逐项给出位置、预期/实际、影响与建议，区分缺输入和内容错误；不直接改变已确认标准。
```

### A10-REVISE

```text
[A10-REVISE] 请根据 {反馈} 修订 {制品路径}，保留来源和版本关系。重点仍是：区分产品目标和本轮任务，写明方案与理由、活动裁剪、并行边界、验证与集成条件；依赖无循环，初始化不要求自己的产物预先存在。先列影响，再修改获准内容，同步关联制品并在 A16 标记需重验的证据；业务规则变化无确认来源时暂停相关改动。
```

### A10-VERIFY

```text
[A10-VERIFY] 请独立核对 {制品路径} 的候选 {候选}，依据 {输入路径} 与 A10 规范。验证 每个就绪任务有真实前置满足证据，裁剪与并行边界有理由，验证与集成条件可执行，不引入范围外工作。给出通过/失败/无法判定/阻塞，附步骤、环境、版本和证据；只读产品实现，不以生成者总结当结果。
```

### A10-HANDOFF

```text
[A10-HANDOFF] 请把 设计与实施计划（plan） 交给下一执行者，保存到 {交接路径}。明确 协调者和执行 Agent 选择下一个就绪任务，记录输入/输出版本、真实检查、未决项及下一条指令。接手者应能只凭文件继续，涉及运行中的服务先标记需要复查状态。
```

### A10-FAILURE

```text
[A10-FAILURE] 处理生成或验证 设计与实施计划（plan） 时发生的 {错误}。读取实际输出、当前版本和 A10 输入要求，判断是工具/环境、规格缺失还是实现问题。记录已尝试方案和影响；仅执行已授权的安全恢复，不放宽验收、不伪造结果。
```

## 完成、更新与交接

检查必填项、来源、质量标准和下游可用性；每次修改按版本更新，不覆盖旧确认历史。草稿完成不等于业务确认，候选验证不等于已发布。无证据的运行结论保持无法判定。交接给上述使用者，失败按 FAILURE 返回相关阶段。
