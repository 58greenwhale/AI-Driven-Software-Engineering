# A17 发布清单

## 用途与生命周期

- 适用与触发：每次发布必要；每个发布候选生成，变化则重新核对。
- 生产者：人驱动的 AI；责任角色：发布责任人。
- 输入：已验收候选、构建输出、版本范围、环境与恢复方案。
- 使用者与用途：发布执行者和维护/回退执行者。
- 输出：目标项目内 `evidence/releases/{版本}/manifest.md`；这是推荐路径，不是本仓库文件。实例、版本、来源及失效遵循[约定](../conventions.md)。
- 配套：[模板](../../templates/A17-release-manifest.md) · [教学填写示例](../../examples/focustask/docs/artifact-examples/A17-release-manifest.md)。

## 必填内容与字段含义

| 章节 | 必须回答 |
| --- | --- |
| 范围与身份 | 版本、功能与延期项、提交或源码快照、构建摘要 |
| 环境与依赖 | 目标主机/端口、配置名称、数据库、迁移和运行时 |
| 质量与风险 | 验收、评审、测试、安全、已知问题和回退引用 |
| 决定与后续 | 负责人、确认来源、go/no-go/无法判定及部署指令 |

元数据必须包含实例ID、版本、状态、责任角色、输入版本、确认来源、下游用途、未决项。字段未知标明原因；建议与事实分开。

## 质量标准与边界

已知失败优先no-go，证据不全无法判定，确认仅限指定版本与目标。绑定源码、真实构建、配置和目标环境，开发运行不等于正式交付产物。规则变化先更新来源，相关测试/运行记录标为待重验，旧结果保留原适用版本。

- 不足示例：“发布最新版，一切正常”。
- 可判定示例：“清单指向指定版本的源码快照、构建摘要、配置名、迁移版本和实际冒烟记录”。

## 人驱动 AI 的操作链

依[提示词协议](../practices/prompt-protocol.md)取得参数。开始时人提供目标与输入位置；AI先读取事实，缺关键规则才追问。选择/修订用真实人的反馈或既有授权，不要求每一步重新批准。只写本文需文件读写；验证/执行代码另需终端和目标环境，UI需浏览器。

### A17-START

```text
[A17-START] 请为 {项目} 的 {目标} 开始准备 A17 发布清单。先读取 {输入路径}：已验收候选、构建输出、版本范围、环境与恢复方案。绑定源码、真实构建、配置和目标环境，开发运行不等于正式交付产物。列事实、缺口与下一步；可发现的事实直接核对，不重复问人。
```

### A17-CLARIFY

```text
[A17-CLARIFY] 请澄清 发布清单 的 {问题}。先读 {输入路径} 并说明冲突来源，给出会改变结果的选项和取舍。重点检查：已知失败优先no-go，证据不全无法判定，确认仅限指定版本与目标。未知关键规则暂停定案，已明确内容继续起草。
```

### A17-SELECT

```text
[A17-SELECT] 依据 {确认来源}，本轮对 发布清单 采用 {已选方案}，适用范围是 {目标}。请记录决定、来源、影响和未确认事项；先核对来源真实存在，再更新状态，不把建议写成人的批准。
```

### A17-GENERATE

```text
[A17-GENERATE] 请依据 {输入路径} 为 {目标} 生成 A17 发布清单，写入 {输出路径}，使用 templates/A17-release-manifest.md。绑定源码、真实构建、配置和目标环境，开发运行不等于正式交付产物。逐章填写规范要求，未知和不适用说明原因；涉及运行结果必须来源于真实工具，未执行不得填通过；返回文件、版本和实际检查。
```

### A17-REVIEW

```text
[A17-REVIEW] 请按下游使用者的视角审阅 {制品路径}：发布执行者和维护/回退执行者。检查 已知失败优先no-go，证据不全无法判定，确认仅限指定版本与目标。逐项给出位置、预期/实际、影响与建议，区分缺输入和内容错误；不直接改变已确认标准。
```

### A17-REVISE

```text
[A17-REVISE] 请根据 {反馈} 修订 {制品路径}，保留来源和版本关系。重点仍是：绑定源码、真实构建、配置和目标环境，开发运行不等于正式交付产物。先列影响，再修改获准内容，同步关联制品并在 A16 标记需重验的证据；业务规则变化无确认来源时暂停相关改动。
```

### A17-VERIFY

```text
[A17-VERIFY] 请独立核对 {制品路径} 的候选 {候选}，依据 {输入路径} 与 A17 规范。验证 已知失败优先no-go，证据不全无法判定，确认仅限指定版本与目标。给出通过/失败/无法判定/阻塞，附步骤、环境、版本和证据；只读产品实现，不以生成者总结当结果。
```

### A17-HANDOFF

```text
[A17-HANDOFF] 请把 发布清单 交给下一执行者，保存到 {交接路径}。明确 发布执行者和维护/回退执行者，记录输入/输出版本、真实检查、未决项及下一条指令。接手者应能只凭文件继续，涉及运行中的服务先标记需要复查状态。
```

### A17-FAILURE

```text
[A17-FAILURE] 处理生成或验证 发布清单 时发生的 {错误}。读取实际输出、当前版本和 A17 输入要求，判断是工具/环境、规格缺失还是实现问题。记录已尝试方案和影响；仅执行已授权的安全恢复，不放宽验收、不伪造结果。
```

## 完成、更新与交接

检查必填项、来源、质量标准和下游可用性；每次修改按版本更新，不覆盖旧确认历史。草稿完成不等于业务确认，候选验证不等于已发布。无证据的运行结论保持无法判定。交接给上述使用者，失败按 FAILURE 返回相关阶段。
