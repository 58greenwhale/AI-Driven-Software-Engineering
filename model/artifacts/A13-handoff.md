# A13 会话交接

## 用途与生命周期

- 适用与触发：条件触发；可并入交付记录；上下文切换、长任务检查点、执行者变化。
- 生产者：人驱动的 AI；责任角色：交出任务的责任人。
- 输入：任务、当前分支/改动、运行进程、验证结果、未决项。
- 使用者与用途：不拥有原始聊天的新 Agent。
- 输出：项目内 `evidence/handoff.md`；实例、版本、来源及失效遵循[约定](../conventions.md)。
- 配套：[模板](../templates/A13-handoff.md) · [教学填写示例](../../examples/focustask/docs/artifact-examples/A13-handoff.md)。

## 必填内容与字段含义

| 章节 | 必须回答 |
| --- | --- |
| 任务与身份 | 目标、范围、状态、当前所处活动、候选快照、未提交改动归属 |
| 输入与决定 | 必读路径、已确认选择、未确认建议的区别 |
| 环境与复现 | 工作目录、运行时、数据来源、命令、目标服务、密钥获取方式 |
| 进度与证据 | 完成项、实际检查、失败、日志与制品链接 |
| 下一步与风险 | 一个可立即执行动作、下一活动入口、预期、失败处理和阻塞 |

元数据必须包含实例ID、版本、状态、责任角色、输入版本、确认来源、下游用途、未决项。字段未知标明原因；建议与事实分开。

## 质量标准与边界

仅凭记录可找到输入、重现环境并推进一步；进程需重新核实，自检通过不等于已验收。提供真实版本、环境和命令目录，接手者不依赖原聊天。交接须写明当前所处活动、候选状态与下一活动入口；实现者自检与独立验收分别记录，自检通过不代表已验收。规则变化先更新来源，相关测试/运行记录标为待重验，旧结果保留原适用版本。

- 不足示例：“继续刚才的代码，你知道上下文”。
- 可判定示例：“从交接记录读取规格版本和失败命令，确认端口后重跑指定AC，再记录结果”。

## 人驱动 AI 的操作链

依[提示词协议](../practices/prompt-protocol.md)取得参数。开始时人提供目标与输入位置；AI先读取事实，缺关键规则才追问。选择/修订用真实人的反馈或既有授权，不要求每一步重新批准。只写本文需文件读写；验证/执行代码另需终端和目标环境，UI需浏览器。

### A13-START

```text
[A13-START] 请为 {项目} 的 {目标} 开始准备 A13 会话交接。先读取 {输入路径}：任务、当前分支/改动、运行进程、验证结果、未决项。提供真实版本、环境和命令目录，接手者不依赖原聊天。列事实、缺口与下一步；可发现的事实直接核对，不重复问人。
```

### A13-CLARIFY

```text
[A13-CLARIFY] 请澄清 会话交接 的 {问题}。先读 {输入路径} 并说明冲突来源，给出会改变结果的选项和取舍。重点检查：仅凭记录可找到输入、重现环境并推进一步；进程需重新核实，自检通过不等于已验收。未知关键规则暂停定案，已明确内容继续起草。
```

### A13-SELECT

```text
[A13-SELECT] 依据 {确认来源}，本轮对 会话交接 采用 {已选方案}，适用范围是 {目标}。请记录决定、来源、影响和未确认事项；先核对来源真实存在，再更新状态，不把建议写成人的批准。
```

### A13-GENERATE

```text
[A13-GENERATE] 请依据 {输入路径} 为 {目标} 生成 A13 会话交接，写入 {输出路径}，使用 model/templates/A13-handoff.md。提供真实版本、环境和命令目录，接手者不依赖原聊天。逐章填写规范要求，未知和不适用说明原因；涉及运行结果必须来源于真实工具，未执行不得填通过；返回文件、版本和实际检查。
```

### A13-REVIEW

```text
[A13-REVIEW] 请按下游使用者的视角审阅 {制品路径}：不拥有原始聊天的新 Agent。检查 仅凭记录可找到输入、重现环境并推进一步；进程需重新核实，自检通过不等于已验收。逐项给出位置、预期/实际、影响与建议，区分缺输入和内容错误；不直接改变已确认标准。
```

### A13-REVISE

```text
[A13-REVISE] 请根据 {反馈} 修订 {制品路径}，保留来源和版本关系。重点仍是：提供真实版本、环境和命令目录，接手者不依赖原聊天。先列影响，再修改获准内容，同步关联制品并在 A16 标记需重验的证据；业务规则变化无确认来源时暂停相关改动。
```

### A13-VERIFY

```text
[A13-VERIFY] 请独立核对 {制品路径} 的候选 {候选}，依据 {输入路径} 与 A13 规范。验证 仅凭记录可找到输入、重现环境并推进一步；进程需重新核实，自检通过不等于已验收。给出通过/失败/无法判定/阻塞，附步骤、环境、版本和证据；只读产品实现，不以生成者总结当结果。
```

### A13-HANDOFF

```text
[A13-HANDOFF] 请把 会话交接 交给下一执行者，保存到 {交接路径}。明确 不拥有原始聊天的新 Agent，记录输入/输出版本、真实检查、未决项及下一条指令。接手者应能只凭文件继续，涉及运行中的服务先标记需要复查状态。
```

### A13-FAILURE

```text
[A13-FAILURE] 处理生成或验证 会话交接 时发生的 {错误}。读取实际输出、当前版本和 A13 输入要求，判断是工具/环境、规格缺失还是实现问题。记录已尝试方案和影响；仅执行已授权的安全恢复，不放宽验收、不伪造结果。
```

## 完成、更新与交接

检查必填项、来源、质量标准和下游可用性；每次修改按版本更新，不覆盖旧确认历史。草稿完成不等于业务确认，候选验证不等于已发布。无证据的运行结论保持无法判定。交接给上述使用者，失败按 FAILURE 返回相关阶段。

交接确认前核对项目 README 和任务状态是否与实际工程一致，检查工具缓存和进程当前是否存在；对同一生成目录有竞争的验证命令注明执行顺序。接手效果需要另行记录实际结果，不能由说明文件推断。
