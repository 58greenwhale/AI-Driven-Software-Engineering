# A06 重要决定记录

## 用途与生命周期

- 适用与触发：条件触发；不为普通命名创建；影响多功能、难以逆转或修改既有主要约束，含重构技术选型与精修设计取舍。
- 生产者：人驱动的 AI；责任角色：受该决定影响的业务或技术责任人。
- 输入：冲突或风险、候选方案、范围和技术事实。
- 使用者与用途：实现者解释取舍，维护者判断何时重新评估。
- 输出：项目内 `docs/decisions/0002-example.md`；实例、版本、来源及失效遵循[约定](../conventions.md)。
- 配套：[模板](../templates/A06-adr.md) · [教学填写示例](../../examples/focustask/docs/artifact-examples/A06-adr.md)。

## 必填内容与字段含义

| 章节 | 必须回答 |
| --- | --- |
| 身份与状态 | 编号、日期、状态、责任角色、确认来源 |
| 背景与约束 | 触发问题、现状、受影响对象 |
| 触发活动与关联 | 决定来自哪项活动（构建/重构/审查/精修/验收/维护）及关联的 A24/A27/A15 编号 |
| 备选与取舍 | 至少两个可行方案的收益、风险与成本 |
| 决定与后果 | 选择、适用范围、负面影响、实施和验证行动 |
| 复评与替代 | 复评触发、旧决定引用与迁移影响 |

元数据必须包含实例ID、版本、状态、责任角色、输入版本、确认来源、下游用途、未决项。字段未知标明原因；建议与事实分开。

## 质量标准与边界

选项有真实差异，建议与确认分开，后果和复评条件明确；注明触发活动与关联制品编号。记录当前决定的真实来源及备选取舍，保留被替代历史。重构的技术选型与替换范围、精修的设计来源与交互取舍，凡影响多功能或难以逆转都记录在本文；A24 记差距与步骤、A27 记设计交付，本文只记取舍、来源与后果。规则变化先更新来源，相关测试/运行记录标为待重验，旧结果保留原适用版本。

- 不足示例：“选择这个方案因为最好”。
- 可判定示例：“本地专用端口避免触碰现有服务；代价是脚本需记录和恢复进程身份”。

## 人驱动 AI 的操作链

依[提示词协议](../practices/prompt-protocol.md)取得参数。开始时人提供目标与输入位置；AI先读取事实，缺关键规则才追问。选择/修订用真实人的反馈或既有授权，不要求每一步重新批准。只写本文需文件读写；验证/执行代码另需终端和目标环境，UI需浏览器。

### A06-START

```text
[A06-START] 请为 {项目} 的 {目标} 开始准备 A06 重要决定记录。先读取 {输入路径}：冲突或风险、候选方案、范围和技术事实。记录当前决定的真实来源及备选取舍，保留被替代历史。列事实、缺口与下一步；可发现的事实直接核对，不重复问人。
```

### A06-CLARIFY

```text
[A06-CLARIFY] 请澄清 重要决定记录 的 {问题}。先读 {输入路径} 并说明冲突来源，给出会改变结果的选项和取舍。重点检查：选项有真实差异，建议与确认分开，后果和复评条件明确；注明触发活动与关联制品编号。未知关键规则暂停定案，已明确内容继续起草。
```

### A06-SELECT

```text
[A06-SELECT] 依据 {确认来源}，本轮对 重要决定记录 采用 {已选方案}，适用范围是 {目标}。请记录决定、来源、影响和未确认事项；先核对来源真实存在，再更新状态，不把建议写成人的批准。
```

### A06-GENERATE

```text
[A06-GENERATE] 请依据 {输入路径} 为 {目标} 生成 A06 重要决定记录，写入 {输出路径}，使用 model/templates/A06-adr.md。记录当前决定的真实来源及备选取舍，保留被替代历史。逐章填写规范要求，未知和不适用说明原因；涉及运行结果必须来源于真实工具，未执行不得填通过；返回文件、版本和实际检查。
```

### A06-REVIEW

```text
[A06-REVIEW] 请按下游使用者的视角审阅 {制品路径}：实现者解释取舍，维护者判断何时重新评估。检查 选项有真实差异，建议与确认分开，后果和复评条件明确；注明触发活动与关联制品编号。逐项给出位置、预期/实际、影响与建议，区分缺输入和内容错误；不直接改变已确认标准。
```

### A06-REVISE

```text
[A06-REVISE] 请根据 {反馈} 修订 {制品路径}，保留来源和版本关系。重点仍是：记录当前决定的真实来源及备选取舍，保留被替代历史。先列影响，再修改获准内容，同步关联制品并在 A16 标记需重验的证据；业务规则变化无确认来源时暂停相关改动。
```

### A06-VERIFY

```text
[A06-VERIFY] 请独立核对 {制品路径} 的候选 {候选}，依据 {输入路径} 与 A06 规范。验证 选项有真实差异，建议与确认分开，后果和复评条件明确；注明触发活动与关联制品编号。给出通过/失败/无法判定/阻塞，附步骤、环境、版本和证据；只读产品实现，不以生成者总结当结果。
```

### A06-HANDOFF

```text
[A06-HANDOFF] 请把 重要决定记录 交给下一执行者，保存到 {交接路径}。明确 实现者解释取舍，维护者判断何时重新评估，记录输入/输出版本、真实检查、未决项及下一条指令。接手者应能只凭文件继续，涉及运行中的服务先标记需要复查状态。
```

### A06-FAILURE

```text
[A06-FAILURE] 处理生成或验证 重要决定记录 时发生的 {错误}。读取实际输出、当前版本和 A06 输入要求，判断是工具/环境、规格缺失还是实现问题。记录已尝试方案和影响；仅执行已授权的安全恢复，不放宽验收、不伪造结果。
```

## 完成、更新与交接

检查必填项、来源、质量标准和下游可用性；每次修改按版本更新，不覆盖旧确认历史。草稿完成不等于业务确认，候选验证不等于已发布。无证据的运行结论保持无法判定。交接给上述使用者，失败按 FAILURE 返回相关阶段。
