# A26 同类问题排查与修复记录

## 用途与生命周期

- 适用与触发：发现缺陷、验收失败或维护问题时必要；未发现其他实例也须记录排查范围、方法、结果与限制；可在四项活动、独立验收与维护中触发。
- 生产者：人驱动的 AI；责任角色：问题责任人或审查责任人。
- 输入：原始问题与复现、候选版本与位置、A12/A14/A15相关记录、代码库与确认规格。
- 使用者与用途：修复执行者、审查责任人、维护者，以及A22模型评价的改进输入。
- 输出：项目内 `evidence/pattern-remediation.md`；实例、版本、来源及失效遵循[约定](../conventions.md)。
- 配套：[模板](../../templates/A26-pattern-remediation.md) · [教学填写示例](../../examples/focustask/docs/artifact-examples/A26-pattern-remediation.md)。

## 必填内容与字段含义

| 章节 | 必须回答 |
| --- | --- |
| 问题与复现 | 原始问题、候选版本、位置、复现步骤或证据来源 |
| 根因与模式 | 根因说明、可重复出现的代码模式与业务条件、可能变体 |
| 排查范围与方法 | 使用的文本/结构/语义手段、覆盖模块、未检查部分及原因 |
| 实例分类 | 已确认、疑似、不适用逐项位置与判定依据 |
| 修复与回归 | 修复项与影响、回归验证方式与结果、未执行项 |
| 复查与规则沉淀 | 再次排查结论、剩余风险、更新的A08/A12/A15/A16及规则 |

元数据必须包含实例ID、版本、状态、责任角色、输入版本、确认来源、下游用途、未决项。字段未知标明原因；建议与事实分开。

## 质量标准与边界

排查同时使用文本、结构与业务语义，不能只搜索相同代码片段；疑似项先验证，不按相似度直接替换；全部覆盖不等于证明不存在缺陷；未检查部分明确记录原因，不写成没有问题；修复在已有授权内进行，涉及业务语义变化的决定需确认来源。本文不替代A12的评审结论，也不替代A14独立验收。

- 不足示例："已全局搜索相同写法，未发现问题。"
- 可判定示例："根因为写请求前未重新校验成员角色；按调用路径、中间件与替代写法检索 12 处，确认 2 处（创建、筛选保存），疑似 1 处（归档切换，待运行验证），不适用 3 处（只读接口）；生成文件与第三方依赖未检查，原因：非自有实现。"

## 人驱动 AI 的操作链

依[提示词协议](../practices/prompt-protocol.md)取得参数。开始时人提供已发现问题、复现方式与候选位置；AI先读取事实并解释根因，缺关键规则才追问。选择/修订用真实人的反馈或既有授权，不要求每一步重新批准。只写本文需文件读写；复现与回归验证另需终端和目标环境，UI需浏览器。

### A26-START

```text
[A26-START] 请为 {项目} 的 {问题} 开始准备 A26 同类问题排查与修复记录。先读取 {输入路径}：问题描述与复现、候选版本与位置、A12/A14/A15 相关记录。解释根因并核对实际代码；列出可发现的事实、缺口与下一步，不重复问人。
```

### A26-CLARIFY

```text
[A26-CLARIFY] 请澄清 同类问题排查与修复记录 的 {问题}。先读 {输入路径} 并说明冲突来源，给出会改变结果的选项和取舍。重点检查：根因是否可解释全部实例、业务条件边界是否明确、修复是否会改变已确认行为。未知关键规则暂停定案，已明确内容继续起草。
```

### A26-SELECT

```text
[A26-SELECT] 依据 {确认来源}，本轮对 同类问题排查与修复记录 采用 {已选方案}，适用范围是 {问题或模块}。请记录决定、来源、影响和未确认事项；涉及业务语义变化的修复须有确认来源，先核对来源真实存在，再把疑似项标为已确认。
```

### A26-GENERATE

```text
[A26-GENERATE] 请依据 {输入路径} 为 {问题} 生成 A26 同类问题排查与修复记录，写入 {输出路径}，使用 templates/A26-pattern-remediation.md。先解释根因并提炼可能重复出现的代码模式与业务条件，再检查整个项目：不局限于相同文本，覆盖同类调用、相似模块、替代写法与相关异常路径；将实例分为已确认、疑似、不适用并说明依据、覆盖范围与未能检查的部分；在授权内修复确认实例并补充有针对性的回归验证；未执行的检查不得报告通过。
```

### A26-REVIEW

```text
[A26-REVIEW] 请按下游使用者的视角审阅 {制品路径}：修复执行者、审查责任人、维护者。检查根因是否可解释实例、检索手段是否覆盖结构与语义、分类依据是否可核对、回归是否针对受影响路径、未检查部分是否说明原因。逐项给出位置、预期/实际、影响与建议；不直接改变已确认标准。
```

### A26-REVISE

```text
[A26-REVISE] 请根据 {反馈} 修订 {制品路径}，保留来源和版本关系。重点仍是：实例分类与回归结果是否随修复同步，剩余风险是否更新。先列影响，再修改获准内容，同步 A12/A15/A16 与受影响的 A08 规则；业务语义变化无确认来源时暂停相关改动。
```

### A26-VERIFY

```text
[A26-VERIFY] 请独立核对 {制品路径} 的候选 {修复候选}，依据 {输入路径} 与 A26 规范。验证原问题按原用例关闭、确认实例已修复、回归覆盖受影响路径、修复后再次排查已执行。给出通过/失败/无法判定/阻塞，附命令、环境、版本和证据；未执行的检查保持无法判定。
```

### A26-HANDOFF

```text
[A26-HANDOFF] 请把 同类问题排查与修复记录 交给下一执行者，保存到 {交接路径}。明确修复执行者、审查责任人与维护者，记录根因、实例分类、已修复与未验证项、更新的规则及下一条指令。接手者应能只凭文件继续。
```

### A26-FAILURE

```text
[A26-FAILURE] 处理生成或验证 同类问题排查与修复记录 时发生的 {错误}。读取实际输出、当前版本和 A26 输入要求，判断是工具/环境、复现条件缺失还是修复引入新问题。记录已尝试方案和影响；仅执行已授权的安全恢复，不放宽验收、不伪造排查结果。
```

## 完成、更新与交接

检查必填项、来源、质量标准和下游可用性；修复后再次排查并更新记录，不把首轮结论直接复制为新版本通过。排查完成不等于不存在其他缺陷，规则沉淀需同步A08与相关制品。无证据的运行结论保持无法判定。交接给上述使用者，失败按 FAILURE 返回受影响活动或[维护](../stages/maintenance.md)。
