# A05 UI 与交互规格

## 用途与生命周期

- 适用与触发：有 UI 时必要；全局令牌可共用；新增页面、布局、交互或状态变化。
- 生产者：人驱动的 AI；责任角色：设计/产品责任人。
- 输入：A01/A03、用户旅程、设计系统和接口错误语义。
- 使用者与用途：界面实现者、视觉和可访问性验收者。
- 输出：项目内 `docs/pages/task-list.md`；实例、版本、来源及失效遵循[约定](../conventions.md)。
- 配套：[模板](../../templates/A05-ui-spec.md) · [教学填写示例](../../examples/focustask/docs/artifact-examples/A05-ui-spec.md)。

## 必填内容与字段含义

| 章节 | 必须回答 |
| --- | --- |
| 页面目标与权限 | 路由、入口、角色、核心动作与非目标 |
| 设计来源与确认 | 对应 A27 版本、设计来源（设计AI/人工或外包/混合）、确认状态与未确认项 |
| 布局与令牌 | 信息层级、组件、字体、色彩、间距与四视口规则 |
| 交互与状态 | 初始/加载/空/成功/错误/无权限/只读，操作后行为 |
| 表单与可访问性 | 标签、校验、焦点、Escape、取消、读屏与缩放 |
| 数据与验收 | 极端文本、角色、目标视口、预期证据 |

元数据必须包含实例ID、版本、状态、责任角色、输入版本、确认来源、下游用途、未决项。字段未知标明原因；建议与事实分开。

## 质量标准与边界

协议错误映射界面恢复，没有虚假入口，适用的键盘和辅助操作可用；设计来源与确认状态对应 A27 版本，未确认图稿不自动成为要求。依据实际页面和设备定义布局、交互、角色以及完整状态。本文保存当前用于编码与验证的 UI 行为，设计交付与确认过程保存在 A27；精修的表现变化更新本文，行为变化还需同步 A03 与受影响验收项。规则变化先更新来源，相关测试/运行记录标为待重验，旧结果保留原适用版本。

- 不足示例：“页面现代简洁，自适应”。
- 可判定示例：“390×844 使用全屏创建表单，提交失败保留输入，成功焦点回到创建按钮”。

## 人驱动 AI 的操作链

依[提示词协议](../practices/prompt-protocol.md)取得参数。开始时人提供目标与输入位置；AI先读取事实，缺关键规则才追问。选择/修订用真实人的反馈或既有授权，不要求每一步重新批准。只写本文需文件读写；验证/执行代码另需终端和目标环境，UI需浏览器。

### A05-START

```text
[A05-START] 请为 {项目} 的 {目标} 开始准备 A05 UI 与交互规格。先读取 {输入路径}：A01/A03、用户旅程、设计系统和接口错误语义。依据实际页面和设备定义布局、交互、角色以及完整状态。列事实、缺口与下一步；可发现的事实直接核对，不重复问人。
```

### A05-CLARIFY

```text
[A05-CLARIFY] 请澄清 UI 与交互规格 的 {问题}。先读 {输入路径} 并说明冲突来源，给出会改变结果的选项和取舍。重点检查：协议错误映射界面恢复，没有虚假入口，适用的键盘和辅助操作可用；设计来源与确认状态对应 A27 版本，未确认图稿不自动成为要求。未知关键规则暂停定案，已明确内容继续起草。
```

### A05-SELECT

```text
[A05-SELECT] 依据 {确认来源}，本轮对 UI 与交互规格 采用 {已选方案}，适用范围是 {目标}。请记录决定、来源、影响和未确认事项；先核对来源真实存在，再更新状态，不把建议写成人的批准。
```

### A05-GENERATE

```text
[A05-GENERATE] 请依据 {输入路径} 为 {目标} 生成 A05 UI 与交互规格，写入 {输出路径}，使用 templates/A05-ui-spec.md。依据实际页面和设备定义布局、交互、角色以及完整状态。逐章填写规范要求，未知和不适用说明原因；涉及运行结果必须来源于真实工具，未执行不得填通过；返回文件、版本和实际检查。
```

### A05-REVIEW

```text
[A05-REVIEW] 请按下游使用者的视角审阅 {制品路径}：界面实现者、视觉和可访问性验收者。检查 协议错误映射界面恢复，没有虚假入口，适用的键盘和辅助操作可用；设计来源与确认状态对应 A27 版本，未确认图稿不自动成为要求。逐项给出位置、预期/实际、影响与建议，区分缺输入和内容错误；不直接改变已确认标准。
```

### A05-REVISE

```text
[A05-REVISE] 请根据 {反馈} 修订 {制品路径}，保留来源和版本关系。重点仍是：依据实际页面和设备定义布局、交互、角色以及完整状态。先列影响，再修改获准内容，同步关联制品并在 A16 标记需重验的证据；业务规则变化无确认来源时暂停相关改动。
```

### A05-VERIFY

```text
[A05-VERIFY] 请独立核对 {制品路径} 的候选 {候选}，依据 {输入路径} 与 A05 规范。验证 协议错误映射界面恢复，没有虚假入口，适用的键盘和辅助操作可用；设计来源与确认状态对应 A27 版本，未确认图稿不自动成为要求。给出通过/失败/无法判定/阻塞，附步骤、环境、版本和证据；只读产品实现，不以生成者总结当结果。
```

### A05-HANDOFF

```text
[A05-HANDOFF] 请把 UI 与交互规格 交给下一执行者，保存到 {交接路径}。明确 界面实现者、视觉和可访问性验收者，记录输入/输出版本、真实检查、未决项及下一条指令。接手者应能只凭文件继续，涉及运行中的服务先标记需要复查状态。
```

### A05-FAILURE

```text
[A05-FAILURE] 处理生成或验证 UI 与交互规格 时发生的 {错误}。读取实际输出、当前版本和 A05 输入要求，判断是工具/环境、规格缺失还是实现问题。记录已尝试方案和影响；仅执行已授权的安全恢复，不放宽验收、不伪造结果。
```

## 完成、更新与交接

检查必填项、来源、质量标准和下游可用性；每次修改按版本更新，不覆盖旧确认历史。草稿完成不等于业务确认，候选验证不等于已发布。无证据的运行结论保持无法判定。交接给上述使用者，失败按 FAILURE 返回相关阶段。
