# A23 原型版本与反馈确认记录

## 用途与生命周期

- 适用与触发：每轮[原型构建](../stages/prototype-building.md)必要；轻量项目可并入A10或A16章节，但保留版本与确认字段；新版本形成、收到体验反馈或确认行为变化时更新。
- 生产者：人驱动的 AI；责任角色：产品与原型责任人。
- 输入：当前原型与运行入口、A03功能规格、A10计划、人的体验反馈、既有A23与A16追踪表。
- 使用者与用途：下一轮构建执行者、重构与审查责任人、独立验收者。
- 输出：项目内 `evidence/prototypes/{版本}/feedback.md`；实例、版本、来源及失效遵循[约定](../conventions.md)。
- 配套：[模板](../../templates/A23-prototype-feedback.md) · [教学填写示例](../../examples/focustask/docs/artifact-examples/A23-prototype-feedback.md)。

## 必填内容与字段含义

| 章节 | 必须回答 |
| --- | --- |
| 原型版本与运行入口 | 版本或候选标识、启动方式、依赖与环境、访问入口、源码摘要 |
| 当前范围与边界 | 本轮选定行为、已实现部分、模拟与占位、假设清单及依据 |
| 体验反馈与差异 | 反馈来源与时间、观察结果、期望与差异、影响面、涉及制品 |
| 确认与未决 | 已确认行为及来源、未确认项、未决问题与责任人、下一步 |
| 版本演化关系 | 前序版本、变更摘要、行为保持与变化、失效证据与待重验项 |

元数据必须包含实例ID、版本、状态、责任角色、输入版本、确认来源、下游用途、未决项。字段未知标明原因；建议与事实分开。

## 质量标准与边界

版本、运行入口与确认行为可追溯；模拟与假设显式标注，不冒充已实现；反馈区分事实、期望与建议；确认来源真实可查，未确认内容保持待决；演化关系指向具体前序版本与差异，不用笼统措辞代替变更摘要。本记录不是验收报告，不能替代A14的独立结论。

- 不足示例："本轮完成度较高，功能基本可用，反馈良好。"
- 可判定示例："v0.4.2 由目标项目命令启动；AC-01 与 AC-07 已由人体验确认（来源：会话记录 teaching-1）；负责人下拉使用模拟数据，未接成员接口；AC-08 幂等重试未验证，列为未决项。"

## 人驱动 AI 的操作链

依[提示词协议](../practices/prompt-protocol.md)取得参数。开始时人提供本轮目标、原型入口与反馈内容；AI先读取事实，缺关键规则才追问。选择/修订用真实人的反馈或既有授权，不要求每一步重新批准。只写本文需文件读写；核对运行入口和实际行为另需终端和目标环境，UI需浏览器。

### A23-START

```text
[A23-START] 请为 {项目} 的 {目标} 开始准备 A23 原型版本与反馈确认记录。先读取 {输入路径}：当前原型与运行入口、A03 功能规格、A10 计划、本轮反馈与既有 A23。核对版本、已确认行为、模拟与假设边界；列事实、缺口与下一步；可发现的事实直接核对，不重复问人。
```

### A23-CLARIFY

```text
[A23-CLARIFY] 请澄清 原型版本与反馈确认记录 的 {问题}。先读 {输入路径} 并说明冲突来源，给出会改变结果的选项和取舍。重点检查：真实与模拟边界、假设依据、每条反馈对应的确认来源是否明确。未知关键规则暂停定案，已明确内容继续起草。
```

### A23-SELECT

```text
[A23-SELECT] 依据 {确认来源}，本轮对 原型版本与反馈确认记录 采用 {已选方案}，适用范围是 {目标}。请记录决定、来源、影响和未确认事项；先核对来源真实存在，再更新状态，不把建议或体验印象写成人的批准。
```

### A23-GENERATE

```text
[A23-GENERATE] 请依据 {输入路径} 为 {目标} 生成 A23 原型版本与反馈确认记录，写入 {输出路径}，使用 templates/A23-prototype-feedback.md。逐章填写版本与运行入口、范围与模拟边界、反馈与差异、确认与未决、版本演化关系；未知和不适用说明原因；涉及运行结果必须来源于真实工具，未执行不得填通过；返回文件、版本和实际检查。
```

### A23-REVIEW

```text
[A23-REVIEW] 请按下游使用者的视角审阅 {制品路径}：下一轮构建执行者、重构与审查责任人、独立验收者。检查每条确认行为是否可验证、模拟与假设是否标明、反馈是否区分事实与期望、未决项是否有责任人。逐项给出位置、预期/实际、影响与建议，区分缺输入和内容错误；不直接改变已确认标准。
```

### A23-REVISE

```text
[A23-REVISE] 请根据 {反馈} 修订 {制品路径}，保留来源和版本关系。重点仍是：真实与模拟边界、确认行为与演化关系是否随代码变化同步。先列影响，再修改获准内容，同步 A03/A10/A11，并在 A16 标记需重验的证据；业务规则变化无确认来源时暂停相关改动。
```

### A23-VERIFY

```text
[A23-VERIFY] 请独立核对 {制品路径} 的候选 {候选}，依据 {输入路径} 与 A23 规范。验证运行入口可用、确认行为有可观察结果、模拟部分未冒充已实现、版本演化关系可追溯。给出通过/失败/无法判定/阻塞，附步骤、环境、版本和证据；只读产品实现，不以生成者总结当结果。
```

### A23-HANDOFF

```text
[A23-HANDOFF] 请把 原型版本与反馈确认记录 交给下一执行者，保存到 {交接路径}。明确下一轮构建执行者、重构与审查责任人、独立验收者，记录输入/输出版本、真实检查、未决项及下一条指令。接手者应能只凭文件继续，涉及运行中的服务先标记需要复查状态。
```

### A23-FAILURE

```text
[A23-FAILURE] 处理生成或验证 原型版本与反馈确认记录 时发生的 {错误}。读取实际输出、当前版本和 A23 输入要求，判断是工具/环境、规格缺失还是实现问题。记录已尝试方案和影响；仅执行已授权的安全恢复，不放宽验收、不伪造确认或运行结果。
```

## 完成、更新与交接

检查必填项、来源、质量标准和下游可用性；每轮构建形成新版本时增量更新，不覆盖旧确认历史。草稿完成不等于业务确认，运行入口可用不等于验收通过。无证据的运行结论保持无法判定。交接给上述使用者，失败按 FAILURE 返回[原型构建](../stages/prototype-building.md)。
