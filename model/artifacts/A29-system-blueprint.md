# A29 系统蓝图

## 用途与生命周期

- 适用与触发：每个项目维护一个当前有效实例；系统边界、模块地图、外部关系、跨模块流程或全局约束变化时更新。
- 生产者：人驱动的 AI；责任角色：项目产品/技术责任人。
- 输入：A01、A02、A04、A07、A10、所有 A28、外部系统资料、代码事实和开发人员回答。
- 使用者与用途：模块责任人、系统实现者、架构与领域责任人、审查者、独立验收者和后续会话接手者。
- 输出：项目内 `docs/system-blueprint.md`；实例、版本、来源及失效遵循[约定](../conventions.md)。
- 配套：[模板](../templates/A29-system-blueprint.md) · [教学填写示例](../../examples/focustask/docs/artifact-examples/A29-system-blueprint.md)。

## 必填内容与字段含义

| 章节 | 必须回答 |
| --- | --- |
| 系统定位与边界 | 系统目标、业务上下文、包含范围、非目标和 A01 关系 |
| 模块地图 | 模块 ID、名称、职责、状态、优先级、A28 路径和模块依赖 |
| 外部系统与系统关系 | 外部参与者、系统、接口、事件、数据所有权和信任边界 |
| 跨模块旅程与关键流程 | 端到端流程、模块顺序、关键分支、失败传播和恢复边界 |
| 全局角色与不变量 | 跨模块角色边界、权限原则、数据一致性和系统级约束摘要 |
| 系统数据流与非功能摘要 | 主要数据流、性能/安全/可用性目标、监控和 A04/A07 入口 |
| 演化与实施顺序 | 模块依赖、实现状态、原型演化顺序、集成候选和 A10 入口 |
| 关联制品与版本 | A01/A02/A04/A07/A10/A16 及全部 A28 的路径、版本、状态和用途 |
| 未决事项与系统风险 | 问题、来源、影响范围、责任人、决定状态、变更传播和下一步 |
| 确认与 handoff | 确认人、确认版本、复核意见、剩余风险、模块入口和下一条指令 |

每个项目只能有一个当前有效 A29 实例。全部当前模块 A28 必须在 A29 登记，A28 必须反向记录所属 A29 路径和版本。A29 只保存系统级摘要、关系、状态和索引，不复制 A01/A02/A03/A04/A28/A10 的完整权威细节。

## 质量标准与边界

系统目标、边界、模块地图、外部关系、跨模块旅程和全局风险可从本文直接找到；每项摘要都有来源和版本。A01 负责项目范围，A02 负责正式领域与权限规则，A03 负责功能点细节，A04 负责技术契约，A28 负责模块内部上下文，A10 负责实施安排。发生冲突时标记来源、影响和待决定事项，不能覆盖权威制品。

- 不足示例：只列模块名称，没有职责、A28 路径、模块关系、跨模块流程或来源。
- 可判定示例：系统蓝图列出任务与通知模块，标注各自 A28、数据所有权及“创建任务后发布通知事件”的跨模块旅程，并把事件契约指向 A04。

## 人驱动 AI 的操作链

依[提示词协议](../practices/prompt-protocol.md)取得参数。主模型整理资料和问题，开发人员回答系统级关键问题并确认；其他模型复核是可选只读质量环节，复核意见不能自动成为业务确认。

### A29-START

```text
[A29-START] 请为 {项目} 盘点系统蓝图输入。读取 {输入路径}：A01/A02/A04/A07/A10、全部已有 A28、外部系统资料、代码事实和项目约束。列出已知事实、缺口、冲突、模块候选和需要开发人员回答的问题，不补充未确认的系统边界或全局规则。
```

### A29-GENERATE

```text
[A29-GENERATE] 请依据 {输入路径} 使用 model/templates/A29-system-blueprint.md 生成 {项目} 系统蓝图草稿，写入 {输出路径}。建立系统边界、模块地图、外部关系、跨模块旅程、全局约束摘要、演化顺序和关联制品索引。每项摘要记录来源；未知内容标为待确认、模拟或不适用。
```

### A29-CLARIFY

```text
[A29-CLARIFY] 请针对 {系统蓝图问题} 读取 {输入路径}，按影响排序列出需要开发人员回答的问题和选项。记录回答来源、适用范围、影响章节及需要同步的 A01/A02/A04/A28/A10；可从仓库发现的事实直接核对，不重复询问。
```

### A29-REVIEW

```text
[A29-REVIEW] 请只读复核 {制品路径} 的系统边界、模块覆盖、跨模块旅程、外部关系、来源一致性、重复定义、未决项和下游可实施性。区分事实、建议和待确认；不能修改权威制品或把建议写成确认。
```

### A29-REVISE

```text
[A29-REVISE] 请根据开发人员确认和 {复核意见} 修订 {制品路径}。先列影响，再修改获准内容，更新 A28 清单、关联制品版本和失效/待重验项；系统语义没有确认来源时暂停相关改动。
```

### A29-HANDOFF

```text
[A29-HANDOFF] 请交付已确认的 {制品路径} 作为系统级 handoff。记录系统版本、模块/A28 清单、权威制品版本、跨模块风险、未决事项和下一条模块构建指令；说明 A29 不替代 A13 会话交接。
```

## 完成、更新与交接

检查章节、来源、版本、模块清单和下游可用性；确认人和确认版本必须真实记录。草稿完成不等于系统确认，复核建议不等于业务批准。A29 版本变化保留旧版本关系；权威制品或 A28 变化后标记摘要和关联版本待更新。
