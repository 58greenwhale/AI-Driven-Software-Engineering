# A27 视觉与交互设计交付包

## 用途与生命周期

- 适用与触发：有UI且开展[原型精修](../stages/04-prototype-polishing.md)时必要；无UI不生成，但保留A05的接口与交互验收；设计来源、版本或交付内容变化时更新。
- 生产者：人驱动的 AI 与设计来源（设计AI、人工或外包、混合）；责任角色：设计与产品责任人。
- 输入：A05当前UI与交互规格、A03行为与权限规则、设计与可访问性约束、既有设计资产与许可、A12与A25结论。
- 使用者与用途：实施改动的执行者、审查责任人、独立验收者；当前用于编码与验证的UI行为以A05为准。
- 输出：项目内 `docs/design/{特性}/delivery.md`，并记录效果图与源文件存放位置；实例、版本、来源及失效遵循[约定](../conventions.md)。
- 配套：[模板](../../templates/A27-design-delivery.md) · [教学填写示例](../../examples/focustask/docs/artifact-examples/A27-design-delivery.md)。

## 必填内容与字段含义

| 章节 | 必须回答 |
| --- | --- |
| 设计简报与目标 | 待解决问题、目标用户与场景、约束、成功判据 |
| 来源与工具 | 设计AI／人工或外包／混合，工具与版本，使用限制与许可 |
| 参考与交付物 | 参考、效果图、源文件、版本与修改关系、存放位置 |
| 交互与状态说明 | 交互流程、加载/空/错误/权限状态、响应式、可访问性 |
| 行为差异与影响 | 与A03/A05的差异、表现变化与行为变化分类、受影响验收项 |
| 反馈与确认 | 反馈记录、确认来源与范围、未确认项、下游用途 |

元数据必须包含实例ID、版本、状态、责任角色、输入版本、确认来源、下游用途、未决项。字段未知标明原因；建议与事实分开。

## 质量标准与边界

三种来源各有协作方式，但汇入同一交付要求：目标、参考、效果图与源文件、交互说明、状态覆盖、响应式、可访问性、素材来源与许可、行为差异及确认记录。静态效果图无法表达的交互必须补充文字说明；混合来源记录各部分来源、版本与修改关系，不把人工设计伪写成AI生成；未确认图稿只作候选，不自动视为新业务要求；素材来源与许可可查。设计通用要求明确目标、参考、约束与输出，不固定某一家产品的专有语法。

- 不足示例："设计更现代、更好看，用户体验提升。"
- 可判定示例："列表页空态与筛选无结果态分别提供效果图 v2 与文字说明；创建表单在 390x844 使用全屏、成功后焦点回到新建按钮；图标来自开源素材并记录 CC0 许可；本轮为仅表现变化，AC-13 需重验；设计方向由产品责任人按 teaching-1 确认。"

## 人驱动 AI 的操作链

依[提示词协议](../practices/prompt-protocol.md)取得参数。开始时人提供精修目标、当前A05与设计约束；AI先读取事实，缺关键规则才追问。选择/修订用真实人的反馈或既有授权，不要求每一步重新批准。只写本文需文件读写；使用设计AI另需对应工具能力，核对视觉效果需浏览器，人工或外包设计需交付清单与反馈渠道。

### A27-START

```text
[A27-START] 请为 {项目} 的 {精修目标} 开始准备 A27 视觉与交互设计交付包。先读取 {输入路径}：A05 当前规格、A03 行为与权限、设计与可访问性约束、既有素材与许可。列出待改善的界面与交互、必须保持的行为、适用视口与状态清单、可用设计来源及缺口；可发现的事实直接核对，不重复问人。
```

### A27-CLARIFY

```text
[A27-CLARIFY] 请澄清 视觉与交互设计交付包 的 {问题}。先读 {输入路径} 并说明冲突来源，给出会改变结果的选项和取舍。重点检查：设计目标与成功判据是否明确、素材许可是否可查、差异属表现变化还是行为变化。未知关键规则暂停定案，已明确内容继续起草。
```

### A27-SELECT

```text
[A27-SELECT] 依据 {确认来源}，本轮对 视觉与交互设计交付包 采用 {已选方案}，适用范围是 {特性或页面}。请记录决定、来源、影响和未确认事项；先核对来源真实存在，再更新状态，不把未确认图稿写成已接受的新业务要求。
```

### A27-GENERATE

```text
[A27-GENERATE] 请依据 {输入路径} 为 {精修目标} 生成 A27 视觉与交互设计交付包，写入 {输出路径}，使用 templates/A27-design-delivery.md。按设计AI（文生图与图生图，按实际工具能力组织提示词）、人工或外包（设计简报、交付清单与反馈记录）或混合来源组织内容；逐章填写简报与目标、来源与工具、参考与交付物、交互与状态说明、行为差异与影响、反馈与确认；静态图无法表达的交互补文字说明；未知和不适用说明原因；未执行的视觉检查不得填通过。
```

### A27-REVIEW

```text
[A27-REVIEW] 请按下游使用者的视角审阅 {制品路径}：实施改动的执行者、审查责任人、独立验收者。检查交付项是否齐全（状态、响应式、可访问性、素材来源与许可、版本与修改关系）、交互说明是否可实施、行为差异分类是否准确。逐项给出位置、预期/实际、影响与建议，区分缺输入和内容错误；不直接改变已确认标准。
```

### A27-REVISE

```text
[A27-REVISE] 请根据 {反馈} 修订 {制品路径}，保留来源、版本与修改关系。重点仍是：状态覆盖、可访问性、素材许可与行为差异分类是否随设计变化同步。先列影响，再修改获准内容，同步 A05 与受影响的 A03/A07/A16；行为变化无确认来源时暂停相关改动。
```

### A27-VERIFY

```text
[A27-VERIFY] 请独立核对 {制品路径} 的候选 {候选}，依据 {输入路径} 与 A27 规范。在约定视口与缩放条件下核对布局、焦点与语义、加载/空/错误/权限状态，并检查行为变化处的回归结果；截图证明外观，接口与数据结果证明权限与持久化。给出通过/失败/无法判定/阻塞，附步骤、环境、版本和证据。
```

### A27-HANDOFF

```text
[A27-HANDOFF] 请把 视觉与交互设计交付包 交给下一执行者，保存到 {交接路径}。明确实施者、审查责任人与独立验收者，记录确认的设计版本、更新的 A05、表现与行为变化分类、受影响验收项及下一条指令。接手者应能只凭文件继续。
```

### A27-FAILURE

```text
[A27-FAILURE] 处理生成或验证 视觉与交互设计交付包 时发生的 {错误}。读取实际输出、当前版本和 A27 输入要求，判断是设计工具能力不足、素材许可缺失、交付缺项还是实现问题。记录已尝试方案和影响；仅执行已授权的安全恢复，不用未确认图稿替代已接受规格。
```

## 完成、更新与交接

检查必填项、来源、质量标准和下游可用性；设计版本变化后按版本更新并保留修改关系，不覆盖旧确认历史。交付包完成不等于设计已确认，实施结果以真实视觉与回归检查为准。无证据的运行结论保持无法判定。交接给上述使用者，失败按 FAILURE 返回[原型精修](../stages/04-prototype-polishing.md)。
