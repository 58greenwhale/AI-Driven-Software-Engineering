# A03 功能规格（SOP）

## 用途与生命周期

- 适用与触发：每项业务功能必要；AC 可嵌入本文；新增功能、确认需求变化或发现规格歧义。
- 生产者：人驱动的 AI；责任角色：产品责任人。
- 输入：所属模块 A28、A01/A02、页面草稿、接口约束及已接受 ADR。
- 使用者与用途：编码 Agent 生成实现与测试；独立验收者建立逐项用例。
- 输出：项目内 `docs/features/TASK-001-create-task.md`；实例、版本、来源及失效遵循[约定](../conventions.md)。
- 配套：[模板](../templates/A03-feature-spec.md) · [教学填写示例](../../examples/focustask/docs/artifact-examples/A03-feature-spec.md)。

## 必填内容与字段含义

| 章节 | 必须回答 |
| --- | --- |
| 元信息与范围 | 所属模块 ID、A28 路径、编号、优先级、当前状态、责任角色、依赖、包含与不包含 |
| 用户故事与前置条件 | 角色、意图、业务价值；登录、资源和状态条件 |
| 输入与规则 | 字段类型、规范化、必填、边界、默认值、错误文本及规则来源 |
| 流程与数据变化 | 正常流程、角色与权限判定、事务结果、幂等/并发、持久化与数据变化 |
| 异常与界面状态 | 加载、空、错误、权限变化、重试和失败恢复 |
| 接口与关联页面 | API、状态码、字段契约和页面章节引用 |
| 验收与测试映射 | AC 编号、给定/当/那么、验证层次、数据与证据 |
| 待决策与交接 | 未决事项、影响、下一步与不适用依据 |

元数据必须包含实例ID、版本、状态、责任角色、输入版本、确认来源、下游用途、未决项。字段未知标明原因；建议与事实分开。

本文承载当前功能逐步澄清的细节：顶层目标与版本范围留在 A01，业务术语与权限规则以 A02 为准。正常、异常与边界行为、权限与数据变化、验收要求逐项可判定；原型中的模拟与假设须标明，经澄清后才能成为正式需求。

## 质量标准与边界

用例能以界面、接口或其他适用观察判定，覆盖失败恢复和关键边界。核对当前功能的输入、角色、数据变化、重试和错误语义，保留确认的验收编号与覆盖。规则变化先更新来源，相关测试/运行记录标为待重验，旧结果保留原适用版本。

- 不足示例：“创建失败时友好提示”。
- 可判定示例：“响应丢失后用同一幂等键重试，返回首次任务 ID，数据库只增加一条”。

## 人驱动 AI 的操作链

依[提示词协议](../practices/prompt-protocol.md)取得参数。开始时人提供目标与输入位置；AI先读取事实，缺关键规则才追问。选择/修订用真实人的反馈或既有授权，不要求每一步重新批准。只写本文需文件读写；验证/执行代码另需终端和目标环境，UI需浏览器。

### A03-START

```text
[A03-START] 请为 {项目} 的 {目标} 开始准备 A03 功能规格（SOP）。先读取 {输入路径}：所属模块 A28、A01/A02、页面草稿、接口约束及已接受 ADR。核对当前功能的输入、角色、数据变化、重试和错误语义，保留确认的验收编号与覆盖。列事实、缺口与下一步；可发现的事实直接核对，不重复问人。
```

### A03-CLARIFY

```text
[A03-CLARIFY] 请澄清 功能规格（SOP） 的 {问题}。先读 {输入路径} 并说明冲突来源，给出会改变结果的选项和取舍。重点检查：用例能以界面、接口或其他适用观察判定，覆盖失败恢复和关键边界。未知关键规则暂停定案，已明确内容继续起草。
```

### A03-SELECT

```text
[A03-SELECT] 依据 {确认来源}，本轮对 功能规格（SOP） 采用 {已选方案}，适用范围是 {目标}。请记录决定、来源、影响和未确认事项；先核对来源真实存在，再更新状态，不把建议写成人的批准。
```

### A03-GENERATE

```text
[A03-GENERATE] 请依据 {输入路径} 为 {目标} 生成 A03 功能规格（SOP），写入 {输出路径}，使用 model/templates/A03-feature-spec.md。核对当前功能的输入、角色、数据变化、重试和错误语义，保留确认的验收编号与覆盖。逐章填写规范要求，未知和不适用说明原因；涉及运行结果必须来源于真实工具，未执行不得填通过；返回文件、版本和实际检查。
```

### A03-REVIEW

```text
[A03-REVIEW] 请按下游使用者的视角审阅 {制品路径}：编码 Agent 生成实现与测试；独立验收者建立逐项用例。检查 用例能以界面、接口或其他适用观察判定，覆盖失败恢复和关键边界。逐项给出位置、预期/实际、影响与建议，区分缺输入和内容错误；不直接改变已确认标准。
```

### A03-REVISE

```text
[A03-REVISE] 请根据 {反馈} 修订 {制品路径}，保留来源和版本关系。重点仍是：核对当前功能的输入、角色、数据变化、重试和错误语义，保留确认的验收编号与覆盖。先列影响，再修改获准内容，同步关联制品并在 A16 标记需重验的证据；业务规则变化无确认来源时暂停相关改动。
```

### A03-VERIFY

```text
[A03-VERIFY] 请独立核对 {制品路径} 的候选 {候选}，依据 {输入路径} 与 A03 规范。验证 用例能以界面、接口或其他适用观察判定，覆盖失败恢复和关键边界。给出通过/失败/无法判定/阻塞，附步骤、环境、版本和证据；只读产品实现，不以生成者总结当结果。
```

### A03-HANDOFF

```text
[A03-HANDOFF] 请把 功能规格（SOP） 交给下一执行者，保存到 {交接路径}。明确 编码 Agent 生成实现与测试；独立验收者建立逐项用例，记录输入/输出版本、真实检查、未决项及下一条指令。接手者应能只凭文件继续，涉及运行中的服务先标记需要复查状态。
```

### A03-FAILURE

```text
[A03-FAILURE] 处理生成或验证 功能规格（SOP） 时发生的 {错误}。读取实际输出、当前版本和 A03 输入要求，判断是工具/环境、规格缺失还是实现问题。记录已尝试方案和影响；仅执行已授权的安全恢复，不放宽验收、不伪造结果。
```

## 完成、更新与交接

检查必填项、来源、质量标准和下游可用性；每次修改按版本更新，不覆盖旧确认历史。草稿完成不等于业务确认，候选验证不等于已发布。无证据的运行结论保持无法判定。交接给上述使用者，失败按 FAILURE 返回相关阶段。

## FocusTask 可直接使用的填写示例

使用时机：依据教学上下文完善 TASK-001 功能规格（SOP）。输出仅为教学草稿，不创建应用，也不建立真实用户确认。

```text
[A03-GENERATE / 已填示例] 请从仓库根读取 examples/focustask/docs/context.md，
用 model/templates/A03-feature-spec.md 完善 TASK-001 的教学规格，
写入 examples/focustask/docs/artifact-examples/A03-feature-spec.md。
保持 AC-01 至 AC-13 的业务判据；身份/项目/成员仅作为教学前置输入，
本例不包含邀请功能。网络丢失后重试必须保持同键、同任务ID和一条数据。
列出来源、冲突、需同步的界面/测试内容及未决项；现在仅生成规格，不编码。
```

## 五条操作路径及预期

| 路径 | 人的指令 | AI 的可观察输出 | 通过判断 |
| --- | --- | --- | --- |
| 正常生成 | 上述已填 GENERATE | 规则与AC完整草稿、来源、依赖差异 | 未将预置功能写成实现；AC保留 |
| 缺失权限 | CLARIFY，问题填“输入没有规定 Viewer 能否写入” | 优先读取既有权限矩阵，若确有规则直接引用；全部来源缺失才向人提选项 | 不猜权限，不问已经可查的事实 |
| 反馈修订 | REVISE，反馈填“明确相同幂等键不同内容返回409，来源架构约定” | 补异常用例与测试映射，并标相关证据待重验 | 创建正常规则未被改动 |
| 独立检查 | VERIFY，候选填规格文件内容摘要 | AC完整性、规则来源及错误路径的检查记录 | 无运行环境不声称应用通过 |
| 跨阶段交接 | HANDOFF，交接路径填任务交接文档 | A03版本、必读文件、未决项、下一步A07测试策略指令 | 下一位无需原聊天即可开始 |

这些是操作样板及判据；未来实际项目应另外保存真实执行结果，不在教学例预填成功。
