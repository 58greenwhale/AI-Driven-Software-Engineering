# A01 范围说明

## 用途与生命周期

- 适用与触发：必要；可与 A02/A03 合并；首次项目、版本目标或范围发生变化。
- 生产者：人驱动的 AI；责任角色：产品责任人。
- 输入：人的目标、现有产品资料、预算和环境限制。
- 使用者与用途：设计者和任务规划者据此选择本轮工作，验收者据此区分必做与延期。
- 输出：项目内 `docs/scope.md`；实例、版本、来源及失效遵循[约定](../conventions.md)。
- 配套：[模板](../../templates/A01-scope.md) · [教学填写示例](../../examples/focustask/docs/artifact-examples/A01-scope.md)。

## 必填内容与字段含义

| 章节 | 必须回答 |
| --- | --- |
| 背景与目标 | 问题、目标用户、当前约束及信息来源 |
| 场景与成功条件 | 端到端动作和能观察的结果，不使用主观形容词 |
| 版本范围 | 逐项列版本、包含、排除与理由 |
| 约束与风险 | 技术、资源、时间、合规和数据限制 |
| 决定与未决事项 | 已确认来源、待决定问题及影响范围 |

元数据必须包含实例ID、版本、状态、责任角色、输入版本、确认来源、下游用途、未决项。字段未知标明原因；建议与事实分开。

## 质量标准与边界

每个目标有成功条件，延期项不冒充交付，产品指标与技术判据区分。区分产品愿景、本轮交付与未来需求；每个范围决定引用来源。本文只承载顶层目标、版本范围与成功条件，功能细节由 A03 逐步澄清；细节缺失不阻止启动原型构建，但关键业务规则未确认时列为待决，不写成已确认。规则变化先更新来源，相关测试/运行记录标为待重验，旧结果保留原适用版本。

- 不足示例：“做一个好用的任务系统”。
- 可判定示例：“教学场景 teaching-base 预期支持已登录 Editor 在给定项目创建持久化任务，Viewer 只能查看”。

## 人驱动 AI 的操作链

依[提示词协议](../practices/prompt-protocol.md)取得参数。开始时人提供目标与输入位置；AI先读取事实，缺关键规则才追问。选择/修订用真实人的反馈或既有授权，不要求每一步重新批准。只写本文需文件读写；验证/执行代码另需终端和目标环境，UI需浏览器。

### A01-START

```text
[A01-START] 请为 {项目} 的 {目标} 开始准备 A01 范围说明。先读取 {输入路径}：人的目标、现有产品资料、预算和环境限制。区分产品愿景、本轮交付与未来需求；每个范围决定引用来源。列事实、缺口与下一步；可发现的事实直接核对，不重复问人。
```

### A01-CLARIFY

```text
[A01-CLARIFY] 请澄清 范围说明 的 {问题}。先读 {输入路径} 并说明冲突来源，给出会改变结果的选项和取舍。重点检查：每个目标有成功条件，延期项不冒充交付，产品指标与技术判据区分。未知关键规则暂停定案，已明确内容继续起草。
```

### A01-SELECT

```text
[A01-SELECT] 依据 {确认来源}，本轮对 范围说明 采用 {已选方案}，适用范围是 {目标}。请记录决定、来源、影响和未确认事项；先核对来源真实存在，再更新状态，不把建议写成人的批准。
```

### A01-GENERATE

```text
[A01-GENERATE] 请依据 {输入路径} 为 {目标} 生成 A01 范围说明，写入 {输出路径}，使用 templates/A01-scope.md。区分产品愿景、本轮交付与未来需求；每个范围决定引用来源。逐章填写规范要求，未知和不适用说明原因；涉及运行结果必须来源于真实工具，未执行不得填通过；返回文件、版本和实际检查。
```

### A01-REVIEW

```text
[A01-REVIEW] 请按下游使用者的视角审阅 {制品路径}：设计者和任务规划者据此选择本轮工作，验收者据此区分必做与延期。检查 每个目标有成功条件，延期项不冒充交付，产品指标与技术判据区分。逐项给出位置、预期/实际、影响与建议，区分缺输入和内容错误；不直接改变已确认标准。
```

### A01-REVISE

```text
[A01-REVISE] 请根据 {反馈} 修订 {制品路径}，保留来源和版本关系。重点仍是：区分产品愿景、本轮交付与未来需求；每个范围决定引用来源。先列影响，再修改获准内容，同步关联制品并在 A16 标记需重验的证据；业务规则变化无确认来源时暂停相关改动。
```

### A01-VERIFY

```text
[A01-VERIFY] 请独立核对 {制品路径} 的候选 {候选}，依据 {输入路径} 与 A01 规范。验证 每个目标有成功条件，延期项不冒充交付，产品指标与技术判据区分。给出通过/失败/无法判定/阻塞，附步骤、环境、版本和证据；只读产品实现，不以生成者总结当结果。
```

### A01-HANDOFF

```text
[A01-HANDOFF] 请把 范围说明 交给下一执行者，保存到 {交接路径}。明确 设计者和任务规划者据此选择本轮工作，验收者据此区分必做与延期，记录输入/输出版本、真实检查、未决项及下一条指令。接手者应能只凭文件继续，涉及运行中的服务先标记需要复查状态。
```

### A01-FAILURE

```text
[A01-FAILURE] 处理生成或验证 范围说明 时发生的 {错误}。读取实际输出、当前版本和 A01 输入要求，判断是工具/环境、规格缺失还是实现问题。记录已尝试方案和影响；仅执行已授权的安全恢复，不放宽验收、不伪造结果。
```

## 完成、更新与交接

检查必填项、来源、质量标准和下游可用性；每次修改按版本更新，不覆盖旧确认历史。草稿完成不等于业务确认，候选验证不等于已发布。无证据的运行结论保持无法判定。交接给上述使用者，失败按 FAILURE 返回相关阶段。
