# TASK-001 创建任务

## 1. 元信息

- 优先级：P0
- 状态：就绪
- 所属里程碑：M2 任务核心流程
- 依赖：PROJECT-002、MEMBER-001
- 关联页面：`docs/pages/task-list.md`
- 关联领域规则：`docs/domain.md`
- 关联权限规则：`docs/permissions.md`

## 2. 用户故事

作为项目 Admin 或 Editor，我希望在项目中创建一条任务并可选地分配负责人和截止日期，以便团队知道需要完成什么、由谁负责以及何时到期。

## 3. 目标

允许具备编辑权限的项目成员通过任务列表页面创建一条合法、持久化且不会因重复提交而重复生成的任务。

## 4. 范围

### 本任务包含

- 从任务列表打开创建表单；
- 输入任务标题；
- 可选项目成员作为负责人；
- 可选未来或当天日期作为截止日期；
- 客户端基础校验和服务端完整校验；
- 防止重复提交；
- 创建成功后更新列表；
- 加载、成功、字段错误、权限错误和网络错误状态。

### 本任务不包含

- 创建时选择初始状态，初始状态固定为 `todo`；
- 描述、标签、优先级、子任务、附件和评论；
- 邀请新成员；
- 批量创建或从模板创建；
- 编辑已创建任务；
- 发送通知。

## 5. 角色与权限

- Admin：允许创建；
- Editor：允许创建；
- Viewer：不显示创建入口，API 返回 `403`；
- Non-member：页面和 API 均不能确认项目存在；
- 归档项目：任何角色都不能创建任务。

详细规则见 `docs/permissions.md`。

## 6. 前置条件

- 用户已登录；
- 项目存在且状态为 `active`；
- 用户是该项目的 Admin 或 Editor；
- 项目成员数据已经可以读取。

## 7. 输入与规则

| 字段 | 必填 | 输入形式 | 规则 | 错误信息 |
| --- | --- | --- | --- | --- |
| 标题 | 是 | 单行文本 | 去除首尾空格后 1–100 字符 | 空值：“请输入任务标题”；超长：“任务标题不能超过 100 个字符” |
| 负责人 | 否 | 单选下拉 | 必须是当前项目成员 | “所选负责人不属于当前项目” |
| 截止日期 | 否 | 日期选择器 | 不得早于项目时区的今天 | “截止日期不能早于今天” |

附加规则：

- 服务端负责最终校验，客户端校验不能替代服务端校验；
- 标题以去除首尾空格后的值保存，内部连续空格不做修改；
- 未选择负责人和日期时保存为 `null`；
- 状态固定为 `todo`；
- `createdBy` 取当前登录用户，不接受客户端传值；
- 负责人列表按显示名称升序排列，同名时按邮箱升序排列。

## 8. 正常流程

1. 用户进入活动项目的任务列表页面。
2. 用户点击“新建任务”。
3. 系统打开创建表单，焦点进入标题字段。
4. 用户填写标题，可选负责人和截止日期。
5. 用户点击“创建任务”。
6. 客户端校验输入并发送带唯一 `Idempotency-Key` 的请求。
7. 服务端验证登录状态、项目状态、权限和字段规则。
8. 服务端在事务中创建任务并返回 `201`。
9. 页面关闭表单，将新任务插入符合当前筛选条件的位置。
10. 页面显示简短成功提示“任务已创建”，焦点回到“新建任务”按钮。

## 9. 页面与交互状态

### 初始状态

- 标题为空；
- 负责人默认“未分配”；
- 截止日期为空；
- 创建按钮可点击，但空标题提交后显示字段错误。

### 提交中

- 按钮文字变为“创建中…”并显示进度；
- 提交按钮不可重复触发；
- 其他字段暂时不可编辑；
- 关闭操作不可用，避免用户误以为已取消服务端请求。

### 成功

- 关闭表单；
- 列表显示服务端返回的任务；
- 不通过复制客户端输入伪造成功记录；
- 当前筛选会排除该任务时，不强行改变筛选，提示“任务已创建，但不符合当前筛选条件”。

### 字段错误

- 表单保持打开；
- 在字段下方显示错误；
- 焦点移动到第一个错误字段；
- 用户已填写的其他合法值保留。

### 网络或服务端错误

- 表单保持打开，所有输入保留；
- 显示“创建失败，请重试”；
- 提供重试按钮；
- 重试必须沿用第一次提交的幂等键，直到内容发生变化或创建成功。

### 权限或项目状态变化

- 如果表单打开后用户权限被移除，服务端拒绝请求；
- 页面显示“你没有权限创建任务”；
- 关闭表单并重新获取项目权限；
- 如果项目已归档，页面进入归档只读状态。

## 10. API 行为

接口：`POST /api/v1/projects/:projectId/tasks`

请求头必须包含 `Idempotency-Key`。请求和响应结构见 `docs/architecture.md`。

| 场景 | 状态码 | 数据变化 |
| --- | --- | --- |
| 创建成功 | `201` | 创建一条任务 |
| 同一幂等键重复请求且内容相同 | `201` | 不重复创建，返回首次结果 |
| 同一幂等键重复请求但内容不同 | `409` | 无变化 |
| 字段校验失败 | `400` | 无变化 |
| 未登录 | `401` | 无变化 |
| Viewer 创建 | `403` | 无变化 |
| 项目不存在或 Non-member 访问 | `404` | 无变化 |
| 项目已归档 | `409`，错误码 `PROJECT_ARCHIVED` | 无变化 |

## 11. 验收用例

### AC-01：使用必填字段创建任务

给定用户是活动项目的 Editor，任务数量为 3，
当用户只输入标题“准备周会材料”并提交，
那么接口返回 `201`，列表显示该任务，刷新后仍存在，任务数量为 4，状态为 `todo`，负责人和截止日期均为空。

### AC-02：创建带负责人和截止日期的任务

给定用户是 Admin，用户 B 是当前项目成员，
当用户输入合法标题、选择用户 B，并选择今天之后的日期，
那么只创建一条任务，负责人和截止日期与提交值一致。

### AC-03：标题空白

给定标题输入为三个空格，
当用户提交，
那么标题字段显示“请输入任务标题”，请求不应发送，任务数量不变。

### AC-04：服务端拒绝超长标题

给定客户端直接向 API 提交 101 字符标题，
当服务端处理请求，
那么返回 `400` 和标题字段错误，数据库无新增任务。

### AC-05：无效负责人

给定负责人是另一个项目的成员，
当用户提交，
那么服务端返回 `400`，错误为“所选负责人不属于当前项目”，数据库无新增任务。

### AC-06：过去的截止日期

给定截止日期早于项目时区的今天，
当用户提交，
那么页面显示“截止日期不能早于今天”，数据库无新增任务。

### AC-07：重复点击

给定合法表单，
当用户快速双击创建按钮，
那么界面只发起一个有效提交，并且数据库只新增一条任务。

### AC-08：响应丢失后重试

给定服务端已创建任务但客户端未收到响应，
当客户端使用相同幂等键重试相同请求，
那么服务端返回第一次创建的任务，数据库中只有一条记录。

### AC-09：Viewer 无权限

给定用户是项目 Viewer，
那么页面不显示“新建任务”；当其直接调用创建 API 时，返回 `403`，数据库无变化。

### AC-10：Non-member 不可探测项目

给定用户不是项目成员，
当其调用创建 API，
那么返回 `404`，响应不说明项目是否存在，数据库无变化。

### AC-11：项目归档后拒绝创建

给定 Admin 已打开创建表单，随后项目被另一 Admin 归档，
当该用户提交，
那么返回 `409 PROJECT_ARCHIVED`，页面关闭表单并显示归档只读状态，数据库无新增任务。

### AC-12：网络失败保留输入

给定用户已经填写全部字段，
当请求因网络中断失败，
那么表单保持打开，输入保持不变，显示重试入口；恢复网络后重试只创建一条任务。

### AC-13：移动端和键盘操作

给定视口为 `390x844` 或用户只使用键盘，
当用户打开、填写、提交并关闭表单，
那么控件无重叠或裁切，焦点顺序合理，成功后焦点返回“新建任务”按钮。
