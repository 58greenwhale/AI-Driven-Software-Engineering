# 统一完成标准

功能只有在所有适用项目均满足时才算完成。标记“不适用”时必须说明原因。

## 1. 需求

- [ ] 实现内容仅覆盖已确认的任务范围；
- [ ] 所有验收用例均已通过；
- [ ] 正常、异常、空数据、加载和无权限路径均有定义并已处理；
- [ ] 实现与领域模型、权限矩阵和决策记录一致；
- [ ] 没有通过隐含假设补充关键业务规则。

## 2. 数据和服务端

- [ ] 输入在服务端完成格式和业务校验；
- [ ] 权限在服务端校验，不能只依赖隐藏界面控件；
- [ ] 数据库约束和迁移与领域模型一致；
- [ ] 写操作具备要求的事务性、幂等性或并发保护；
- [ ] 错误不会产生部分或重复数据；
- [ ] 日志不包含密码、令牌或不必要的个人数据。

## 3. UI 和可访问性

- [ ] 复用设计系统和现有组件；
- [ ] 已验证 `1440x900`、`1024x768`、`768x1024` 和 `390x844`；
- [ ] 无重叠、文字溢出、控件裁切或非预期横向滚动；
- [ ] 键盘可完成核心操作，焦点清晰且顺序合理；
- [ ] 表单标签、错误、弹窗和动态状态可被辅助技术识别；
- [ ] 放大至 200% 后核心流程仍可使用。

## 4. 代码质量

- [ ] 代码符合项目模块边界和现有风格；
- [ ] 没有与任务无关的大范围重构或依赖升级；
- [ ] 没有遗留调试代码、无意义日志或硬编码密钥；
- [ ] 复杂规则具有必要而简洁的说明；
- [ ] 新依赖具有明确用途并经过安全检查。

## 5. 测试和构建

- [ ] `npm run lint` 通过；
- [ ] `npm run typecheck` 通过；
- [ ] `npm test` 通过；
- [ ] `npm run test:e2e` 中相关流程通过；
- [ ] `npm run build` 通过；
- [ ] 新增或修改的业务规则具有自动化测试；
- [ ] 没有被忽略的相关回归失败。

如果仓库尚未提供某条命令，交付报告必须标为“无法执行”并创建后续任务，不能将其记为通过。

## 6. 非功能要求

- [ ] 相关性能指标达到 `non-functional.md` 的目标；
- [ ] 安全和隐私要求已验证；
- [ ] 错误具备可追踪的请求标识；
- [ ] 必要的健康检查、指标或告警已更新；
- [ ] 目标浏览器和设备范围内核心功能可用。

## 7. 文档和交付

- [ ] 规格、API 和实际行为一致；
- [ ] 必要的环境变量示例和迁移说明已更新；
- [ ] 提供测试结果和关键页面截图；
- [ ] 已知限制、风险和规格偏差已记录；
- [ ] 独立验收 Agent 已给出“通过”结论。

## 8. 交付报告模板

```markdown

## 完成内容
- ...

## 主要改动
- `path/to/file`：...

## 验证结果

- `npm run build`：通过
- UI：四个目标视口通过

## 验收证据
- 截图：...
- 测试日志：...

## 未解决事项
- 无；或列出风险、限制和对应后续任务。
```
