# ADR-0003：实证工具链与独立本地数据库

- 状态：依据计划允许的主要版本ADR流程选定；后续本地生成、迁移、集成、构建及发布验证通过，证据见evidence/runs与acceptance-v01/v02。
- 责任角色：技术执行者；不是虚构的用户逐项批准。
- 来源：实际工具检查、npm官方注册表元数据；D06要求直接本地运行。

## 背景与选择

原产品架构指定PostgreSQL16；本机只有PostgreSQL18.3，已有用户服务监听5432。另有Node24.14.0/npm11.9.0，可避免修改默认Node26。框架沿用Next15/React19/TypeScript5。

本地实证选择使用现有PostgreSQL18.3二进制初始化任务专用数据目录，另选回环端口，开发/测试/发布独立数据库。它不是对用户数据库的升级，也不能声明PostgreSQL16已验证。数据库版本变更仅限实证；原产品愿景约束保留。

备选：另行安装PostgreSQL16可精确匹配旧示例，但增加系统安装依赖；复用已有5432库会扩大数据风险，因此不采用。若18.3出现契约/迁移兼容问题，保留证据并重新评估，不改业务AC求通过。

## 版本与验证

运行时Node24.14.0、npm11.9.0；官方注册表确认Next15.5.25支持Node>=20，Prisma6.19.3支持Node>=18.18。选择这些补丁线，React19.3.0；TypeScript保持5系列。其他开发工具安装时锁定确切版本，记录lockfile；不使用无约束latest运行发布。

准备、迁移、API/数据库集成、生产构建、重启数据、回退和安全审计必须实际通过后才能称基线可用。制定本ADR时尚无结果，之后的post-ci-baseline、post-ci-unit、acceptance-v01/v02和A19已提供本地兼容性证据；不能推导旧PostgreSQL16版本已验证。系统Node与用户数据库服务不修改。
