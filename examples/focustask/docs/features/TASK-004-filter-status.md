# A03 TASK-004：状态筛选（v0.2）

状态：实证实现完成并已发布v0.2.0-rc2。来源：根实施计划及[变更单](../changes/CHANGE-001.md)。前置：成员可读取项目与任务，v0.1发布完成。验收与发布证据见[独立复核](../../evidence/acceptance-v02.md)和[运行记录](../../evidence/releases/v0.2.0-rc2/run.md)。

## 输入与结果

status可缺省或为空表示全部，合法枚举todo/in_progress/done；API非法值400，UI显示可恢复错误并可清除。总数为当前过滤结果，排序保持updatedAt倒序、id升序。客户端发送当前URL的status，URL是可恢复选择来源。

## 交互与异常

选择变化使用浏览器历史记录；刷新/后退同步选择和结果。请求失败保留选择并可重试，不显示筛选空。慢响应不得覆盖后来选择；卸载组件后不应用旧结果。

项目真空与筛选空区分：无任务保持“还没有任务”；有其他状态但本筛选空显示“没有符合条件的任务”和清除按钮。Viewer和归档项目可筛选，创建能力不变。新建任务固定todo，done/in_progress筛选下成功提示不匹配且不改变选择。

## 数据与测试

不修改schema、状态机、权限或已有任务。所有写入仍遵守TASK-001。验收编号CF-01–09及对应给定/当/那么以CHANGE-001为唯一来源；服务/API枚举检查、URL/空状态/竞态/创建反馈E2E及500条数据筛选P95样本已执行。CF-09是APP-06后增加的创建请求与浏览器历史并发场景，原判据未降低。

四个规定视口均验证筛选控件、无结果、错误与新建反馈，保留原视口和权限回归。失败先检查契约与请求版本，不通过忽略URL或移除测试规避问题。
