# A18 本地生产构建发布与回退

状态：v0.1首版发布、v0.2 rc2升级、坏包失败及回退/恢复均已实际执行；真实结果见[发布与恢复记录](../evidence/releases/v0.2.0-rc2/run.md)。依据用户D06，无Docker。

## 环境前置

在app目录使用Node24；node scripts/setup.mjs release准备专用focustask_release库和忽略配置。数据库实例127.0.0.1:55461为本任务所有，5432已有用户服务不可改。发布端口3212；启动前检查归属，不杀占用端口的未知进程。

## 发布操作

1. 确认候选通过规格/独立验收、安全审计和五项检查；源快照与测试记录一致。
2. npm run build生成生产构建，不使用dev服务器。
3. node scripts/release.mjs pack v0.1.0复制standalone及静态资源到.runtime/releases/v0.1.0，生成文件摘要。版本已存在则拒绝覆盖，应另取候选标签。
4. 使用该版本对应迁移部署到release数据库；重复执行只应用未执行迁移。不得seed重置发布数据。
5. node scripts/release.mjs start v0.1.0检查专属服务并启动3212；健康通过后还需登录/权限/创建/刷新/重启持久化冒烟。
6. 保存A17/A19的实际命令、源码及构建标识、配置名称、数据ID与结果。健康通过不能替代业务冒烟。

## 回退

使用已保存的前版产物：node scripts/release.mjs start v0.1.0。脚本只停止状态文件指向且ps命令确认路径匹配的本任务进程；配置和发布数据库保留。回退前检查新旧schema兼容，不支持自动反向执行任意迁移。

恢复后验证版本健康、原Task.id可读、合法新建及Viewer拒绝，记录结果。失败时保留日志与数据，不删除库重新seed。停止运行用node scripts/release.mjs stop，不停止用户服务。
