# A10 设计与实施计划（plan） — FocusTask 教学示例

> 教学填写示例。用于演示文档内容与检查方法，不作通过结论。

## 元信息

- 实例ID：FocusTask-A10-teaching
- 版本：teaching-1
- 状态：草稿（教学）
- 责任角色：迭代责任人
- 输入：[FocusTask 教学上下文](../context.md)，版本 teaching-1。
- 确认来源：教学设定；实际项目需另行确认。
- 下游用途：协调者和执行 Agent 选择下一个就绪任务。
- 生成方式：按制品模板填写的教学例。

## 迭代范围

teaching-base 演示创建和查看任务；身份、项目和成员为教学输入，邀请不在范围。

## 方案与理由

创建重试选服务端幂等键而非仅前端禁用按钮，理由是 AC-08 要求响应丢失后重试返回同一任务且只有一条数据，被否方案无法覆盖网络丢失场景。teaching-filter 的状态筛选选服务端过滤，理由是权限判定与数据量都在服务端，代价是查询接口需增加状态参数。

## 任务表

示例任务按最小准备、TASK-001 原型构建、适用重构、审查和精修、独立验收、发布组织；具体活动可合并。实施时按目标项目的依赖确定顺序。

## 活动裁剪与并行边界

teaching-base 走构建、审查、独立验收；教学设定下无重构需要，A24 可省，理由是当前实现已满足教学工程约束。teaching-filter 可与 teaching-base 并行，文件归属为筛选相关组件与任务查询接口，共享的 A02 权限规则由产品责任人维护。

## 依赖与就绪

数据库就绪是身份实现依赖；创建初始化命令不要求该命令先存在。teaching-filter 依赖 teaching-base 的列表接口稳定。

## 验证与集成条件

每项任务列验证方式：创建与重试用集成测试加浏览器断网恢复，权限用 API 与数据结果。集成顺序先 teaching-base 后 teaching-filter；集成后重验 AC-08、AC-09 与筛选叠加创建的跨功能路径。

## 流转与证据

候选验收通过后集成，再标完成，不能提前标已发布。

## 变更与下一步

新筛选需求成为单独变更任务，旧版通过不直接继承。
