# A15 DRILL-002：失败发布与版本回退

类型：受控失败候选的本地发布演练。目标：在保留业务数据的前提下恢复已知可用版本，验证A17/A18/A19/A20制品。

## 步骤与边界

v0.2发布与冒烟完成后，复制其产物到一个明确的bad演练版本，替换仅该副本的启动入口为返回503健康失败的本地进程。记录注入差异、摘要和版本，不修改正常产物或数据库。

启动bad候选应健康失败。保存失败日志，使用A18恢复v0.1旧构建并读出v0.2前已经确认的Task.id，再合法创建和校验Viewer拒绝。最后恢复v0.2当前版本并再次验证旧/新数据均存在。

数据库schema本次没有破坏性变更，因此采用代码/配置切换回退；不能把这次演练说成验证了任意不可逆数据库迁移。不得删除库重新seed，不停止未知进程。

## 关闭判据

坏版本真实运行且失败被检测；旧版恢复后数据校验通过；新版恢复后核心读写和权限通过；所有产物、运行和数据检查点可追踪。若失败进程尚占端口，先核对归属后停止；不盲目杀端口。
