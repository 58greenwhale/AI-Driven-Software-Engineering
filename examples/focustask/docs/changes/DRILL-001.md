# A15 DRILL-001：隔离的 Viewer 权限缺陷演练

类型：人为注入故障，用于评价验收和维护链路；不是实际用户数据事故。依据实施计划P4-02，执行边界已授权。

## 预期与注入

正常规格保持Viewer只读、直接创建403且数据不变。演练复制一个已验证版本到忽略的独立目录，使用专用drill数据库与3213端口。只在该源码副本移除创建服务中的Viewer拒绝分支，再构建。正常源码、发布产物和release数据库保持独立。

将副本作为候选交给独立验证者，只提供既有权限规格、地址、虚构夹具和验证入口，不给编码者的通过声明。验证者执行同一AC-09并记录预期/实际与数据变化。协调者保存注入差异和候选摘要，用于之后解释这是演练。

## 修复与关闭

失败确认后在演练副本恢复服务端角色检查，重新构建同版本的修复候选（使用独立制品编号），再让相同AC和相关回归验证。保留失败与修复日志；不修改规格或断言来让演练通过。

完成需证明：独立验证者发现缺陷、写入只发生在drill库、修复后403且数量不变、正常源码与发布候选哈希未被注入修改、相关回归通过。演练结束只停止其归属进程，日志和脱敏结果保留。

## 实际执行提示词（模板实例）

```text
[MAINT-START / DRILL-001] 请对指定演练候选按TASK-001 AC-09验证Viewer行为。
先核对候选与隔离数据库，不修改实现。执行直接API并比较前后任务数，
按预期403和无新增判定，保存请求状态、数据计数与候选摘要，失败写缺陷记录。
不要以按钮隐藏或编码者说明作为通过依据。
```

注入内容只用于演练来源记录；独立验证任务按产品判据检查，不要求其不知道演练存在，关键是不能改变标准。
