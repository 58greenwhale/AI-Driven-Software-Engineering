# 角色与权限

> 迁移说明：保留的 FocusTask 产品规格输入；本地实证仅覆盖选定切片，范围与状态以 [实证范围](empirical-scope.md) 和 [实证任务表](iteration-plan.md) 为准。本文不是功能已实现的证明。

## 1. 项目角色

- `Admin`：管理项目、成员和任务。
- `Editor`：创建和修改任务。
- `Viewer`：只读访问项目和任务。
- `Non-member`：不是项目成员，包括未登录用户。

## 2. 权限矩阵

| 资源或操作 | Admin | Editor | Viewer | Non-member |
| --- | --- | --- | --- | --- |
| 查看活动项目 | 允许 | 允许 | 允许 | 拒绝 |
| 查看归档项目 | 允许 | 允许 | 允许 | 拒绝 |
| 修改项目信息 | 允许 | 拒绝 | 拒绝 | 拒绝 |
| 邀请或移除成员 | 允许 | 拒绝 | 拒绝 | 拒绝 |
| 修改成员角色 | 允许 | 拒绝 | 拒绝 | 拒绝 |
| 归档项目 | 允许 | 拒绝 | 拒绝 | 拒绝 |
| 创建任务 | 允许 | 允许 | 拒绝 | 拒绝 |
| 修改任务 | 允许 | 允许 | 拒绝 | 拒绝 |
| 修改任务状态 | 允许 | 允许 | 拒绝 | 拒绝 |

归档项目中的所有写操作均拒绝，即使用户角色为 Admin。

## 3. 界面规则

- 无权限的主要写操作入口应隐藏，例如 Viewer 看不到“新建任务”按钮。
- 如果用户通过旧页面、书签或直接地址进入无权限操作，应显示明确的无权限状态。
- 不应通过禁用按钮暗示用户未来可执行一个其角色永久不允许的操作。
- 归档项目应展示只读标记，并隐藏所有写操作入口。

## 4. 服务端规则

- 每个受保护请求均根据当前用户和目标项目重新校验权限。
- 不信任客户端提交的角色、项目成员身份或创建人字段。
- 不存在的资源和无权查看的资源均返回 `404`，防止泄露资源是否存在。
- 已登录且能查看资源、但无权执行写操作时返回 `403`。
- 未登录请求返回 `401`。

## 5. 角色管理约束

- 项目至少有一名 Admin。
- 最后一名 Admin 不能退出项目、被移除或降级。
- 用户不能提升自己的角色。
- Admin 可以调整其他成员的角色，但不得绕过“至少一名 Admin”的规则。

## 6. 验收要求

每项受保护功能至少验证：

- 允许角色可通过界面和 API 完成操作；
- Viewer 看不到写操作入口，直接调用 API 仍被拒绝；
- Non-member 无法确认项目及任务是否存在；
- 归档项目拒绝全部写操作；
- 权限拒绝不会产生数据变化。
