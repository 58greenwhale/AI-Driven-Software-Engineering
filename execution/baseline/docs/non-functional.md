# 非功能要求

## 1. 测试环境基线

除特别说明外，性能验收使用：

- 生产构建；
- Chrome 最新稳定版；
- 4 核 CPU、8 GB 内存的测试环境；
- 网络往返延迟 100ms，下行 10 Mbps；
- 项目包含 500 条任务和 20 名成员。

## 2. 性能

| 指标 | 目标 | 验收方法 |
| --- | --- | --- |
| 项目任务列表首屏可交互 | P95 <= 2.5 秒 | 在基线环境运行 20 次并记录 |
| 创建任务 API | P95 <= 500ms | 100 次合法请求，排除网络延迟 |
| 筛选任务后的结果更新 | P95 <= 1 秒 | 500 条任务数据集下测试 |
| 页面布局偏移 CLS | <= 0.1 | Lighthouse 或等效工具 |
| 单页初始 JS 压缩体积 | <= 250KB | 构建产物分析，不含框架共享缓存 |

当指标无法在本地稳定复现时，应记录环境、测量方式和原始结果，不得只写“性能良好”。

## 3. 可用性和可靠性

- 月度目标可用性为 99.5%，不包括提前公告的维护窗口；
- 创建和更新操作必须具备事务一致性；
- 重试同一创建任务请求不得产生重复记录；
- 应用重启后已确认成功的数据不得丢失；
- 外部依赖失败时返回可识别错误，不无限等待；
- 服务端请求超时上限为 10 秒。

## 4. 安全

- 全站只通过 HTTPS 提供生产服务；
- 会话 Cookie 设置 `HttpOnly`、`Secure` 和合适的 `SameSite`；
- 所有写请求验证身份、项目成员关系和具体操作权限；
- 密码使用行业认可的慢哈希算法；
- 用户输入在服务端验证，输出按上下文安全编码；
- 登录接口需要速率限制：单 IP 每分钟最多 10 次失败尝试；
- 依赖中不得存在已知的 Critical 或 High 级可利用漏洞后仍发布；
- 错误响应不得泄露数据库结构、内部路径或堆栈信息。

## 5. 隐私

- MVP 仅收集邮箱、显示名称和产品使用所必需的数据；
- 日志不得记录密码、会话内容、完整认证头或无关个人数据；
- 测试和截图使用虚构数据；
- 用户数据不得用于未在产品政策中说明的用途。

## 6. 可访问性

- 核心流程达到 WCAG 2.2 AA；
- 键盘可完成登录、打开项目、筛选、创建和完成任务；
- 页面放大至 200% 后核心功能仍可操作；
- 自动化无障碍扫描不得包含严重或关键问题；
- 屏幕阅读器能够识别表单标签、错误信息、对话框标题和状态更新。

## 7. 兼容性

- 支持最近两个稳定版本的 Chrome、Edge、Firefox 和 Safari；
- 支持 iOS Safari 和 Android Chrome 最近两个主要版本；
- 视口宽度支持 320px–1920px；
- 不支持 Internet Explorer。

## 8. 备份和恢复

- 生产数据库每日完整备份，每 6 小时增量备份；
- 恢复点目标 RPO 不超过 6 小时；
- 恢复时间目标 RTO 不超过 4 小时；
- 每季度执行一次恢复演练并保存结果；
- 备份保留 30 天且访问受限。

## 9. 可观测性

- API 日志包含时间、请求标识、路由、状态码和耗时；
- 5xx 错误率连续 5 分钟超过 2% 时告警；
- 创建任务失败率连续 10 分钟超过 1% 时告警；
- 健康检查覆盖应用进程和数据库连接；
- 监控数据中不得包含敏感信息。
