# AI 项目仓库初始化

## 1. 目的与边界

仓库初始化的目标不是立即生成完整业务代码，而是建立一个 Agent 能理解、执行和验证的工作环境。核心产物是根目录的 `AGENTS.md`；其他工程文件提供最小、可执行的基线。

本指南适用于需求范围和关键业务规则已经初步明确的项目。产品发现、上线后的运营和日常运维不在本阶段范围内。

## 2. `AGENTS.md` 的职责

`AGENTS.md` 是 Agent 进入仓库后的执行入口，回答以下问题：

- 这个仓库解决什么问题，目前处于什么阶段；
- 哪些文档和代码是事实来源，发生冲突时以谁为准；
- 开始任务前必须读取什么；
- Agent 可以自主决定什么，遇到什么必须停止并询问；
- 实现、验证、验收和交付分别需要做什么；
- 哪些安全和范围边界不得突破。

它不应复制功能规格、页面细节或完整架构说明。具体规则应保留在对应文档中，由 `AGENTS.md` 提供路径和读取顺序，避免同一规则存在多个版本。

## 3. `AGENTS.md` 必备内容

### 仓库目标与适用范围

用短段落说明产品、主要用户、当前里程碑，以及仓库是文档、原型还是可部署应用。明确不在当前范围内的工作。

### 结构与事实来源

列出源代码、测试、规格、迁移和决策记录的位置。定义冲突优先级，例如：已接受 ADR > 功能和页面规格 > 领域与权限规则 > 产品概述。

### 任务开始条件

要求 Agent 读取产品总纲、术语表、相关功能和页面规格、领域与权限规则、架构约束、ADR 和完成标准。开始实现前检查现有代码、测试、依赖和工作区状态。

### 决策与升级边界

- 可以按现有模式决定命名、文件位置和局部实现细节；
- 不得自行改变用户数据、权限、计费、安全或验收结果；
- 关键规则缺失或文档冲突时，记录影响并请求负责人决策；
- 不得为了让实现通过而修改验收标准或扩大任务范围。

### 实施与验证规则

规定一次只完成一个可独立验收的路线图任务，并列出真实可运行的安装、开发、格式、lint、类型检查、测试、E2E 和构建命令。命令缺失或失败时必须如实报告。UI 项目还应规定目标视口、页面状态、键盘操作和可访问性检查。

### 安全与变更限制

禁止提交密钥、令牌和真实个人数据；限制破坏性命令、无关重构、依赖大版本升级和生产操作。说明环境变量、测试数据和日志的安全要求。

### Agent 分工与交付格式

编码 Agent 负责实现、测试、自检和证据；验收 Agent 独立依据规格判断，且不得修改产品实现。交付报告至少包含完成项、主要文件、实际检查结果、截图或日志证据、风险和规格偏差。

### 子目录规则

当单体仓库包含不同技术栈或独立服务时，可在子目录放置更具体的 `AGENTS.md`。根规则适用于全仓库，离目标文件最近的规则补充或覆盖根规则，并应明确覆盖范围。

## 4. 推荐模板

```markdown
# Repository Guidelines

## Purpose and Scope
说明仓库目标、当前阶段和范围边界。

## Structure and Sources of Truth
列出代码、测试、规格和 ADR 路径，并定义文档优先级。

## Before Starting a Task
列出必读材料、依赖检查和任务就绪条件。

## Implementation Boundaries
说明可自主决定事项、必须升级的问题和禁止事项。

## Commands and Verification
列出真实可运行的开发、检查、测试和构建命令。

## Coding and Acceptance Agents
定义两个角色的职责、隔离要求和结论格式。

## Security and Data Handling
定义密钥、个人数据、日志、依赖和破坏性操作规则。

## Delivery Report
规定改动、检查、证据、风险和偏差的输出格式。
```

模板中的说明必须替换为当前仓库的真实信息。不存在的脚本不能作为已具备能力列出；可以标为计划中的工程基线，并说明何时建立。

## 5. 其他工程基线清单

除 `AGENTS.md` 外，初始化时至少确认：

- `README.md` 提供项目入口、安装和运行方式；
- `.gitignore`、默认分支、提交和 Pull Request 规则已确定；
- 技术栈、运行时及包管理器版本已锁定；
- 目录和模块边界与 `docs/architecture.md` 一致；
- `.env.example` 只包含变量名和安全示例；
- `dev`、`lint`、`typecheck`、`test`、`test:e2e`、`build` 脚本真实存在；
- 至少有一个启动或核心路径冒烟测试；
- CI 在合并前执行必要检查；
- 分支保护和评审要求已配置。

最小目录示例：

```text
README.md
AGENTS.md
.gitignore
.env.example
docs/
src/
tests/
package.json
```

不同技术栈可以调整文件名，但不能省略对应能力。文档示例仓库可以只提供清单和模板，无需创建虚假的应用脚手架。

## 6. 初始化验收

初始化完成后，应能证明：

1. 新 Agent 可以从 `README.md` 和 `AGENTS.md` 找到全部事实来源；
2. 一个路线图任务可以追踪到规格、验收用例和测试要求；
3. 所有声明的命令在干净环境可运行，或被明确标为尚未实现；
4. Agent 能区分自主实现细节和必须由负责人决策的业务问题；
5. 编码与独立验收的输入、输出和证据要求明确；
6. 仓库不包含密钥、令牌或真实个人数据。
