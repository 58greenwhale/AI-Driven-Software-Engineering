# 发布准备检查

## 1. 范围与结论

本检查判断版本是否具备进入实际部署流程的条件，不执行部署，也不覆盖线上值班、事故响应、日常运维或产品运营。结论只能是：`go`、`no-go` 或 `无法判定`。

## 2. 进入条件

开始发布检查前：

- 所有目标 P0 任务已独立验收通过；
- 路线图中没有未处理的阻塞项；
- 版本范围、变更说明和已知限制已确认；
- 发布分支包含对应的规格、测试和决策记录更新。

## 3. 检查清单

### 代码与验证

- [ ] lint、类型检查、单元/集成测试、E2E 和生产构建通过；
- [ ] 关键用户旅程和回归测试通过；
- [ ] 目标浏览器、视口和可访问性检查完成；
- [ ] 没有未解释的高严重度缺陷、调试代码或敏感信息泄露。

### 安全与依赖

- [ ] 依赖检查无未接受的 Critical/High 风险；
- [ ] 生产密钥不在仓库、构建产物或日志中；
- [ ] 认证、权限、输入校验和错误响应符合规格；
- [ ] 第三方服务、许可证和新依赖用途已记录。

### 数据与环境

- [ ] 所需环境变量和安全配置有清单，真实值通过部署环境注入；
- [ ] 数据库迁移可重复执行、顺序明确且与当前代码兼容；
- [ ] 迁移失败或版本回退时的处理方式已记录；
- [ ] 备份和恢复前置条件符合 `docs/non-functional.md`，不把备份执行本身当作本指南范围。

### 交付信息

- [ ] 版本号、变更说明和关联任务齐全；
- [ ] 已知限制、未纳入范围和后续任务已列出；
- [ ] 发布负责人、批准人和证据位置明确；
- [ ] 回滚触发条件、代码回退方式和数据兼容限制已记录。

## 4. Go / No-go 规则

输出发布报告时，对每一项给出 `通过`、`失败` 或 `无法判定`，并附命令、日志、截图或数据证据。以下任一条件成立时必须为 `no-go`：

- 目标 P0 任务未通过独立验收；
- 关键测试、构建、安全检查或数据库迁移失败；
- 存在未评估的高严重度缺陷或不可逆数据风险；
- 缺少必要环境变量、回滚方案或发布批准。

缺少执行环境或原始证据时为 `无法判定`，不能按通过处理。
